# 从已有算法到新算法的实验发现流程

## 1. 核心目标

这个流程不是为了证明原算法不好，也不是为了做一个“简化版原算法”。

真正目标是：

```text
基于一篇已有算法论文，拆开它声称重要的机制，
通过一组有控制的实验找出真正起作用的因素，
再把这个因素重新设计成一个可以独立命名、独立比较的新算法。
```

这次 `CMOEA-AOP -> SCOP-CMOEA` 就是一个例子。

## 2. 总体思路

从已有算法出发时，先不要急着改算法。第一步是把原论文的贡献拆成几个可检验因素。

例如 `CMOEA-AOP` 论文声称关键在于：

```text
DDPG 根据种群状态学习多个算子的使用比例。
```

但这句话里面其实混了很多因素：

```text
多算子是否同时存在；
比例是否动态变化；
阶段性比例是否已经足够；
随机变化是否已经有效；
简单反馈是否已经足够；
DDPG 长期学习是否真的必要；
两个种群是否应该使用相同比例。
```

因此实验的核心不是直接提出新算法，而是先设计实验把这些因素逐个拆开。

## 3. 第一批实验：先拆“多算子共存”是不是核心

第一批实验不使用 DDPG，只做固定组合。

实验设计：

```text
单算子：GA-only, DE/rand-only, DE/best-only
固定偏置：GA-heavy, DE/rand-heavy, DE/best-heavy
双算子组合：GA+DE/rand, GA+DE/best, DE/rand+DE/best
三算子均匀：Equal-AOP
原始骨架：EMCMO
原始算法：CMOEA-AOP
```

这批实验回答：

```text
性能提升是不是仅仅来自多个算子共同生成 offspring？
```

判断方式：

- 如果均匀组合已经接近原算法，说明“多算子共存”本身很重要；
- 如果不同问题偏好不同固定比例，说明需要动态控制；
- 如果单算子在少数问题上很强，说明算子选择具有问题依赖性。

这一步的价值是把“DDPG 的作用”先和“多算子 portfolio 的作用”分开。

## 4. 第二批实验：再拆“动态比例”是不是必须靠 DDPG

第二批实验保持三个算子和 EMCMO 框架不变，只改变比例产生方式。

实验设计：

```text
Equal-AOP：始终均匀比例
Random-AOP：每代随机比例
Stage-AOP：按阶段手工设定比例
Survival-Credit-AOP：按 offspring 存活率调比例
CMOEA-AOP：原始 DDPG 调比例
```

这批实验回答：

```text
动态比例是否有效？
如果有效，它是否必须依赖深度强化学习？
```

判断方式：

- 如果 Random 接近 DDPG，说明随机多样性已经贡献很大；
- 如果 Stage 接近 DDPG，说明 DDPG 可能主要学到了阶段规律；
- 如果 Survival-Credit 接近或超过 DDPG，说明轻量即时反馈已经足够；
- 如果 DDPG 明显最好，说明长期状态学习确有价值。

这一步是从“原论文说 DDPG 重要”转向“到底哪种动态机制重要”。

## 5. 第三批实验：如果反馈有效，再拆“什么反馈最有效”

如果简单反馈类方法有潜力，就继续比较不同信用信号。

实验设计：

```text
Survival credit：offspring 是否在环境选择后存活
Feasibility credit：offspring 是否可行
CV credit：offspring 是否降低约束违反
Objective credit：offspring 是否改善目标
Mixed credit：组合 survival、feasibility、CV
Sliding credit：使用最近若干代滑动平均
```

这批实验回答：

```text
在约束多目标优化中，一个算子“有效”到底是什么意思？
```

本次实验发现最有价值的是：

```text
offspring survival 本身就是一个很强的信用信号。
```

原因是环境选择已经同时包含了目标、约束、可行性和多样性压力。一个 offspring 能存活，说明它通过了当前搜索环境的综合检验。

这一步把“调比例”进一步提炼成了一个更一般的机制：

```text
用环境选择后的生存结果反向分配 offspring 生成资源。
```

## 6. 第四批实验：再看结构复杂化是否真的有收益

因为 EMCMO 有两个种群，所以继续测试两个种群是否需要不同的算子比例。

实验设计：

```text
共享比例：两个种群使用同一个 survival credit 控制器
双控制器：两个种群分别维护 survival credit
角色分离：主种群偏可行/收敛，辅助种群偏探索
软耦合：两个种群有不同信用，但保持一定比例耦合
```

这批实验回答：

```text
更复杂的双种群角色分工是否能超过简单共享控制器？
```

本次实验的结论是：

```text
双种群分工是有研究价值的，但没有稳定超过单一 survival-credit 控制器。
```

所以主算法不应该选择更复杂的 `BiSCOP-CMOEA`，而应该选择更简单、更稳定的 `SCOP-CMOEA`。

## 7. 从实验结论到新算法

实验结论不能直接当论文题目。

不应该写成：

```text
CMOEA-AOP 的 DDPG 不是必要的。
```

应该提炼成：

```text
环境选择后的 offspring 生存结果，可以作为算子资源分配的直接信用信号。
```

于是新算法的核心思想变成：

```text
给每个 offspring 记录来源算子；
环境选择后统计各算子的 offspring 存活率；
用存活率平滑更新下一代算子比例；
保留最小比例，避免算子过早消失；
在同一代中持续使用多个互补算子。
```

这就是：

```text
SCOP-CMOEA
Survival-Credit Operator Portfolio for Constrained Multi-objective Optimization
```

它不是 `CMOEA-AOP` 的解释版，而是一个新的算法设计：

```text
用 survival credit 做 offspring 资源调度。
```

## 8. 判断一个变体能否成为新算法

一个实验变体能否独立成算法，至少要满足四点：

```text
性能进入第一梯队；
机制可以一句话讲清楚；
不是原算法的简单参数修改；
能设计外部对比和消融实验支撑。
```

本次判断：

| 变体 | 判断 |
| --- | --- |
| SCOP-CMOEA | 主算法，值得独立成文 |
| BiSCOP-CMOEA | 可作为扩展或消融，不适合主线 |
| Dual-SCOP-CMOEA | 可作为后续结构创新 |
| Role-Separated-Credit-AOP | 有问题依赖性，适合分析 |
| Stage-AOP | 强对照，说明阶段规律存在 |
| Equal/Random-AOP | 基线，不是新算法 |

## 9. 可复用模板

以后研究其他论文算法时，可以按下面顺序做。

### 9.1 拆原算法

```text
原算法声称的核心贡献是什么？
这个贡献由哪些因素组成？
哪些因素在原论文里没有被单独验证？
```

### 9.2 做控制实验

```text
先固定其他模块，只改变一个因素；
先做简单版本，再做复杂版本；
先小规模筛选，再扩大确认。
```

### 9.3 找真实机制

```text
哪些结果说明原论文声称的重要模块不是唯一原因？
哪个更简单的因素能够解释主要性能？
这个因素能否抽象成通用机制？
```

### 9.4 重新设计新算法

```text
不要把新算法写成原算法的修补；
要把真实机制改写成一个新的设计原则；
给它一个独立名称；
建立正式代码入口；
再做外部算法对比。
```

## 10. 最终产出

每研究一篇已有算法，最终至少应形成四类材料：

```text
机制拆解表：原算法被拆成哪些可检验因素；
实验路径图：先做哪些控制实验，再做哪些确认实验；
候选机制结论：真正起作用的机制是什么；
新算法定义：如何基于该机制形成独立算法。
```

对于这次案例，产出是：

```text
机制拆解：DDPG、多算子、动态比例、信用反馈、双种群分工
实验路径：固定组合 -> 动态比例 -> 信用信号 -> 双种群结构
核心机制：offspring survival credit
新算法：SCOP-CMOEA
```

这套流程可以继续用于其他算法论文：

```text
从已有算法中拆机制，
用实验排除表面解释，
找到真正可复用的作用机制，
再把机制重新设计成新算法。
```
