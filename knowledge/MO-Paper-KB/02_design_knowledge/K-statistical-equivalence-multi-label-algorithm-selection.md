# 统计等价驱动的多标签算法选择

## 核心内容

在算法选择中，不把每个问题强行标注为单一最佳算法，而是先根据多次运行的性能分布识别与当前最佳算法统计上无显著差异的一组算法，再用该集合训练多标签模型，预测新问题上可同时作为最佳选择的算法集合。

一种具体流程是：

```text
对每个问题和候选算法做多次独立运行
-> 用性能指标分布找中位数最佳算法
-> 用 MAD 区间重叠筛出候选可比算法
-> 用 ANOVA 和 Tukey HSD 保留统计等价最佳算法
-> 将最佳算法集合编码为多标签目标
-> 用问题特征训练 classifier chain
-> 输出多个推荐算法，并用 ASP 评价误报和命中情况
```

## 建立理由

- 为什么值得独立维护：它提供了明确的“训练问题性能数据 -> 多标签算法选择器 -> 推荐算法集合”接口，可用于算法 portfolio、自动算法选择、hyper-heuristic 外层调度和实验基线选择。
- 单篇具体方法的直接复用价值：P2026-0105 给出 Algorithm 1 和 Algorithm 2，明确了统计标注、ELA 特征、classifier chain 和 ASP 指标的完整流程，并提供公开 Python 代码。
- 与已有设计知识的区别：
  - 不修改种群环境选择；
  - 不构造辅助任务；
  - 不执行跨任务知识迁移；
  - 不改变后代生成算子；
  - 作用位置是算法外层的选择、推荐或组合调度接口。

## 解决的问题

- 适用场景：
  - 多个优化算法在同一问题上性能接近；
  - 算法选择模型需要为新问题推荐算法；
  - 用户希望在性能相近算法中再按运行时间、内存、实现可得性或熟悉程度选择；
  - 算法 portfolio 或 hyper-heuristic 需要一个可靠候选集合，而不是单一算法。
- 现有方法为什么会失败或不足：
  - 单标签算法选择通常按平均指标值强行挑一个赢家，忽略多次运行分布；
  - 当算法差异很小或不显著时，单一赢家标签不稳定；
  - 模型会学习微小、随机、统计上无意义的性能差异，增加过拟合风险；
  - 只在评价阶段宽容“预测到相近算法”仍不能改变训练目标本身。
- 仍需解决的问题：
  - 统计阈值、候选算法池、评价预算和指标选择会改变标签；
  - 构造训练标签需要大量算法运行；
  - 如何把推荐集合进一步转化为并行 portfolio、在线调度或预算分配策略仍未解决。

## 为什么可能有效

```text
多个算法在同一问题上可能性能分布重叠
-> 单一赢家标签把随机微小差异当作真差异
-> 统计检验把可比算法保留为同一最佳集合
-> 多标签模型学习“哪些算法都足够好”
-> 输出集合允许用户或外层调度器按额外成本和偏好选择
-> ASP 奖励命中至少一个真实最佳算法，同时惩罚误报非最佳算法
```

## 实现接口

- 输入：
  - 候选算法集合；
  - 训练问题集合；
  - 每个算法在每个问题上的多次运行性能指标；
  - 问题特征，例如 ELA 特征；
  - 评价预算和运行次数。
- 输出：
  - 新问题上的推荐算法集合；
  - 每个算法的二元标签或预测分数；
  - 可选的 ASP、LRAP、Hamming Loss、Subset Accuracy 等评估结果。
- 可替换组件：
  - 性能指标：如 `I_CMOP`、HV、IGD、IGD+ 或领域指标；
  - 统计等价判定：MAD + ANOVA + Tukey HSD 可替换为非参数检验、bootstrap、Bayesian 等价检验；
  - 问题特征：ELA、实例空间特征、约束特征、初始运行轨迹特征；
  - 多标签模型：classifier chain、binary relevance、label powerset、概率校准模型；
  - 评价指标：ASP 可扩展为 cost-aware ASP 或 risk-aware ASP。

## 如何用于算法创新

### 局部创新

- 将单标签算法推荐模块替换为统计等价多标签推荐模块。
- 在已有 CMOP 算法选择器中，把“平均性能最优算法”标签改成“统计可比最佳算法集合”标签。
- 在算法实验平台中，为新问题输出多个候选算法，再按运行成本、代码可得性或用户偏好选择。
- 用 ASP 替换普通 accuracy，避免模型只因预测完整标签向量不完全相同而被过度惩罚。

### 结构创新

- 构建算法组合框架：离线多标签模型给出候选算法集合，在线阶段对候选算法短跑评估并分配预算。
- 构建自适应调度器：多标签选择器提供初始可行算法池，运行过程中根据可行解比例、收敛速度、约束违反和多样性动态切换。
- 构建人机协同算法选择：模型只给出统计上合理的候选集，用户再按工程成本、可解释性和实现熟悉度选择最终算法。

## 适用条件与风险

- 适用条件：
  - 有足够训练问题和候选算法运行数据；
  - 算法性能具有随机性，需要多次独立运行刻画分布；
  - 多个算法确实可能在问题上表现相近；
  - 能提取对算法表现有预测价值的问题特征。
- 不适用或可能失效的条件：
  - 候选算法中经常存在绝对优势算法，单标签选择已经足够；
  - 训练问题与真实问题分布差异很大；
  - 算法池频繁变化，导致历史标签失效；
  - 性能指标或评价预算不能代表真实使用目标；
  - 特征采样难以覆盖可行区域或关键约束结构。
- 计算与实现成本：
  - 需要对每个训练问题、每个候选算法执行多次独立运行；
  - ELA 特征本身需要额外采样和随机游走；
  - 统计检验和多标签模型需要处理多重比较、类别不平衡和标签相关性。
- 解释风险：
  - “统计无显著差异”不等于算法完全等价，只能说明在当前样本、指标和阈值下未发现显著差异；
  - 输出多个算法不等于所有算法成本相同，后续仍需成本或偏好过滤；
  - ASP 偏向少误报和至少命中一个真最佳算法，不保证完整恢复全部最佳算法集合。

## 证据边界

- 当前只有单篇论文证据。
- 实验只覆盖人工 benchmark CMOP、9 个候选算法、2D/5D/10D 双目标问题和四个评价预算。
- 作者没有给出 classifier chain 相对独立二元分类器的直接消融。
- 该方法解决的是算法选择或推荐层，不是新的底层 MOEA 搜索算子。
- 统计阈值、候选算法池和性能指标改变后，标签集合可能改变。
