# 预测代理驱动的实时多目标控制优化

## 核心内容

先用历史监测数据训练能预测多个性能目标的代理模型；在线决策时，把当前不可控场景变量固定，把可控运行参数作为决策变量，用快速贝叶斯多目标优化在安全约束内搜索 Pareto 前沿，再通过可解释的偏好/权重方法选择最终控制建议。

```text
历史多源监测数据
-> 数据清洗、降噪、特征筛选
-> 训练多输出预测代理  x, context -> objectives
-> 在线固定当前场景变量
-> 在可控参数约束内执行快速 MOO
-> 生成 Pareto 前沿
-> 按场景偏好选择最终控制参数
-> 人或控制系统执行并反馈
```

## 建立理由

- 为什么值得独立维护：它把“昂贵或危险的在线试错”改成“历史数据代理预测 + 快速多目标搜索 + 场景化折中选解”，适合需要秒级建议的工程设备控制、调参和运行优化。
- 单篇具体方法的直接复用价值：P2026-0041 给出 CSD 实例，包括 256 维监测数据筛选、MAGCN 多输出预测代理、MOTPE Pareto 搜索、WSM 选解和安全约束建模，并报告 5.687 s/position 的优化速度。
- 与已有设计知识的区别：
  - 不同于“自适应代理内环加速器”：本知识不是在 MOEA 子代生成和真实评价之间插入在线代理内环，而是把训练好的预测模型作为实时控制优化的目标函数。
  - 不同于“目标条件化生成式设计采样”：本知识不学习“目标条件 -> 设计分布”的生成模型，而是在当前场景约束下用贝叶斯 MOO 搜索可控参数。
  - 不同于资源分配或参考点切换类知识：它主要改变工程优化问题的求解架构，而非 MOEA 内部选择算子。

## 解决的问题

- 适用场景：
  - 真实系统在线试错代价高、风险大或时间窗口短；
  - 有历史运行数据和实时监测数据；
  - 目标之间冲突，例如效率、能耗、安全、质量、排放和寿命；
  - 一部分变量是不可控环境/场景变量，一部分变量是可控操作参数；
  - 需要给人类操作员或控制系统提供可解释、可约束的参数建议。
- 现有方法为什么会失败或不足：
  - 人工经验控制难以稳定处理高维耦合变量和快速变化环境；
  - 单目标预测或单目标优化会把目标冲突隐藏起来；
  - 常规 MOEA/元启发式从头搜索收敛较慢，难以满足秒级控制；
  - 只训练预测模型不能自动给出可执行控制参数；
  - 只做优化而不建代理，在线评价可能太慢或不安全。
- 仍需解决的问题：
  - 代理误差和不确定性如何传递到 Pareto 前沿；
  - 推荐策略偏离操作经验时如何提高可采纳性；
  - 如何把长期设备健康、环境影响和维护成本加入目标；
  - 如何在数据分布漂移、传感器故障和新工况下保持可靠。

## 为什么可能有效

```text
历史运行数据包含环境、控制参数和性能结果
-> 预测代理学习当前场景下参数到目标的局部响应
-> 贝叶斯 MOO 用较少候选评估找到高价值参数区域
-> 安全约束剔除不可执行方案
-> Pareto 前沿显式呈现目标冲突
-> WSM/TOPSIS/AHP 等选解方法把工程偏好转成最终建议
```

核心假设不是代理完全精确，而是在当前工况附近能给出足够可靠的目标排序和趋势，使优化器能在短时间内产生比人工默认值更好的候选控制量。

## 实现接口

- 输入：
  - 历史数据：可控参数、不可控场景变量、性能目标和安全状态；
  - 实时数据：当前场景变量、当前设备状态和约束范围；
  - 多输出预测代理；
  - 快速 MOO 优化器；
  - 偏好或折中选解规则。
- 输出：
  - 当前场景下的 Pareto 候选集；
  - 推荐控制参数；
  - 预测目标值、约束余量和可选的置信度。
- 插入位置：
  - 工程设备控制中心的决策支持模块；
  - 数字孪生系统中的滚动优化层；
  - 人机协同控制中的“建议参数生成器”；
  - 传统 MOEA 或 BO 的代理目标函数层。
- 最小实现：

```text
data <- clean_and_filter(history)
features <- select_control_and_context_variables(data)
surrogate <- train_multi_output_predictor(features, objectives)

while control_window_active:
    context <- read_current_uncontrollable_state()
    bounds <- build_safety_constraints(context)
    pareto <- fast_moo(
        x -> surrogate.predict(x, context),
        bounds=bounds
    )
    feasible <- remove_unacceptable(pareto)
    recommendation <- choose_by_preference(feasible)
    output(recommendation)
```

- P2026-0041 的具体实例：
  - 数据清洗：IQR 异常剔除、S-G 滤波、Min-Max 归一化；
  - 特征选择：MIC 初筛，PCC 去冗余；
  - 预测代理：MAGCN，包含 FFT 多尺度识别、自适应邻接矩阵、MixHop 图卷积、多头注意力和尺度聚合；
  - 优化器：MOTPE，以非支配排序和 HSSP 划分观测，构造 `l(x)`/`g(x)`，按 EHVI 采样，并加入时间权重；
  - 选解：剔除不可接受解后用 WSM 按场景权重选择最终方案。

## 如何用于算法创新

### 局部创新

- 用更简单或更可解释的代理替换深度模型，例如随机森林、GPR、PINN 或物理模型校正网络。
- 在 MOTPE/EHVI 中加入代理不确定性，优先探索预测收益高且风险可控的参数区域。
- 将 WSM 替换为 TOPSIS、AHP、交互式偏好或约束满意度模型。
- 用场景分类器自动选择约束、权重和安全阈值。
- 对推荐方案加入相邻时刻平滑约束，避免控制量频繁跳变。
- 把操作员接受/拒绝反馈作为额外目标或约束，提升推荐可执行性。

### 结构创新

- 构建“预测代理 + 贝叶斯 MOO + 数字孪生 + 人机协同”的滚动控制框架。
- 维护多个场景特化代理或多保真代理，在当前工况下自动选择或集成。
- 将局部设备控制器嵌入上层多设备调度：底层优化单设备效率/能耗，上层协调工期、资源和风险。
- 将短期控制目标与长期健康目标分层：下层秒级 MOO，上层按设备寿命、维护计划和碳排放调整权重。

## 适用条件与风险

- 适用条件：
  - 有足够覆盖当前工况的历史数据；
  - 目标可以由代理在短时间内预测；
  - 约束边界和不可接受区域可被工程规则明确给出；
  - 推荐方案可以先作为决策支持，再逐步接入自动控制；
  - 环境变量在一个控制窗口内相对稳定，或可被实时更新。
- 不适用或可能失效的条件：
  - 历史数据严重偏离当前工况；
  - 关键变量缺失或传感器持续故障；
  - 代理对目标排序不可靠，却被优化器反复利用；
  - 目标遗漏导致优化出“数字好看但工程风险高”的策略；
  - 权重或阈值设置不透明，操作员难以信任；
  - 控制动作具有强滞后或累积效应，但优化模型只看单步收益。
- 计算与实现成本：
  - 需要数据清洗、变量筛选、代理训练、在线推理、优化器和控制系统接口；
  - 若代理为深度模型，需要漂移监测、周期性重训和异常处理；
  - 推荐结果最好包含置信度、约束余量和解释信息。
- 解释风险：
  - Pareto 前沿是代理模型上的前沿，不等同于真实系统前沿；
  - 预测精度高不自动保证优化推荐可靠；
  - 场景平均收益不保证每个个案都改善；
  - 人工经验并非只是不可靠噪声，也可能包含未建模安全知识。

## 证据边界

- 当前只有单篇论文证据。
- 真实效果主要来自历史数据回放和模型优化，没有报告在线闭环实船对照实验。
- MOO 对比是工程数据上的 400 点比较，不是标准多目标 benchmark 的统计检验。
- MAGCN 没有组件消融，无法确认每个结构模块的独立贡献。
- 代理误差未显式传播到 Pareto 前沿和最终控制方案。
- 目标只覆盖生产率与能耗，未覆盖环境、寿命、维护和施工调度。
