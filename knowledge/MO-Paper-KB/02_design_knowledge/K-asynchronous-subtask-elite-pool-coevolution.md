# 异步子任务精英池协同进化

## 核心内容

把一个复杂结构搜索问题拆成多个可并行求解的子任务，让每个子任务持续独立演化；子任务周期性把精英候选加入共享队列，由独立线程异步更新外部精英池。各子任务在固定或自适应时机从精英池随机取候选注入自身种群，使不同子问题中的有用结构能够持续流动，而不需要全局同步停顿。

```text
原问题分解为 K 个子任务
-> K 个子任务线程各自运行进化算法
-> 子任务周期性输出精英到 queue
-> pool 线程异步消费 queue
-> pool 未满则加入精英，已满则随机竞争替换
-> 子任务周期性从 pool 抽取模型注入自身种群
-> 所有子任务连续演化直到停止
```

P2026-0049 将该机制用于多目标 GP 符号回归，子任务来自全局/局部子数据集，精英池保存非支配或优质表达式模型。

## 建立理由

- 为什么值得独立维护：
  - 分解式进化算法常需要在子任务之间交换信息，但同步迁移会打断子任务连续演化。
  - 精英池提供了一个轻量通信层，既能扩散高质量结构，又不要求所有子任务同时等待。
  - 该机制不限于符号回归，可迁移到程序搜索、组合结构演化、NAS、分解式 MOO 或多任务优化。
- 单篇具体方法的直接复用价值：
  - P2026-0049 给出 Algorithm 2-3，包括线程分配、队列、pool 更新和子任务扰动；
  - 消融显示 DGPMP 相比 MoGP/DGP 在多数 benchmark 上有更好 train/test RMSE 和更快收敛；
  - CPU-only 与 CPU-GPU 实验均显示模型探索率明显提升。
- 与已有设计知识的区别：
  - 不同于贡献自适应的多种群多目标协同：该知识按目标子种群贡献分配进化机会；本知识面向异步子任务通信和精英结构共享。
  - 不同于全局非支配占比驱动的子种群均衡进化：这里不补齐落后子种群进度，而是让不同子任务通过精英池持续交换结构。
  - 不同于成功率反馈算子选择：这里调度的是候选结构迁移，不是选择变异/交叉算子。

## 解决的问题

- 适用场景：
  - 原问题可拆成多个子任务、子数据集、局部区域或辅助目标；
  - 每个子任务能独立运行进化搜索；
  - 不同子任务产生的优质结构可互相复用；
  - 全局同步迁移成本高，或会打断子任务连续演化；
  - 候选评价昂贵，希望提升单位时间探索率。
- 现有方法为什么会失败或不足：
  - 普通并行多种群只并行搜索，子任务之间信息流弱；
  - 固定周期全局收集和重分发需要同步，慢子任务拖累快子任务；
  - 一次性收集再重启演化会造成演化过程不连续；
  - 精英池若每次全量非支配更新，频繁通信会造成内存和计算压力。
- 仍需解决的问题：
  - 如何避免精英池被少数容易子任务占满；
  - 如何判断从 pool 注入的候选对当前子任务是否有益；
  - 如何处理跨子任务迁移带来的过拟合、非法结构或负迁移。

## 为什么可能有效

```text
不同子任务暴露问题的不同局部或全局结构
-> 子任务独立演化能快速产生多样精英
-> 异步精英池避免同步等待
-> 精英结构被其他子任务重新训练或继续演化
-> 有用基因型跨子任务复用
-> 搜索多样性、泛化和模型探索率提高
```

关键假设是：子任务之间存在可迁移的结构片段或搜索方向，并且异步注入不会过度破坏每个子任务自身的收敛过程。

## 实现接口

- 输入：
  - 子任务构造器，如子数据集、子目标、参考区域或辅助问题；
  - 可独立运行的宿主进化算法；
  - 精英选择规则；
  - model pool 容量；
  - 子任务扰动频率和每次注入候选数；
  - pool 更新规则。
- 输出：
  - 更新后的各子任务种群；
  - 共享精英池；
  - 全局最优或非支配候选集合。
- 插入位置：
  - 分解式 GP/程序搜索的外层并行框架；
  - 多任务或多子问题 MOEA 的迁移通信层；
  - 多岛模型的 migration layer。
- P2026-0049 的默认实例：
  - 子任务为 global regression 或 local regression 子数据集；
  - 每个子任务运行同参数 MoGP；
  - 另设一个线程维护 model pool；
  - 每 10 代从 pool 随机选择 50 个模型扰动子任务；
  - pool size 为 300；
  - pool 未满时直接加入新精英；pool 已满时，新模型与随机 pool 模型竞争，优者保留。

## 如何用于算法创新

### 局部创新

- 将随机 pool 替换改为拥挤度、结构新颖性、跨任务验证误差或贡献率驱动替换。
- 给每个子任务维护注入成功率，成功率低时减少外来精英扰动。
- 对精英候选先做合法性、安全性或复杂度过滤，避免传播非法表达式和过大结构。
- 将固定扰动周期改为停滞触发、不确定性触发或资源空闲触发。
- 按子任务相似性选择来源 pool，而不是从全局 pool 随机抽取。

### 结构创新

- 构建异步结构搜索总线：

```text
子任务搜索器
-> 精英候选事件流
-> 共享结构记忆池
-> 按需候选注入
-> 子任务反馈迁移效果
```

- 将精英池扩展为多层记忆：全局通用结构、局部子任务结构、探索性稀有结构。
- 与代理模型结合，先用低成本泛化评分预测哪些精英适合迁移到哪个子任务。
- 与异构计算结合，CPU 负责结构变异和选择，GPU/加速器负责候选评价，pool 作为跨设备通信边界。

## 适用条件与风险

- 适用条件：
  - 原问题可合理拆分，子任务质量与原问题质量存在关联；
  - 候选结构能在不同子任务之间复用；
  - 宿主算法支持外来候选注入；
  - pool 更新和迁移开销小于同步或重复搜索成本。
- 不适用或可能失效的条件：
  - 子任务之间差异过大，迁移主要产生负迁移；
  - 精英池容量过小，稀有结构被随机竞争替换掉；
  - 子任务评价尺度不同，直接比较候选优劣不公平；
  - 注入频率过高，破坏子任务局部收敛；
  - 候选结构存在运行时非法风险，如除零、非法函数输入或资源爆炸。
- 计算与实现成本：
  - 需要多线程或分布式执行框架；
  - 需要并发安全队列和 pool 更新；
  - pool 候选可能需要在全数据或统一验证集上重新评价；
  - 对大结构搜索，pool 内存和评价成本需要显式控制。

## 证据边界

- 当前只有单篇论文证据。
- 主要验证对象是符号回归，不代表所有 MOEA 或程序搜索问题。
- 算法收益与 Python 实现、多线程环境、数据规模和表达式评价成本强相关。
- DGPMP 不是 SRBench 全指标最优方法。
- 算术异常导致少数模型 test RMSE 计算失败，说明候选结构安全性需要额外处理。
- GPU 加速收益属于具体异构实现证据，不完全等同于精英池协同机制本身。
