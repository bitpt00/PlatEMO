# CRITIC-TOPSIS 评价反馈引导演化

## 核心内容

把多准则决策评价从 Pareto 解集的后处理步骤前移到进化循环内部。每一代先由多目标元启发式更新种群和非支配档案，再用 CRITIC 计算绩效指标权重，用 TOPSIS 对档案方案打分排序；综合绩效最高的方案作为 elite，反馈给下一代演化过程。

这样形成“优化产生候选 -> 评价排序档案 -> elite 反哺搜索”的闭环，而不是“先跑完优化 -> 再挑一个方案”的两阶段流程。

## 解决的问题

在工程和管理类 MOO 中，Pareto 解的实用价值通常取决于多个派生绩效指标和管理偏好。若只在优化结束后做 MCDM 排序，评价信号无法影响搜索方向；算法可能花大量预算覆盖管理上不重要的区域。

## 设计模式

1. 宿主 MOOA 生成后代并更新候选种群。
2. 将后代非支配解与外部档案合并，得到当前档案。
3. 为档案内每个解计算评价指标矩阵，指标可来自原目标、派生成本、服务水平、风险或韧性指标。
4. 用 CRITIC 根据指标对比强度和指标冲突计算客观权重。
5. 用 TOPSIS 计算每个档案解到正/负理想点的相对接近度。
6. 按评价值排序，选择最高评价解作为 elite。
7. 把 elite 输入宿主算法的引导环节，例如全局最优、leader、精英个体或参考解。

## 为什么可能有效

CRITIC 权重利用当前档案中指标的差异性和相关性，能避免完全依赖人工静态权重。TOPSIS 把多个指标压缩成可排序的综合绩效值，使搜索过程能持续偏向更符合决策语义的区域。对于有外部档案或 leader 机制的 MOOA，该评价值可以直接替代或补充原本的随机 leader、拥挤距离 leader 或单目标最优 leader。

## 可复用接口

| 接口 | 输入 | 输出 |
|---|---|---|
| 评价指标构造 | 当前非支配档案、原目标、业务派生指标 | `m x n` 决策矩阵 |
| CRITIC 权重 | 标准化指标矩阵 | 指标权重向量 |
| TOPSIS 排序 | 权重、正负理想点、标准化指标 | 每个方案的绩效值 |
| elite 注入 | 绩效最高方案、宿主算法状态 | 下一代 leader / gbest / elite / reference solution |

## 适用条件

- Pareto 解需要经过多准则决策或业务绩效指标排序。
- 宿主算法支持 elite、leader、global best、外部档案或参考解引导。
- 评价指标相对便宜，可以在每代或每若干代对档案计算。
- 决策者愿意接受由客观权重和理想点距离形成的折中排序。

## 风险与注意事项

1. CRITIC 权重由当前档案分布决定，早期档案不稳定时可能产生噪声引导。
2. TOPSIS 的正负理想点和归一化方式会影响排序，对极端值敏感。
3. 过度依赖单个最高绩效 elite 可能降低 Pareto 前沿覆盖，应保留多样性选择。
4. 如果评价指标与优化目标高度不一致，搜索会偏离原始 Pareto 覆盖目标。
5. 该机制更适合作为偏好引导层，而不是替代非支配排序、参考向量或多样性维护。

## 与已有卡片的关系

它不同于“成功率反馈的算子与参数自适应选择”：后者反馈的是搜索算子或参数的历史成功率，本知识反馈的是档案解的综合决策绩效。它也不同于“状态驱动的 DRL 演化算子选择”：这里不学习长期策略，而是用 MCDM 每轮重算当前档案排序。

## 论文证据

P2026-0114 将该机制分别嵌入 NSGA-II、MODE、MOPSO 和 MOALO，形成 CT-NSGA-II、CT-MODE、CT-MOPSO、CT-MOALO。数值案例中 CT-MOALO 的最优绩效值为 0.9698，高于 CT-MOPSO 的 0.9344、CT-NSGA-II 的 0.8796 和 CT-MODE 的 0.8535。

论文还比较 CRITIC-TOPSIS、单独 TOPSIS 和无评价策略。表 11 中，CRITIC-TOPSIS 在经济、响应性和韧性三类平均目标值上均优于另外两类策略，作者据此认为评价反馈可提高解的综合绩效。

## 可用于后续创新的方向

- 用多个高评价 elite 或分区域 elite 替代单一 elite，降低多样性损失。
- 将 CRITIC 权重平滑化，使用滑动平均或置信区间降低早期波动。
- 把 TOPSIS 换成 VIKOR、PROMETHEE、ELECTRE、R2 指标或可学习偏好模型。
- 对档案分簇后分别评价，每个簇保留一个业务绩效 leader。
- 将评价反馈频率从每代改为停滞触发或预算阶段触发，降低计算成本。

## 证据边界

P2026-0114 的实验主要是供应链网络设计案例，并未在通用标准 MOO benchmark 上验证该反馈层的普适性。论文中的绩效改善同时受到宿主算法、参数调优、供应链指标设计和不确定模型影响，不能完全归因于 CRITIC-TOPSIS 反馈本身。
