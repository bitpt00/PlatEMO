# 故障子问题辅助的双种群协同重调度

## 核心内容

当动态调度系统发生设备故障或局部扰动时，不直接对全部未完成操作做单一种群全局重排，而是把扰动直接影响的操作抽成一个简化辅助问题。主种群在原问题上维护全局目标和约束，辅助种群只围绕故障影响子问题做快速修复、插入和局部重排。两个种群通过可转换编码双向迁移：主种群的 Pareto 精英为辅助种群提供全局上下文，辅助种群把经过局部修复的候选回流主种群，从而兼顾全局影响和快速恢复。

```text
动态扰动/设备故障
-> 识别稳定操作、直接受影响操作、后续未开始操作
-> 原问题种群 OP: 全局重调度
-> 简化辅助种群 SAP: 直接受影响操作的局部修复
-> OP 精英转换为 SAP 编码
-> SAP 局部演化和时间间隔插入
-> SAP 优质候选转换回 OP 编码
-> OP 输出 Pareto 重调度方案
```

P2026-0129 将该机制用于钢铁冶炼-连铸设备故障后的二目标重调度，其中 OP 处理故障直接影响炉次和未开始炉次，SAP 重点处理故障设备上正在加工的炉次。

## 建立理由

- 为什么值得独立维护：
  - 动态重调度常在“全量重排太慢且扰动大”和“局部修复忽略下游影响”之间摇摆。
  - 该机制给出一个可复用折中：辅助问题负责快速吸收扰动，原问题负责全局 Pareto 质量。
  - 它不是一般多种群并行，而是用扰动结构生成一个与主问题可双向转换的辅助问题。
- 单篇具体方法的直接复用价值：
  - P2026-0129 给出 OP/SAP 两套编码、双向知识迁移、时间间隔插入和自适应突变组件。
  - 真实 SCC 案例中，相比 CCMGPSO、MPMOGA、MOFA、NSGA-II、MOPSO，ATE-MOEA 在 GD、HV、Coverage 和运行时间上整体更优。
  - 消融显示完整框架在 10/16 个案例取得最佳 HV，但双向迁移并非每个案例都带来单调提升，因此适合作为有条件复用的结构知识。
- 与已有设计知识的区别：
  - 不同于“贡献自适应的多种群多目标协同”：该知识按目标子种群贡献分配进化机会；本知识按动态扰动影响范围构造辅助子问题。
  - 不同于“异步子任务精英池协同进化”：该知识关注并行子任务之间通过共享池异步通信；本知识关注主问题和扰动修复辅助问题之间的编码转换与修复回流。
  - 不同于“环境变化严重度驱动的多策略预测响应”：该知识在环境变化后选择预测/响应策略；本知识直接把变化影响区域变成辅助优化问题。
  - 不同于“IUD-ERT-RLS 批调度启发式解码”：该知识是调度解码规则；本知识是动态重调度的双种群问题分解与迁移结构。

## 解决的问题

- 适用场景：
  - 调度、路径、供应链、生产控制等组合优化问题发生局部动态扰动；
  - 扰动直接影响对象可以被识别为一个子集；
  - 原问题仍需维护全局多目标质量和可行性；
  - 辅助子问题可以用更小、更快或更局部的编码表达；
  - 主问题解和辅助问题解之间存在可定义的转换、插入或修复接口。
- 现有方法为什么会失败或不足：
  - 全量重调度会增加计算时间和生产计划变动，动态反馈不够敏捷。
  - 只修复故障附近操作可能忽略下游资源冲突、连锁等待和全局能耗。
  - 常规多种群只是增加并行搜索，并不保证一个种群专门吸收扰动结构。
  - 固定迁移或随机迁移缺少问题语义，容易引入不可行或低质量个体。
- 仍需解决的问题：
  - 如何自动确定扰动影响子集的边界；
  - 如何度量辅助问题回流主问题的真实贡献；
  - 当多处扰动同时发生时，是否使用多个辅助种群或层级辅助问题；
  - 如何避免辅助种群过度局部化而诱导主种群早熟。

## 为什么可能有效

```text
扰动通常先影响局部操作
-> 局部影响子集可被更快修复
-> 辅助种群降低搜索维度并聚焦故障附近可行插入
-> 主种群保留完整目标和约束评价
-> 双向编码迁移把局部修复嵌回全局计划
-> 动态响应速度和 Pareto 解质量同时改善
```

关键假设是：扰动直接影响区域中存在可复用的修复模式，并且这些模式通过编码转换回主问题后仍能保持全局可行性和目标收益。若扰动影响全系统、辅助问题边界不清或主辅编码转换损失过大，该结构可能失效。

## 实现接口

- 输入：
  - 原调度计划、故障时刻、故障设备或扰动对象；
  - 操作状态划分规则；
  - 原问题编码和辅助问题编码；
  - 主辅编码转换函数；
  - 辅助问题局部修复或插入算子；
  - 主种群和辅助种群的选择、交叉、变异与评价函数。
- 输出：
  - 主种群的非支配重调度方案；
  - 辅助问题的局部修复候选；
  - 迁移成功率、可行性恢复率或扰动响应时间统计。
- 插入位置：
  - 动态调度算法的扰动响应模块；
  - 多种群 MOEA 的辅助种群构造层；
  - 可行性修复、局部重排或插入启发式之前；
  - 实时决策系统中“故障检测 -> 优化重调度”的中间层。
- P2026-0129 的默认实例：
  - 状态划分：
    - State 1：故障前已完成或故障时在非故障设备上加工，保持原设备和起始时间；
    - State 2：故障时正在故障设备上加工，需要恢复或重调度；
    - State 3：尚未开始，需要完整重调度。
  - OP 编码：
    - 机器分配矩阵 `M_OP[j,i]`；
    - 炉次顺序矩阵 `S_OP[j,i]`。
  - SAP 编码：
    - 与 OP 同维度的三值插入许可矩阵；
    - 仅 State 2 相关位置可取 `-1/0/1`，其余位置固定为 0。
  - 迁移：
    - OP 非支配精英转换为 SAP 候选；
    - SAP 演化后经 TIAI 时间间隔插入细化，再转换回 OP。

## 如何用于算法创新

### 局部创新

- 将扰动影响子集从手工规则改为基于关键路径、资源冲突传播、图可达性或仿真敏感度自动识别。
- 给 OP->SAP 和 SAP->OP 迁移增加成功率反馈，动态调整迁移频率和迁移规模。
- 把辅助种群的三值许可矩阵扩展为概率插入、优先级插入或多位置候选分布。
- 在 SAP 回流 OP 前加入可行性代理、能耗代理或鲁棒性过滤。
- 将时间间隔插入替换为问题定制的局部搜索，如 2-opt、block move、critical path repair 或 resource leveling。

### 结构创新

- 构建动态 MOO 的主辅问题生成器：

```text
扰动检测
-> 影响传播分析
-> 辅助问题自动生成
-> 主/辅种群协同演化
-> 修复候选回流与全局 Pareto 选择
```

- 为多处故障维护多个辅助种群，让每个辅助种群对应一个扰动簇，再由主种群做全局冲突协调。
- 与鲁棒优化结合：辅助种群不只修复当前故障，还生成对相似故障情景稳定的候选。
- 与代理辅助优化结合：主种群使用代理评估 SAP 回流候选的全局影响，只对高价值候选做真实仿真。
- 与人机交互调度结合：辅助种群可暴露“局部修复解释”，主种群提供不同全局折中方案供调度员选择。

## 适用条件与风险

- 适用条件：
  - 扰动影响具有局部性或可分解性；
  - 存在明确的主问题和辅助问题编码转换；
  - 辅助问题解可以通过插入、修复或补全变成主问题候选；
  - 主问题评价能识别辅助修复对全局目标的真实影响；
  - 重调度时间压力较强，单种群全局搜索响应过慢。
- 不适用或可能失效的条件：
  - 扰动影响全局耦合极强，无法形成低维辅助问题；
  - 辅助种群只优化局部可行性，回流后反复破坏全局目标；
  - 主辅编码转换复杂且损失大，优质辅助解无法稳定映射；
  - 辅助种群迁移过频繁，导致主种群被局部修复模式绑架；
  - 多目标冲突主要来自非故障区域，故障子问题辅助价值有限。
- 计算与实现成本：
  - 需要维护两套编码、两个种群和双向转换函数。
  - 需要问题定制的局部插入或修复算子。
  - 若故障频繁发生，辅助种群重建和迁移调度本身会成为负担。
  - 对实时系统，需要显式限制辅助种群规模、迁移次数和主问题重新评价数量。

## 证据边界

- 当前只有单篇论文证据。
- 主要证据来自钢铁冶炼-连铸重调度，不代表所有动态调度问题。
- 完整框架还包含自适应 Turing 图案突变，实验收益不能全部归因于 OP/SAP 双种群结构。
- 双向知识迁移在消融中不是所有案例都提升，说明辅助问题质量和迁移规则很关键。
- CPLEX 模型验证使用加权目标，与多目标 Pareto 前沿性能不是同一证据。
- 处理时间、运输时间和缓冲等假设较确定，尚未覆盖强随机、强鲁棒或多故障场景。
