# 自适应代理内环加速器

## 核心内容

在宿主 MOEA 的子代生成和真实适应度评价之间插入一个代理模型内环：用最近一代真实评价数据在线训练代理，用代理在内环快速演化候选解，再把有限比例的代理非支配解回灌给宿主算法进行真实评价；同时监控代理解在宿主档案中的跨代生存贡献，贡献衰减到历史峰值的一半或达到代数上限时停用代理。

```text
宿主 MOEA 生成子代
-> 最近一代真实评价种群训练目标代理
-> 代理内环低成本演化候选解
-> 只回灌一部分代理非支配解
-> 宿主 MOEA 真实评价并更新档案
-> 代理贡献半衰期触发退出
```

## 建立理由

- 为什么值得独立维护：它提供了明确的“宿主子代 -> 代理内环 -> 有限回灌 -> 真实评价 -> 贡献退出”接口，可用于改造 NSGA-II、MOEA/D、粒子群、差分进化等基于种群的多目标算法。
- 单篇具体方法的直接复用价值：P2026-0126 给出 Algorithm 1/2、训练数据规则、50% 回灌、半衰期退出、RFR/GPR/1D-CNN 三种代理实例，以及无退出和回灌阈值消融。
- 与已有设计知识的区别：
  - 不构造辅助任务或子问题；
  - 不进行跨任务知识迁移；
  - 不修改目标空间多样性选择；
  - 不依赖变量依赖结构；
  - 直接面向昂贵评价场景中的早期收敛加速和真实评价预算节约。

## 解决的问题

- 适用场景：
  - 单次真实评价昂贵的无约束 MOOP；
  - 主算法在早期需要大量评价才能接近有用 Pareto 前沿；
  - 可以从近期真实评价样本中学习到足够相关的目标排序或趋势；
  - 希望在不大改宿主 MOEA 选择逻辑的情况下增加代理辅助。
- 现有方法为什么会失败或不足：
  - 全程真实评价的 MOEA 评价预算需求过高；
  - 交替式代理往往介入较晚，不适合早期收敛加速；
  - 复杂两环代理常依赖大档案、聚类、参考向量或额外排序，增加实现和运行开销；
  - 全部使用代理候选可能导致多样性下降、错误排序积累和后期性能退化。
- 仍需解决的问题：
  - 如何判断不同代理模型在当前问题上的可靠性；
  - 如何让回灌比例、内环代数和退出阈值真正自适应；
  - 如何扩展到约束、多模态、离散、噪声和 many-objective 问题。

## 为什么可能有效

```text
昂贵评价限制真实搜索步数
-> 近期真实评价种群包含当前搜索区域的局部趋势
-> 代理内环用低成本评价产生可能领先当前主种群的候选解
-> 只回灌部分代理解，保留宿主算法原生子代和多样性
-> 真实评价验证代理候选，避免最终解完全依赖预测值
-> 档案生存贡献下降时停用代理，减少后期错误排序和训练开销
```

这个机制的关键假设不是代理必须全程高精度，而是早期代理排序与真实目标“足够相关”，能够产生若干可真实评价的领先候选解。

## 实现接口

- 输入：
  - 宿主算法当前已真实评价种群；
  - 宿主算法刚生成、尚未真实评价的子代；
  - 真实评价档案或可追踪代理来源的精英集合；
  - 每个目标的代理模型训练器。
- 输出：混合后的宿主子代，其中一部分来自代理内环，随后由真实目标函数评价。
- 插入位置：父代选择和子代生成之后，真实适应度评价之前。
- 最小实现：

```text
if surrogate_active:
    train_data <- last_true_evaluated_population
    models <- train_one_regressor_per_objective(train_data)
    surrogate_population <- estimate(main_offspring, models)
    for g in surrogate_inner_generations:
        surrogate_offspring <- evolve_with_surrogate(surrogate_population, models)
        surrogate_population <- update(surrogate_population, surrogate_offspring)
    candidates <- select_surrogate_nondominated(surrogate_population)
    main_offspring <- replace_at_most_ratio(main_offspring, candidates, ratio)
main_offspring <- true_fitness_evaluation(main_offspring)
update_archive_and_surrogate_status()
```

- P2026-0126 的默认实例：
  - 从第 2 代开始启用；
  - 训练集为最近一代真实评价种群；
  - 每目标单独训练 RFR、GPR 或 1D-CNN；
  - 代理内环代数取宿主代数设置的一半；
  - 最多回灌 50% 子代规模的代理非支配解；
  - 若代理解在档案中的 `t-2` 代生存比例降到历史最大值的一半，或达到第 50 代，则停用。

## 如何用于算法创新

### 局部创新

- 给已有 MOEA 增加代理加速模块，而不改变其环境选择和真实评价后的更新逻辑。
- 将固定真实评价子代中的一部分替换为代理内环生成的候选解。
- 用不同代理模型、训练窗口、回灌筛选和退出指标替换 P2026-0126 的默认设置。
- 对昂贵约束问题增加可行性代理或约束违反代理，使回灌候选同时满足可行性风险控制。

### 结构创新

- 构建由宿主搜索、代理探索和贡献监控器组成的三角色框架。
- 维护多个代理内环，让不同代理模型或不同区域竞争真实评价预算，再根据回灌后的真实贡献动态分配资源。
- 将“贡献半衰期退出”推广到其他辅助模块，例如局部搜索、知识迁移、降维搜索或辅助任务；辅助模块一旦贡献衰减即自动降权或停用。

## 适用条件与风险

- 适用条件：
  - 真实评价时间远大于代理训练和推理开销；
  - 决策变量到目标值的局部关系可由有限近期样本近似；
  - 宿主算法能记录候选解来源，并维护可统计代理贡献的档案或精英集合；
  - 允许早期更激进地探索，后期回到真实评价主导。
- 不适用或可能失效的条件：
  - 评价函数便宜，代理训练开销抵消收益；
  - 目标函数强噪声、强不连续或近期样本无法代表待评估区域；
  - 变量维数过高而种群规模太小，代理容易欠拟合或过拟合；
  - 代理候选在档案中的生存率不能代表真实长期贡献；
  - 100% 或过高比例回灌导致多样性损失和 building block 跳过风险；
  - 宿主算法没有外部档案，或档案更新与代理来源追踪不兼容。
- 计算与实现成本：
  - 每代可能训练多个目标代理；
  - 需要维护样本归一化、模型调参、代理内环、候选来源标签和退出状态；
  - 对 GPU/并行训练、缓存和模型复用有工程优化空间。
- 复现风险：
  - P2026-0126 Algorithm 2 第 9 行疑似将 `chi_t` 写成 `p_t`，实现时需按上下文修正；
  - 论文用固定 `rule of 1/2` 降低参数复杂度，但不同问题的最佳内环代数、回灌比例和退出阈值可能不同；
  - 真实案例只有单次运行，不足以证明统计稳定性。

## 证据边界

- 当前只有单篇论文证据。
- 直接实现和实验主要覆盖 NSGA-II 与 MOEA/D-DRA；对其他 MOEA 仍需移植实验。
- 论文主要处理无约束 2-3 目标问题；many-objective 只有两个 4 目标 DTLZ 变体的初步观察。
- 真实案例成本高但只有单次运行，不能作为统计稳定性证据。
- 部分问题族和代理-宿主组合出现负迁移或后期劣化，说明该模块需要可靠的模型选择和贡献反馈。
