# 不可行解辅助的种群组成管理

## 核心内容

在约束多目标优化中，不把不可行解简单视为失败个体，而是将其作为探索碎片化可行域和约束边界的资源。实现上先用环境选择算子过滤高质量可行解与有潜力不可行解，再用动态管理算子控制种群中的可行/不可行比例：可行解过多时补充不可行探索，不可行解过多时补充可行解推动收敛。

```text
父代 + 子代候选池
-> 用约束支配和密度筛选可行/不可行候选
-> 得到混合种群
-> 估计目标不可行比例
-> 不可行过少则替换低质可行解并补充不可行解
-> 不可行过多则删除高 CV 不可行解并补充可行解
-> 后续档案更新、局部搜索或主算法选择
```

## 建立理由

- 为什么值得独立维护：它提供了明确的“不可行解质量过滤 + 不可行比例控制”接口，可插入 constrained MOEA 的环境选择或种群更新阶段。
- 单篇具体方法的直接复用价值：P2026-0032 给出了 SIFO、DIMO、CMOEA-IAS 总框架和复杂度分析，并通过消融和迁移到 NSGA-II、INSGA-II、CEOA 的实验支持其有效性。
- 与已有设计知识的区别：
  - 不构造代理模型；
  - 不构造辅助任务；
  - 不做跨任务迁移；
  - 不修改目标空间流形选择；
  - 直接处理约束优化中的可行/不可行种群组成。

## 解决的问题

- 适用场景：
  - 可行域稀疏、碎片化或被复杂约束分割；
  - 早期可行解难找，或可行解过早集中在局部可行区域；
  - 不可行解中包含接近可行边界或目标质量较好的搜索线索；
  - 希望在已有 MOEA 中替换或增强可行性优先的环境选择。
- 现有方法为什么会失败或不足：
  - 可行优先规则可能过早丢弃轻微不可行但目标很好的候选；
  - 罚函数/额外目标需要权重或参数，可能使约束与目标错位；
  - 多任务或阶段切换方法可能依赖任务相似性和复杂资源调度；
  - 无控制地保留不可行解又会浪费预算在难以修复的区域。
- 仍需解决的问题：
  - 如何在线评价不可行解的长期贡献；
  - 如何自适应设置不可行比例而不是依赖初始种群；
  - 如何与局部修复、边界搜索和问题特定算子结合。

## 为什么可能有效

```text
复杂约束导致可行域小且碎片化
-> 只保留可行解容易在容易到达的局部可行区早熟
-> 轻微不可行或目标优秀的解可能位于通往更优可行区域的边界附近
-> 先筛选不可行解质量，避免无意义不可行探索
-> 再控制不可行解比例，避免种群被可行或不可行区域单方占据
-> 搜索可以同时推进可行性、收敛性和多样性
```

## 实现接口

- 输入：
  - 父代、子代或候选合并集合；
  - 每个候选解的目标值、总约束违反 `CV` 和可行性标签；
  - 种群规模 `NP`；
  - 可生成可行解和不可行解的算子或修复/反修复机制。
- 输出：大小为 `NP` 的混合种群，包含受控比例的可行解和不可行解。
- 插入位置：子代生成之后、下一代种群确定之前；也可作为 archive update 前的过滤模块。
- P2026-0032 的具体实现：
  - SIFO 使用严格约束支配：`x_i` Pareto 支配 `x_j` 且 `CV(x_i) <= CV(x_j)` 时才支配；
  - `SF=R+D`，其中 `R` 为基于严格约束支配的 raw fitness，`D` 为约束 shift 后的密度估计；
  - `SF<1` 的候选先进入临时档案，不足则按 `SF` 补齐，过多则删除拥挤解；
  - DIMO 用 `eta=Inf_num(P0)/NP` 和 `gamma=(rand(-0.01,0.01)+eta)*NP` 设定目标不可行数量；
  - 不可行过少时删除低质可行解并生成不可行解，不可行过多时删除高 CV 不可行解并生成可行解。

## 如何用于算法创新

### 局部创新

- 将基础 CMOEA 中的 feasibility-first 环境选择替换为“约束支配 + 不可行比例管理”。
- 为已有 NSGA-II、MOEA/D、PSO、DE 或路径规划算法增加不可行边界探索。
- 将固定不可行比例替换为基于可行解增长率、CV 下降率、HV 贡献或成功修复率的反馈控制。
- 对组合优化问题，用领域算子生成“可修复不可行解”；对连续问题，用约束边界采样或投影扰动生成不可行探索点。

### 结构创新

- 设计双库结构：可行精英库维护可执行高质量解，不可行边界库维护约束边界附近的探索解，再由统一选择器分配种群份额。
- 让不可行解比例成为在线资源分配变量，与代理模型、辅助任务、局部搜索或多任务迁移共享预算。
- 为不同约束类型维护不同不可行子种群，例如容量违反、时间窗违反、等式约束违反分别探索。

## 适用条件与风险

- 适用条件：
  - 约束违反可量化为可比较的 `CV`；
  - 不可行解经过少量变化有机会变为可行或接近更优可行区域；
  - 可行域碎片化、狭窄或早期难以找到；
  - 算法可以生成或修复可行/不可行候选。
- 不适用或可能失效的条件：
  - 不可行区域与可行优质区域几乎无连续或结构关系；
  - 约束极硬，任何不可行解都没有工程意义或不可修复；
  - `CV` 尺度归一化不稳定，使不同约束的重要性失真；
  - 不可行比例过高会浪费评价预算，过低则回到可行优先早熟；
  - 对约束较松或小规模问题，额外不可行管理可能不如简单可行优先。
- 计算与实现成本：
  - SIFO 至少需要 `O(NP^2 log NP)` 的密度和支配计算；
  - DIMO 需要生成补充可行/不可行解，成本取决于领域算子；
  - 若叠加局部搜索，整体成本可能由档案局部搜索主导。
- 复现风险：
  - P2026-0032 Algorithm 2 的条件行疑似应使用当前种群 `P` 的不可行数量，而非初始种群 `P0`；
  - `eta` 基于初始不可行比例，可能无法反映进化后期的真实需求；
  - SIFO 与 DIMO 的效果和领域局部搜索 ALSC 有交互，移植时需重新消融。

## 证据边界

- 当前只有单篇论文证据，虽然包含跨三种算法的移植实验。
- 主要验证场景是 MOVRPTW；对连续 CMOP、等式约束和动态约束问题没有直接实验。
- 较小或约束较松实例中，简单可行优先或已有 MOVRPTW 方法有时更好。
- CMOEA-IAS 并非在所有质量维度上最强：MMFEA/D 在非支配解数量和 NR 上非常接近或更高。
- DIMO 伪代码与正文存在潜在变量歧义，复现需核对实现。
