# 多目标优化科研知识库项目需求说明

当前版本：`V2.0-simple`  
当前原则：以最简单、可长期维护的结构保存论文知识。

## 1. 最终目标

本知识库不是普通论文摘要库，也不是复杂的数据管理系统。

它的目标是利用多目标优化论文中的真实知识，帮助研究者以某个已有算法为基础提出：

- 局部创新：修改、替换或增加某个具体方法；
- 结构创新：保留或迁移基础理念，重新设计算法角色、流程或信息交换结构。

知识库需要保存足够的论文依据，使后续研究能够回答：

```text
基础算法为什么需要修改？
可以采用什么论文知识？
为什么这种修改可能有效？
它适用于什么条件，有什么风险？
```

## 2. 当前资料位置

```text
论文 PDF：E:\多目标优化\pdfs
论文 Markdown：E:\多目标优化\MD
PlatEMO：E:\多目标优化\PlatEMO-4.15
知识库：E:\多目标优化\MO-Paper-KB
```

原始 PDF 和 Markdown 不批量重命名，由论文索引建立映射。

预计未来处理约 1000-2000 篇论文。每篇论文只建立一张论文卡，设计知识卡严格筛选并跨论文复用，从而控制维护规模。当前优先使用文件名和全文搜索，不提前建设复杂数据库。

论文处理使用轻量队列机制：自动扫描 `MD` 和 `pdfs`，将新增论文加入 `papers.csv`；每个新对话自动领取一篇未处理论文并标记为 `in_progress`，完成后标记为 `extracted`。同一 DOI 的多个来源副本自动合并，避免重复处理。

## 4. 三类内容的职责

### 论文索引

`00_index/papers.csv` 只负责记录论文 ID、标题、原始文件路径和处理状态，并由 `paper_queue.ps1` 统一维护，不要求人工逐行编辑。

### 论文卡

每篇论文建立一张论文卡，用于保存：

- 研究问题、应用场景和现有方法不足；
- 本文算法的核心理念、流程和主要方法；
- Introduction / Related Work 中的重要评价；
- 实验结论、局限和未来工作；
- 可复用知识与创新线索；
- 关键内容的章节或 PDF 页码。

论文卡是每篇论文唯一必须创建的知识文件。

### 设计知识卡

设计知识卡保存能够跨论文复用、并可用于改进算法或设计新结构的高价值知识。当前优先保存实现明确、能够直接改造算法的具体方法。

场景、失效原因、研究空白、方法、原理和架构模式不再分别建立卡片，而是在同一张设计知识卡中共同说明：

```text
它是什么？
解决什么问题？
为什么可能有效？
如何用于局部创新或结构创新？
适用于什么条件？
有什么风险？
有哪些论文证据？
```

设计知识卡不是每篇论文一张，而是每个高价值可复用知识一张。同一知识由多篇论文共同补充证据。单篇论文中抽象出的原理或架构思路，通常先保留在论文卡中。

## 5. 单篇论文处理规则

处理一篇论文时：

```text
1. 队列脚本自动领取下一篇并标记为 in_progress
2. 阅读 Markdown，必要时回查 PDF
3. 创建论文卡并记录可靠知识
4. 判断是否发现高价值可复用知识
5. 只有确有价值时才创建或更新设计知识卡
6. 队列脚本将成功完成的论文标记为 extracted
```

普通论文处理完成后，只产生一张论文卡是正常结果。

PDF 核验时允许临时生成页面截图。此类由处理流程自行生成、文件名明确包含论文 ID 的临时截图，应在核验结束后直接清理，不询问用户或弹出确认窗口；此授权不适用于原始 PDF、Markdown、论文卡、设计知识卡或其他用户文件。

## 6. 设计知识升级条件

新建设计知识卡前，必须先使用名称、别名、解决的问题和作用机制全文搜索现有卡片。

只有同时满足以下基本条件，才建立独立设计知识卡：

1. 能够用于修改其他算法或设计新结构；
2. 能明确说明所解决的问题和作用机制；
3. 具有可追溯的论文依据；
4. 值得未来跨论文查询和复用。

此外，还应至少满足以下情况之一：

1. 已被至少两篇论文采用、讨论或共同支持；
2. 虽然只来自一篇论文，但方法实现明确，可以直接移植或改造其他算法；
3. 当前研究已经明确准备使用该知识。

发现相同知识时，不新建卡片，只向原卡补充论文证据、实现差异、适用条件和限制。无法确认是否重复时，先留在论文卡。

小方法、普通事实、单篇论文抽象出的原理和架构、低置信度判断及未成熟想法，默认全部留在论文卡中。

## 7. 创新支持方式

### 局部创新

```text
基础算法论文卡中的流程与不足
-> 查找可以替换、增加或调整的设计知识
-> 在实际研究阶段形成局部修改方案
```

### 结构创新

```text
基础算法论文卡中的核心理念与结构不足
-> 查找可迁移的原理或架构设计知识
-> 在实际研究阶段重新设计整体结构
```

知识库不预先维护创意卡。阅读论文时产生的初步想法记录在论文卡的“创新线索”中；真正开始研究时，再单独撰写研究方案。

## 8. 证据规则

- Markdown 是深度提取的主要阅读、搜索和理解来源；
- PDF 是缺失、模糊或关键结论的定点核验来源，不默认通篇重复阅读；
- 重要结论记录章节或 PDF 页码；
- 区分作者观点、实验支持和我们的判断；
- 单篇论文的观点不能直接视为领域共识；
- 多篇论文评价冲突时，保留各自条件与来源。

## 9. 额度控制原则

额度控制只减少重复阅读，不降低论文深度提取和设计知识升级标准：

- 新对话只读取执行任务所需的最小规则文件集合；
- 不默认读取完整 `papers.csv`，论文信息以队列脚本输出为准；
- 不默认读取与当前论文无关的既有论文卡；
- 设计知识查重先查看极简索引，只打开相关卡片，必要时再定向全文搜索；
- 不重复从 PDF 阅读 Markdown 已经清楚、完整表达的内容；
- 初次阅读后需要回查时使用章节、关键词或行号定向定位，不重复整篇读取同一来源；
- 不能因节省额度而省略重要方法、实验证据、局限或创新线索。

## 10. 明确不维护的内容

当前知识库不建立或强制维护：

- 独立场景卡、失效机制卡和 Gap 卡；
- 分层的原理、模式和模块目录；
- 独立算法模型卡；
- 创意卡与候选算法目录；
- 方法提及、证据、关系、算法槽位和结构特征等复杂 CSV；
- 完整实验结果数据库；
- 每篇论文对应的所有小方法文件。

预计处理 2000 篇论文时，允许论文卡接近 2000 张，但设计知识卡必须严格控制为少量真正可复用的知识，不随论文数量线性增长。

## 11. 审查标准

审查本知识库时，只需重点判断：

1. 每篇论文是否能够被可靠理解和追溯；
2. 高价值设计知识是否能够跨论文积累；
3. 保存的知识能否帮助未来进行局部创新或结构创新；
4. 是否存在重复维护或不必要复杂度；
5. 日常处理流程是否足够简单，可以长期执行。
6. 新设计知识卡是否经过查重，是否确实值得独立维护。

任何新增目录、卡片类型或索引，都必须证明其价值明显高于维护成本。
