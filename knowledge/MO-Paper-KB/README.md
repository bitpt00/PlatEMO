# 多目标优化科研知识库

## 目标

本知识库用于从真实论文中积累可追溯的科研知识，帮助基于已有多目标优化算法提出：

- 局部创新：修改或替换算法中的某个方法；
- 结构创新：保留或迁移基本理念，重新设计算法整体结构。

知识库只负责保存论文知识和可复用设计知识，不预先创建新算法创意，也不负责代码实现与实验验证。

## 目录

```text
MO-Paper-KB/
  00_index/             论文索引与简单处理规则
  01_papers/            每篇论文一张论文卡
  02_design_knowledge/  跨论文复用的设计知识卡
  03_templates/         论文卡与设计知识卡模板
  项目需求说明_供AI审查.md
  README.md
```

## 新开对话处理论文

不需要在同一个对话中连续处理全部论文。每次新开一个对话处理一篇论文时，让 AI 先阅读并执行：

```text
E:\多目标优化\MO-Paper-KB\00_index\新对话处理单篇论文_执行指令.md
```

新对话会运行队列脚本，自动发现新增论文、领取下一篇并标记为处理中，不需要手工提供论文路径。该执行指令已经包含详细提取要求、PDF 核验规则、设计知识查重和完成标记。

PDF 核验过程中由 AI 自行生成的临时页面截图，会在核验结束后作为流程内临时文件直接清理，不需要用户逐次确认。该规则不适用于原始论文文件或知识库文件。

为减少重复额度消耗，新对话默认只读取执行指令要求的最小文件集合，不重复读取内容相同的规则文档、完整 `papers.csv` 或全部设计知识卡。论文仍执行深度提取；Markdown 是主要阅读来源，PDF 只对缺失、模糊或关键内容进行定点核验。

## 添加新论文

将新论文放入：

```text
E:\多目标优化\MD
E:\多目标优化\pdfs
```

Markdown 与 PDF 建议使用相同文件名，仅扩展名不同。下一次运行队列的 `status` 或 `claim` 时，新论文会自动加入 `papers.csv`。

同一 DOI 的多个来源副本会自动合并，只领取一个代表文件。Markdown 或 PDF 暂时缺失时会标记为 `missing-md` 或 `missing-pdf`，文件配齐后自动转为 `unprocessed`。

默认按加入队列时间和文件名依次处理。用户明确需要优先处理某篇已登记论文时，可以使用论文 ID 指定领取。

## 日常处理方式

阅读一篇论文后，默认只做两件事：

1. 在 `01_papers/` 创建一张论文卡；
2. 运行队列脚本的 `complete` 命令，将论文标记为已提取。

只有发现真正能够用于改进其他算法、设计新结构，并且值得以后跨论文反复使用的知识时，才创建或更新 `02_design_knowledge/` 中的设计知识卡。具体、可直接复用的方法优先；单篇论文抽象出的原理和架构通常先留在论文卡。

```text
阅读论文
-> 创建论文卡
-> 发现高价值可复用知识？
   -> 否：结束
   -> 是：先查看设计知识极简索引，只打开相关卡片
      -> 已存在：补充新论文证据
      -> 不存在：满足严格升级条件后才新建
```

`02_design_knowledge/README.md` 中的极简索引用于快速定位可复用知识。处理论文或设计创新时先查看索引，不默认通读整个设计知识目录；索引无法判断时再进行定向全文搜索。

## 两种创新如何获得支持

### 局部创新

从论文卡理解基础算法流程和具体不足，再查找可直接替换、增加或调整的设计知识。

```text
基础算法的论文卡
-> 找到具体问题或可修改位置
-> 查找适用的设计知识
-> 形成局部修改方案
```

### 结构创新

从论文卡理解基础算法的核心理念和结构问题，再查找可迁移的原理或架构知识，重新设计角色、流程和信息交换方式。

```text
基础算法的论文卡
-> 理解核心理念和结构不足
-> 查找可迁移的设计知识
-> 重新设计整体结构
```

具体研究方案在真正开始研究时单独撰写，不作为知识库固定卡片。

## 最简原则

1. 每篇论文只强制创建一张论文卡；
2. 不要求每篇论文产生设计知识卡；
3. 场景、失效原因、研究空白、方法、原理和架构统一写入设计知识卡，不分别建目录；
4. 普通小方法和未成熟知识只留在论文卡；
5. 同一设计知识只建一张卡，多篇论文共同补充证据；
6. 关键结论必须能够追溯到论文章节或 PDF 页码；
7. 不维护创意卡、算法模型卡、复杂关系表和多层数据库结构；
8. 新增文件前，先判断它是否会直接帮助未来的局部创新或结构创新。
9. 单篇论文提出的抽象原理和架构思路默认不升级，等待跨论文支持或实际研究需要；
10. 新建设计知识卡前必须先全文搜索现有卡片，无法确认是否重复时先留在论文卡。
