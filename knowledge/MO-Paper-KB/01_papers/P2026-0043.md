# Self-adaptive resource allocation based on reinforcement learning for multi-concept multi-objective optimization

## 一句话理解

论文面向 multi-concept MOP：同一个设计任务存在多个独立候选概念/方案，每个概念有自己的变量空间、目标函数和约束。SARL-MCMOP 用两个指标刻画概念价值：`Fscore` 表示当前收敛水平，`IGDp` 表示演化潜力；再用 reinforcement learning 更新概念 `Value` 和 `State`，让优势概念获得更高进化概率和更多环境选择保留名额，同时给初期表现差但有潜力的概念保留机会。

## 问题与动机

- 研究问题和场景：
  - multi-concept multi-objective optimization problem (MCMOP) 中，一个工程对象可由多个结构概念或技术路线实现；
  - 每个 concept 有不同的设计变量、目标函数、约束和 Pareto front；
  - 总体目标不是分别优化每个概念，而是在所有概念的并集中寻找全局 Pareto front；
  - 论文用悬臂梁截面概念举例：圆形、矩形、L/I/T 等截面可视为不同设计概念。
- 现有 MCMOP 策略的不足：
  - independent evolutionary strategy 为每个概念固定相同资源，可靠但浪费预算，收敛慢；
  - representation-based strategy 根据当前全局非支配解中各概念占比重分配资源，收敛快但容易过早淘汰初期表现差的潜在优势概念；
  - minimum-resource guarantee strategy 给每个概念保底个体数，比纯占比法更稳，但仍缺少可解释的概念价值评估；
  - 这些策略没有同时考虑“当前收敛好”和“未来仍有演化空间”。
- 本文希望解决什么：
  - 自动识别 advantageous concepts；
  - 自适应分配每个概念的进化计算资源；
  - 在环境选择中给优势概念更多个体，同时避免过早清空潜在优势概念；
  - 提高 MCMOP 的收敛速度和最终精度，尤其是有主导概念或部分优势概念初期表现差的 Type-I/Type-II 问题。

## 核心理念与算法流程

- 核心理念：
  - 概念级资源分配不能只看当前非支配占比；
  - `Fscore` 负责度量概念当前解集的收敛质量；
  - `IGDp` 负责度量从旧种群到新种群的改进空间/演化潜力；
  - `State` 作为硬门控，标记某概念是否已稳定且被其他概念支配；
  - `Value` 作为软价值估计，控制该概念下一代被进化的概率和环境选择个体配额。
- SARL-MCMOP 主循环：
  - 初始化每个概念的种群、`Value[i]=1` 和 `State[i]=1`；
  - 每代对每个概念抽样判断 `rand < Value[i]`，决定是否给该概念生成 offspring；
  - 合并父代和子代后，对所有概念执行环境选择；
  - 通过 reinforcement learning 模块根据旧/新种群目标值更新 `IGDp`、`Fscore`、`State`、`Reward` 和 `Value`；
  - `Value` 越高，该概念越可能继续获得进化机会。
- 概念状态检测：
  - 前 10 代保持相对充分探索，不急于淘汰概念；
  - `t > 10` 后，如果一个已进化概念的 `IGDp < 0.005`，说明其种群演化趋于稳定；
  - 再做全局非支配排序，如果该概念个体被其他概念个体支配，则将 `State[i]=0`，减少后续资源浪费；
  - 若仍有非支配贡献，则保持 `State[i]=1`。
- 强化学习反馈：
  - 奖励函数综合归一化后的 `Fscore` 与 `IGDp`；
  - 参数 `a` 随代数衰减，用于调节当前收敛与未来潜力的权重；
  - `State[i]=0` 时直接让 `Reward=0`；
  - `Value` 由历史值和即时 reward 平滑更新，避免概念价值因单代波动剧烈震荡。
- 环境选择：
  - 早期仍使用普通非支配排序和拥挤距离，让各概念种群统计特征先稳定；
  - 后期根据各概念 `Value` 计算保留个体数，并设置上限和 `Nmin` 下限；
  - 先在每个概念内部保留一部分，再把剩余候选跨概念合并做一次环境选择，补足总体种群规模；
  - 目标是在优势概念上集中个体资源，同时给潜在优势概念保留最低探索空间。

## 实验证据

- 实验设置：
  - 测试集为 28 个 MCMOP suite 问题，覆盖 Type-I、Type-II、Type-III 和部分三目标实例；
  - 每个算法每个问题运行 31 次；
  - 指标包含 IGD+、HV、Spacing，并用 Wilcoxon rank sum test 做显著性比较；
  - 主要对比传统 MCMOP 的 S1/S2 两类策略，以及仅替换进化策略或环境选择策略的消融变体。
- 总体性能：
  - 摘要报告 SARL-MCMOP 在 28 个问题中的 18 个上显著优于传统方法；
  - 作者报告最优情况下 median performance improvement 约 70%；
  - 在 Type-I 问题中，SARL-MCMOP 对 MCMOP_S1 的优势主要体现在更快收敛和更高精度；
  - 对 MCMOP_S2 的优势更多体现在能找到被 S2 过早忽略的优势前沿。
- 进化资源分配消融：
  - Table 6 显示，在使用 S1 环境选择时，SARL 进化策略在 40%、60%、80% 预算处的优势更明显；
  - Table 7 显示，在使用 S2 环境选择时，SARL 进化策略能帮助 Type-II/Type-III 中初期表现差的优势概念重新获得资源；
  - Fig. 8 的资源分配曲线显示，优势概念的进化概率随迭代上升，劣势概念下降。
- 环境选择消融：
  - Table 8/9 比较 SARL 环境选择与 S1/S2 环境选择；
  - 作者总结 SARL 环境选择可更合理地分配各概念个体资源，提升最终收敛精度；
  - Fig. 10 显示优势概念获得更多个体，且不像纯占比策略那样过度失衡。
- RL 模块识别潜在优势概念：
  - Table 10 报告 critical problems 上 SARL-MCMOP precision 高于 MCMOP_S2；
  - MCMOP_II1、II2、II3、II6 上 SARL precision 分别为 0.8065、0.7742、0.9677、1.0；
  - 对应 MCMOP_S2 为 0.5806、0.7419、0.7742、0.7419；
  - 这支持 RL 模块能识别并利用执行过程中出现的优势概念。
- 证据边界：
  - Type-III 问题上表现不如 Type-I/Type-II 稳定，因为所有概念都可能贡献 PF，贪心资源集中会牺牲长期低回报概念；
  - 三目标问题中，当前演化算子本身难以搜索真实前沿，单靠资源分配不能解决；

## 局限与未来工作

- 作者明确说明的局限/未来方向：
  - Type-III 问题和 tri-objective 问题仍有提升空间；
  - SARL-MCMOP 机制偏“贪心收敛加速”，对需要长期投资的概念缺少战略耐心；
  - 将初始参数 `a` 从 0.9 降到 0.7 可增强探索和多样性，但会降低收敛速度；
  - 未来需要更复杂的概念评价方法，例如动态权重或 problem-specific features；
  - 可并行化独立概念进化、使用 approximate sorting 或 adaptive population reduction 降低非支配排序成本。
- 我们认为仍需确认的问题：
  - `Fscore` 与 `IGDp` 的归一化是否对目标尺度、概念维度和概念 population size 敏感；
  - `t>10` 和 `IGDp<0.005` 是否能跨问题泛化，还是需要按 budget/维度自适应；
  - `Value` 作为概率时，低价值概念是否仍有非零探索概率，避免 Type-III 长期概念被饿死；
  - 与 bandit、Bayesian optimization 或 contribution-based scheduling 的正面对比还不足；
  - 真实工程 MCMOP 的概念建模、变量异构和约束异构会比 benchmark 更复杂。

- 值得建立或补充的设计知识：
  - 新建设计知识：[RL 优势概念识别的多概念资源分配](../02_design_knowledge/K-rl-advantage-concept-resource-allocation.md)。它抽象出“概念/方案作为资源单元，收敛质量 + 演化潜力 + 状态门控 + RL 价值”这一类 MOO 资源分配模式。
- 与已有设计知识的边界：
  - 不同于 [贡献自适应的多种群多目标协同](../02_design_knowledge/K-contribution-adaptive-mpmo-coevolution.md)，本文的资源单元不是按目标划分的子种群，而是具有不同变量空间和约束的候选设计概念；
  - 不同于 [状态驱动的 DRL 演化算子选择](../02_design_knowledge/K-drl-state-driven-evolutionary-operator-selection.md)，本文不是选择 GA/DE/PSO 等算子，而是决定哪个概念获得进化机会和个体配额；
  - 不同于 [Actor-Critic 自适应生态位环境选择](../02_design_knowledge/K-actor-critic-adaptive-niche-selection-mmop.md)，本文不调 niche size，而是调跨概念的资源分配；
  - 不同于 [双空间分层自适应资源分配](../02_design_knowledge/K-dual-space-hierarchical-resource-allocation.md)，本文没有变量组/搜索区域层级，而是面向多概念设计路线的异构资源调度。
- 局部创新线索：
  - 用 contextual bandit 替代固定 RL reward，显式建模概念特征、阶段和 uncertainty；
  - 给 `Value` 加最小探索概率或 UCB bonus，缓解 Type-III 长期潜力概念被饿死；
  - 把概念状态从二值 `State` 扩展为 active、sleep、probe、retired 四态；
  - 用 archive contribution、reference-region gap 或 HV contribution 替代单一 `Fscore`；
  - 对每个概念维护低频 probe budget，周期性测试被压低资源的概念是否恢复潜力。
- 结构创新线索：
  - 形成通用多方案 MOO 框架：concept registry -> concept-level indicators -> value scheduler -> per-concept evolution -> global environmental selection -> state update；
  - 可迁移到多结构拓扑设计、多材料方案选择、多工艺路线优化、多 operating mode 控制和多仿真模型选择。
