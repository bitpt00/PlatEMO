# Optimally solving multi-objective co-scheduling of lock group and approach channel with dynamic synchronous speeds

## 一句话理解

本文面向三峡-葛洲坝枢纽的锁群与引航道绿色协同调度，建立同时优化水资源利用率、船舶有序加权等待时间和碳排放的混合整数模型，并提出 MOISM：用船舶顺序链与锁/升船机分配链表达解，再通过船舶装载、航行时序和闸次运行三阶段动态解码保证可行，最后用 FREA 适应度、协同离散 DE 和改进 VNSA 搜索高质量 Pareto 调度。

## 问题与动机

- 研究场景：Three Gorges-Gezhou Dams (TGGD) 内河通航系统，包含三峡大坝南/北线五级船闸、三峡升船机、葛洲坝 1/2/3 号船闸、锚地和引航道。来源：Sec. 3.1、Fig. 1。
- 新问题：green co-scheduling problem of lock group and approach channel (GCSP-LG&AC)，同时考虑 lock group、approach channel、ship lift、dynamic synchronous speeds、ship placement、freeboard height、maneuvering capability 和 carbon emissions。来源：Abstract、Sec. I。
- 现有研究不足：
  - 传统扩建或新增设施成本高、周期长且受地理空间限制；水陆转运只能转移部分货物且成本高；更现实的路径是优化已有船闸和引航道资源。来源：Sec. I。
  - 既有 TGGD 锁群调度多关注三峡五级船闸和葛洲坝船闸，或只处理船闸/升船机/引航道中的部分资源，缺少多资源协同。来源：Sec. II。
  - 既有方法未同时纳入 synchronous moving process、freeboard height、maneuvering capability 和 carbon emissions，导致真实约束与绿色目标不足。来源：Sec. II、Table 1。
  - 普通 LSP 编码/解码难直接处理 GCSP-LG&AC，因为任务顺序、双坝路径、闸室二维装载、等待区容量、船队同步速度和闸次时序强耦合。来源：Sec. II、IV。
- 本文目标：在不新增大规模基础设施的前提下，通过锁群-引航道协同调度减少拥堵、等待和碳排，同时保持水资源利用。

## 核心理念与算法流程

- 问题建模：
  1. 将 GCSP-LG&AC 类比为带 batch machines 的 bidirectional flexible flow-shop：grouping area、waiting area 和 chambers 类似机器，ships 类似 jobs。来源：Sec. 3.1。
  2. 分解为三个子问题：ship navigation、ship placement、lockage operation scheduling。来源：Sec. 3.1。
  3. 三目标为最大化 water resource utilization (WRU)、最小化 ordered weighted averaging of waiting time (OWT)、最小化 total carbon emissions (TCE)。来源：Sec. 3.3.1。
  4. 动态同步速度由 lockage 内船舶平均 maneuvering capability 和 freeboard height 标准差共同影响，用于同步移动、进闸和出闸速度设置。来源：Sec. 3.3.1、Fig. 3。
- MOISM 主流程：
  1. Dual-chain encoding：第一条链用 random key 生成船舶排列和上下行方向；第二条链用两位整数表示每艘船经过的 TGD/GD 设施组合，并检查 ship lift、Lock 3 尺寸和吃水约束。来源：Sec. 4.1。
  2. Population initialization：用 FCFS 按到达时间构造一个启发式解，用 modified bottleneck elimination mechanism (BEM) 修正锁分配不均衡，再混合随机个体形成初始种群。来源：Sec. 4.2。
  3. Three-stage dynamic decoding：先做 ship placement，把连续船舶装入虚拟闸室直到二维装载约束失效；再计算锚地、虚拟编组区、等待区的到达/离开/等待时间；最后根据前一闸次、转换时间、处理时间和等待区到达时间确定各闸次进出时间。来源：Sec. 4.3。
  4. FREA-based FEM：把 `RU=1-WRU`、OWT、TCE 转成比较点，按每代动态 ideal/nadir point 构造 fuzzy sets，并用 fuzzy relative entropy coefficient `rho` 作为个体 fitness，`rho` 越大越接近理想点。来源：Sec. 4.4。
  5. Collaborative DDE：对双链结构执行 DE/best/1 型离散变异、单点协同交叉和基于 `rho` 的选择；交叉概率随当前个体 `rho` 相对最大/平均 fitness 自适应。来源：Sec. 4.5。
  6. Modified VNSA：只对较优的 `N%` 个体执行 ship-based exchange、ship-based insertion、facility-based exchange、facility-based multiple-point mutation 四类邻域，并用 SA 接受机制避免局部最优。来源：Sec. 4.6。

## 实验证据

- 实验设置：
  - 数据来自 TGGD 历史数据、已有文献和随机生成 ship information；实验环境为 AMD R5-5600h 3.30 GHz、16 GB RAM、Windows 11、MATLAB R2019a。来源：Sec. 5、5.1。
  - 船数从 `{80,100,200,300,500,800}` 采样；船舶重量 `U[1500,6000]` tons，长度 `U[82,107]` m，宽度 `U[14,18.2]` m，到达时间服从 `N(10,5^2)`；速度、freeboard height、maneuvering capability 分别为 `U[1,1.5]` m/s、`U[8,18]` m、`U[1,10]`。来源：Sec. 5.1。
  - 船闸有效尺寸、转换时间、闸门/灌泄水时间和升船机时间来自 TGGD 实际/文献参数。来源：Sec. 5.1。
  - 评价指标：improvement rate (IR) 和 hypervolume (HV)，HV reference point 为 `[1.2,1.2,1.2]`。来源：Sec. 5。
  - Taguchi 标定得到 MOISM 最优参数：`P=120, F=0.2, CRmin=0.3, CRmax=0.7, N=15`，每组运行 20 次、120 代。来源：Sec. 5.2。
- 算法对比：
  - 对比 CAMOA、MOEA/D、NSGA-II、SPEA-II；公平性处理包括相同编码/解码和 HV 参考点，且为各对比算法做 Taguchi 参数标定。来源：Sec. 5.3。
  - 基于补充表 S.1，MOISM 的 WRU 相对四个算法分别提升 `1.265% / 14.097% / 13.514% / 17.447%`；OWT 分别降低 `2.731% / 23.275% / 19.428% / 21.728%`；TCE 分别降低 `3.441% / 17.841% / 14.007% / 8.432%`。来源：Sec. 5.3。
  - 基于补充表 S.2，MOISM 在全部 12 个测试实例上平均 HV 最大。来源：Sec. 5.3。
  - 基于补充表 S.3，五个算法的平均 WRU 分别为 `67.6576% / 58.8649% / 59.2644% / 56.5687% / 68.3974%`，平均 OWT 为 `61.5785h / 73.8929h / 71.5873h / 72.9659h / 59.9417h`，平均 TCE 为 `5,171,988,278 / 5,891,998,679 / 5,700,266,089 / 5,421,533,460 / 4,999,936,615` tons；MOISM 对应最后一组，为最优平均目标。来源：Sec. 5.3。
  - MOISM 在 12 个问题中除 `80 x Route-1`、`200 x Route-1`、`500 x Route-1` 三个场景略弱外整体更优；Kruskal-Wallis ANOVA 在 95% 置信区间下支持 MOISM 与对比算法显著区分。来源：Sec. 5.3、Fig. 10。
  - 三维解集可视化显示 MOISM 解集更接近 ideal point 且分布更均匀；CAMOA 小规模较好但大规模退化，MOISM 在 300/800 船大规模问题上更稳定。来源：Sec. 5.3、Fig. 11。
- 同步通行布局：
  - 四种布局：Layout 1 无同步过程，Layout 2 在锚地编组并全程同步，Layout 3 将等待区视为并行缓冲且不规则过闸，Layout 4 在各通航设施设置一个虚拟编组区和一个虚拟等待区。来源：Sec. 5.4、Fig. 12。
  - 6 个船数实例的平均 OWT/TCE：Layout 1 为 `76.2728h / 6,250,677,909 tons`，Layout 2 为 `73.7190h / 6,111,956,510 tons`，Layout 3 为 `70.0099h / 5,876,983,282 tons`，Layout 4 为 `70.9225h / 5,939,644,033 tons`。来源：Table 4。
  - 管理启示中作者总结 Layout 3 相对 Layout 1 平均等待时间降低 `8.946%`、碳排降低 `6.359%`。来源：Sec. 5.6。
  - 作者也指出 Layout 3 把多等待区当并行缓冲在实际引航道空间中可能有碰撞风险；Layout 4 更符合“一个虚拟编组区 + 一个虚拟等待区”的实操结构。来源：Sec. 5.4。
- 等待区容量：
  - 对 `{100,500}` 艘船、三类等待区容量 `Z1/Z2/Z3`、四条典型路线构造 24 个场景，每个重复 20 次。来源：Sec. 5.5。
  - 平均 OWT/TCE：`Z1=53.3139h / 2,630,350,273 tons`，`Z2=50.3256h / 2,529,806,065 tons`，`Z3=54.2033h / 2,672,681,381 tons`。来源：Table 5。
  - 从 0 个等待区增加到 1 个等待区可降低等待时间 `5.938%`、碳排 `3.974%`；继续扩张到 2 个等待区出现收益递减或负效应，同时增加空间和建设成本。来源：Sec. 5.6。
  - 路线选择也显著影响性能：增加升船机或葛洲坝 Lock 3 可改善通航表现；三峡五级船闸结构会增加通过时间。来源：Sec. 5.5。

## 局限与未来工作

- 作者指出，船速是碳排关键因素，但本文尚未做速度-排放关系的详细敏感性分析。来源：Sec. 5.6。
- MOISM 的 FREA-based FEM 能提升解质量，但增加计算复杂度；未来需要开发更轻量、高效、适合实时调度的多目标算法。来源：Sec. 5.6。
- 作者计划扩展到设备故障、水位波动、天气变化等动态不确定事件，需要 robust rescheduling 和 rolling-horizon frameworks。来源：Sec. 6。
- 作者承认本文尚未通过真实工程应用现场验证导航性能，未来需要收集更多实际数据并建立智能调度系统。来源：Sec. 6。
- 未来还希望结合 machine learning、reinforcement learning、surrogate models 和 hyper-heuristic strategies 提高动态环境下的效率与适应性。来源：Sec. 6。
- 我们认为仍需注意：
  - 对比算法共享了 MOISM 的编码/解码，性能差异不能完全归因于算子或 FREA；
  - Tables S.1-S.3 的完整逐实例数值在当前 Markdown 中不可见；
  - TCE 数值单位和量级很大，实际碳排核算口径需要回查公式和行业参数；
  - Layout 3 在数值上最好但实际安全可行性受到引航道空间约束，不能直接作为推荐方案。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建“双链同步通行的船闸-航道动态解码”：抽象为在强约束多阶段通行调度中，用任务顺序链和资源路径链表达候选，再用领域三阶段动态解码器生成可行时空排程。
- 暂留在论文卡中的方法、原理或架构启发：
  - dynamic synchronous speed 把安全通行能力从固定速度参数变成由编队内 freeboard dispersion 和 maneuvering capability 决定的状态量；
  - OWT 用 ordered weighted averaging 体现大船或高权重船舶等待的服务公平/优先级；
  - 等待区容量不是越大越好，过度同步会带来 stop-go、空间和建设成本。
- 局部创新线索：
  - 将 FREA fitness 换成 Pareto rank + 业务偏好诊断，比较是否能保持可解释性并降低复杂度；
  - 用学习模型预测不同布局/等待区的拥堵风险，再指导 BEM 或局部搜索；
  - 将 `CR` 自适应从 `rho` 扩展为可行率、锁负载不均衡、等待区拥堵和碳排梯度联合反馈；
  - 对 Layout 3 的碰撞风险加入安全约束或仿真验证，避免只按目标值选布局。
- 结构创新线索：
  - “双链编码 -> 领域可行修复 -> 多阶段动态解码 -> 结构保真 DDE/VNSA”的框架可迁移到多船闸系统、港口进出港、机场跑道-滑行道-机位、AGV 通道和多工位阻塞流水线；
  - 与滚动时域结合后，可把已执行闸次锁定，只重新优化未来船队和等待区；
  - 与鲁棒场景结合后，可同时处理水位、天气、设备故障和船舶迟到。
