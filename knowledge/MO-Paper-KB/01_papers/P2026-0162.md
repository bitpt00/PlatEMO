# Implementing automated task scheduling framework for fog network using adaptive actor critic deep reinforcement learning with sparse attention through multi-objective constraints

## 一句话理解

论文提出 IRC-DOA-A-ACDRL-SA，用于 cloud-fog 网络中的自动任务调度：A-ACDRL-SA 以任务属性、VM/节点状态、能耗和 trust 为状态，用 actor-critic 学习任务到 fog node/VM 的分配策略；sparse attention 只关注 top-k 关键任务-资源关系以降低状态交互成本；IRC-DOA 作为改造 Dollmaker Optimization Algorithm 的元启发式调参层，优化奖励、惩罚、优先级、steps/episodes 等调度参数。实验报告显示该框架在 latency、energy、makespan、deadline violation 和 sparse-attention 开销上优于若干基线。

## 问题与动机

- 研究问题和场景：
  - IoT 产生的大量任务需要在 edge/fog/cloud 之间动态调度；
  - fog node 靠近数据源，可降低 latency，但资源有限且能耗敏感；
  - cloud 有更强计算与存储能力，但远距离传输会增加 latency 和带宽压力；
  - task scheduling 需要同时处理 latency、energy、makespan、CPU load、storage utilization、trust、deadline 和 task dependency。
- 现有方法为什么不足：
  - 静态或规则调度难以适配动态任务到达、节点负载变化和异构硬件；
  - 传统 GA/PSO/ACO/SA 等元启发式可能局部收敛、后期收敛慢、在线适应弱；
  - DDPG/MODRL 等 DRL 方法在大状态空间、复杂任务依赖和大规模部署中计算成本高；
  - 全注意力会显式建模大量无关 task-resource 交互，状态维度和训练开销膨胀。
- 本文希望解决什么：
  - 用 actor-critic 在线学习 task allocation policy；
  - 用 sparse attention 过滤不重要的任务/资源关系；
  - 用 IRC-DOA 自适应调节调度超参数、奖励/惩罚和优先级相关参数；
  - 在多约束目标下获得低延迟、低能耗、高吞吐和较少 deadline violation。

## 核心理念与算法流程

- 核心理念：
  - 调度决策可建成 MDP：状态描述任务与 fog/cloud 资源，动作是任务分配，奖励融合 QoS 和 trust；
  - actor-critic 负责在线学习策略，sparse attention 负责压缩关键交互，IRC-DOA 负责外层调参；
  - 任务优先级先把 deadline、资源需求、依赖关系和重要性转成可排序分数，再交给 RL 调度策略细化。
- 任务类型：
  - sequential tasks：必须按顺序执行；
  - parallel tasks：可同时分配给多个 VM/fog node；
  - dependency-based tasks：按 DAG predecessor completion 判断是否 ready；
  - 论文强调 Eq. 15 假设 DAG 依赖，避免 cyclic constraints 造成任务永久等待。
- MDP 建模：
  - state 包含 task vector `[U_i, M_i, S_i, E_i, J_i]`，其中包含任务长度、资源需求、deadline 和 impact parameter；
  - state 还包含 VM/fog node workload、CPU capacity、energy consumption、system trustworthiness 等；
  - action space 为将任务分配给 `M` 个 fog nodes、每个 node 的 `N` 个 VM，即离散动作规模约 `M x N`；
  - actor 输出任务分配策略，训练时加入 Gaussian noise 促进探索；
  - critic 估计状态-动作的累计 reward，用 MSE critic loss 和 target network soft update 稳定训练；
  - replay buffer 存储 `(state, action, reward, next_state)`，小批量采样更新 actor 与 critic。
- Reward / priority / constraint：
  - reward 函数混合 makespan、energy consumption、trust/prior priority 等；
  - priority score 使用任务时长、资源需求、deadline、依赖数和任务重要性等因素；
  - 多约束目标包括 response time、makespan、queuing delay、processing delay、latency、CPU load、storage utilization；
  - 文中给出 `Fit_k = F1 + F2` 的组合式目标，其中包含 reward 和各类 delay/utilization penalty。
- IRC-DOA：
  - 基于 Dollmaker Optimization Algorithm；
  - 主要优化 A-ACDRL-SA 的 steps、episodes、reward/penalty、priority 和 node-selection 相关参数；
  - 关键改造是用 current fit、best fit、mean fit、worst fit 更新随机系数 `r_k`，试图让搜索在探索和开发之间自调节；
  - population size 设为 10，chromosome length 为 2，max iterations 为 50。
- Sparse attention：
  - 对每个 query 只选择一组 key，而不是访问所有历史 key；
  - 在任务调度中用于筛选关键 task-resource 交互、重要依赖边和相关节点状态；
  - 论文声称 full self-attention 的状态交互复杂度可由近似二次降低到 top-k 相关的线性/次二次开销；
  - sparse attention 不是随机稀疏，而是保留 DAG 依赖和任务资源相关性。
- 必须保留的核心：
  - DAG 依赖和 ready-condition 应在调度层显式维护，不能完全交给 attention 学习；
  - sparse attention 只可剪去无关 task-resource 交互，不能剪断关键依赖边；
  - reward/penalty 的多目标缩放需要归一化或外层调参，否则某个指标会主导学习；
  - 调度框架应区分 micro fog nodes 与 macro fog nodes 的能耗/容量模型。

## 实验证据

- 仿真设置：
  - Python 实现；
  - 硬件记录为 Windows 11、i3、8GB RAM、500GB ROM；
  - 软件/库包括 PyCharm、Anaconda、Keras、TensorFlow、OpenCV、tflearn、matplotlib、numpy、prettytable；
  - fog topology 示例包含 50 fog nodes、300 edge devices、1 cloud node；
  - network topology 示例为 hierarchical tree 3-tier，平均 latency 34.6 ms，energy 482.1 J；
  - IRC-DOA population size 10，chromosome length 2，max iterations 50。
- 收敛与调度性能：
  - 收敛分析中，IRC-DOA-A-ACDRL-SA 在第 30 次迭代的 cost function 相对 DOA/SOA/GOA/FLO 组合分别更低；
  - Table 9 中 IRC-DOA final latency 112.7 ms、energy 98.4 J、120 iterations convergence，优于 GA 和 PSO；
  - 论文总结在第 5 configuration 的 energy consumption 上，相对 FLO/GOA/SOA/DOA 组合提升 10.71%、9.5%、10.71%、11.50%；
  - 相对 ACDRL/MODRL/MGWO/DDPG，第 1 configuration 提升约 3.6%、2.4%、4.7%、4.19%。
- Sparse attention 证据：
  - Table 4：with sparse attention 使稳定 reward 的收敛 episode 从 600-800 降到 350-450，peak reward 提升到 1.15-1.25，单 episode 训练时间降到 0.75-0.85 倍；
  - Table 14：600 epochs 时 dense MLP average reward 0.93，sparse attention 为 1.18；
  - Table 15：A-ACDRL+sparse attention 的 mean reward 1.18、std 0.031、latency 156 ms、energy 9.1 J、training time 245 s，优于无 attention 和 dense attention；
  - Table 20：A-ACDRL-SA FLOPs 9.7e9、inference latency 96.5 ms、training time 3.84 s/epoch、energy 452.8 J，低于 no attention 和 dense attention；
  - Table 32：top-k sparse attention 在 `N_t=100-500` 下比 full attention 时间降低 6.7x 到 21.6x。
- 真实/模拟 workload 证据：
  - Table 16 iFogSim workloads：A-ACDRL-SA latency 156 ± 5 ms、energy 9.0 ± 0.2 J、task completion rate 95.1%、CPU utilization 77.6%、convergence episodes 380；
  - EdgeCloudSim workloads：A-ACDRL-SA response time 215 ± 8 ms、energy 10.3 ± 0.2 J、reward 1.18 ± 0.02、total train time 546 ± 35 s、model params 2.9M；
  - Table 17 ablation：完整 A-ACDRL-SA + IRC-DOA energy 98.4 ± 2.1 J、CPU utilization 83.5 ± 1.5%、task success 96.3 ± 1.1%，优于只用 sparse attention 和随机调参；
  - Table 19：相对 Round-Robin、Min-Min、GA、Actor-Critic DRL，提出方法 energy 98.4 J、delay 112.7 ms、makespan 123.5 ms、throughput 72.4 tasks/sec。
- 多目标/Pareto 证据：
  - Table 25：IRC-DOA 在 multi-objective tuning 中 HV 0.412、GD 4.8、42 个 non-dominated 解、min latency 112.7 ms、min energy 98.4 J，优于 NSGA-II、NSGA-III 和 MOEA/D，但 tuning time 3600 s 高于对比算法；
  - Table 28：A-ACDRL-SA + IRC-DOA offloading 策略 energy 68.9 J、latency 112.7 ms，优于 fog-only、cloud-only、static hybrid 和动态 A-ACDRL；
  - Table 33 给出 energy/latency/trust/priority 四权重下的 Pareto frontier 样例，显示低负载、中负载和高能耗约束场景下的 trade-off。
- deadline、penalty、heterogeneity：
  - Table 10：penalty weight 0.75 时 latency 112.7 ms、makespan 123.5 ms、energy 98.4 J、throughput 72.4，failure rate 3.8%；
  - Table 31：提出方法在 10000 个 tasks 中 deadline violations 为 312，violation rate 3.12%，低于 RR、Min-Min、GA 和 Actor-Critic；
  - Table 21：记录四类 fog node 的 CPU、memory、active/idle power，以及 trust/安全违例/task failure/latency 示例。
- 证据边界：
  - 论文的 Data availability 写明 “No data was used”，但正文又报告 iFogSim、EdgeCloudSim 和大量模拟表格，复现数据来源不够清楚；
  - 许多公式为图片占位，关键 reward、Fit 和 IRC-DOA 更新式难以从 Markdown 完整复核；
  - Table 12 中多组 pairwise test 显示 H0 accepted，却正文又强调多算法显著优势，统计解释存在张力；
  - 多个理论声称如 `O(1)` regret、Markov stability、exponential convergence 较强，但正文证明较概念化；

  - “multi-objective constraints” 主要通过加权/组合 reward 和 Pareto 表格呈现，不是完整 MORL/Pareto policy 学习。

## 局限与未来工作

- 作者明确说明的局限/未来方向：
  - 高计算需求；
  - 随任务规模增长的 scalability challenge；
  - 复杂 task dependency 处理仍困难；
  - 后续考虑 AI-driven predictive scheduling、energy-efficient strategies、cloud-fog hybrid optimization、安全机制和实时资源分配；
  - 扩展到 Pareto front optimization、MO-PPO/PPO 等 MORL 框架；
  - 加入 real-time task preemption；
  - 用 Raspberry Pi fog clusters 做 hardware-in-loop validation；
  - 用 PBFT 共识形式化 trustworthiness；
  - 用 Google Cluster Workloads、NS-3/CloudSim 的 1K+ nodes 验证；
  - 用 Ornstein-Uhlenbeck noise 替代 Gaussian noise；
  - 用 Lyapunov proof、Clipped Double Q-Learning 和 uncertainty modeling 缓解稳定性和 critic overestimation。
- 我们认为仍需确认的问题：
  - reward 中 priority、completion time、available resource 的符号和缩放是否会导致“长任务反而高 reward”等反常；
  - sparse attention 的 top-k 选择标准和 DAG 依赖保留机制需要更可执行的伪代码；
  - IRC-DOA 调参相比 NSGA-II/NSGA-III/MOEA/D 的优势是否抵消了更高 tuning time；
  - Gaussian exploration 会降低训练可复现性，论文承认但未给出多 seed 方差充分统计；
  - 大量 baseline 的参数是否公平调优未完全说明。

- 值得建立或补充的设计知识：

- 与已有设计知识的边界：
  - 不同于 [增量直方图与决策空间划分的离散大规模 MOO](../02_design_knowledge/K-incremental-histogram-division-discrete-lsmop.md)，本文不是离线 MOEA 直接采样离散 offloading 解，而是在线 actor-critic 调度策略；
  - 不同于 [Actor-Critic 自适应生态位环境选择](../02_design_knowledge/K-actor-critic-adaptive-niche-selection-mmop.md)，本文的 actor-critic 控制外部 fog scheduling action，而不是 MOEA 内部 niche size；
  - 不同于 [状态驱动的 DRL 演化算子选择](../02_design_knowledge/K-drl-state-driven-evolutionary-operator-selection.md)，本文没有选择 GA/DE/PSO 等演化算子，而是用 DRL 输出任务分配。
- 局部创新线索：
  - 用 Lagrangian constrained RL 或 primal-dual reward 替代手工加权 reward/penalty；
  - 用 Pareto-conditioned policy 输出不同 energy-latency-trust 偏好下的调度策略；
  - 把 sparse attention 的 top-k 从静态规则改成基于 DAG critical path、deadline slack 和 resource contention 的可解释选择；
  - 用 OU noise、entropy regularization 或 safe exploration 改善动态 workload 下的策略探索。
- 结构创新线索：
  - 可形成通用动态资源调度架构：task DAG/state encoder -> sparse task-resource attention -> actor-critic allocator -> constraint-aware reward -> metaheuristic/BO hyperparameter tuner -> online rescheduler；
  - 可迁移到 edge offloading、GPU job scheduling、microservice placement、warehouse robot dispatch 或 multi-tenant cluster scheduling。
