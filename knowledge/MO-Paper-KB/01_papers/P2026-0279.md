# Three-Part Genetic Algorithm to Optimize the Outbound Train Using a Multi-Objective Approach

## 一句话理解

论文把干港出港列车装箱扩展为三目标 WCAP：优先装载高优先级集装箱、尽量占满车厢容量、最小化 reach stacker 行驶距离；方法上把 TPGA2 改成三段染色体表示“集装箱顺序、车厢容量槽位/车厢顺序、多车辆断点”，再用 epsilon-constraint 把优先级浪费和剩余空间变成业务可接受阈值，只在“近满载且不跳过紧急集装箱”的受限搜索空间内优化距离。

## 问题与动机

- 研究场景：dry port 的 outbound train loading，需要将候选 containers 分配到一列 train 的 wagons，并生成 container-handling vehicle/reach stacker 的取箱-放箱序列。
- 实际痛点：
  - 高优先级或紧急 container 未装上会导致船期/截止期风险；
  - train capacity 未充分利用会造成堆场 congestion；
  - reach stacker 行驶距离过长会增加燃料、维护和温室气体排放。
- 更新后的 WCAP 目标：
  - 最小化 unused wagon capacity，相当于最大化 train capacity utilization；
  - 最小化 handling vehicle 总行驶距离；
  - 最小化 priority waste，让更高优先级 containers 优先被装载。
- 主要约束：
  - 每个 wagon 的 container TEU 总量不能超过 capacity；
  - 每个 container 最多分配给一个 wagon 和一个 vehicle；
  - 每个 vehicle 一次只搬一个 container，不能在两个 container 节点之间或两个 wagon 节点之间直接移动；
  - vehicle route 从 container 节点开始、以 wagon 节点结束，中间流守恒保证连续路径。
- 为什么现有方法不足：
  - 既有 WCAP 只最小化装载距离，没有同时处理满载率和紧急 container；
  - 现实终端工作人员不接受“距离短但半列车没装满”或“遗漏可装的高优先级 container”的方案；
  - exact solver 只适合很小规模，超过 7 containers/7 wagons 后此前工作已难以完成；
  - 人工启发式速度快，但难稳定逼近三目标折中前沿。

## 核心理念与算法流程

- 核心理念：业务偏好中，priority 和 capacity utilization 更接近“必须满足的可接受区域”，distance 才是主要优化目标。因此不直接让三目标平等竞争，而是用 epsilon thresholds 先限定可接受的 priority waste 和 remaining space，再在受限区域内用 GA 搜索低距离解集。
- WCAP 输入：
  - wagons：坐标和容量；
  - containers：位置、priority、size；
  - vehicles：可用搬运车辆数量；
  - areas/wagons 间欧氏距离。
- 三段染色体：
  1. container segment：container permutation；
  2. wagon segment：每个 wagon 按 capacity 拥有对应数量 genes，用来表示可容纳的 slots；
  3. breakpoint segment：odd indices，按 container-wagon pair 序列切分多 vehicle routes。
- 染色体解码：
  - 交替读取 container segment 和 wagon segment，形成 container-wagon assignment pair；
  - 若 container size 超过目标 wagon 剩余容量，该 pair 不加入可评价序列；
  - breakpoint 将 move sequence 切成多个 vehicle routes；
  - 返回 vehicle sequences 和 train remaining space。
- 三段遗传操作：
  - Crossover 对三段分别执行；
  - container 和 wagon segment 是 permutation-like 表示，需保留每类 gene 的出现次数；
  - 对存在重复 wagon genes 的情况，先用 mapping 把重复值临时唯一化，交叉后再 reverse mapping；
  - breakpoint segment 可使用 one-point crossover；
  - mutation 中 container/wagon 段用 swap mutation，breakpoint 段用 valid breakpoint set 中的 flip mutation。
- Fitness 与 epsilon-constraint：
  1. 计算所有 sequences 的 total distance；
  2. 计算 train remaining space；
  3. 计算 priority waste，权重随 priority level 设计，以惩罚跳过高优先级 containers；
  4. distance 归一化作为主 fitness；
  5. 若 priority waste 超过 `epsilon_not_put`，把归一化 priority waste 加入 fitness；
  6. 若 train remaining space 超过 `epsilon_remaining_space`，把归一化 space waste 加入 fitness。
- Pareto set 生成方式：
  - Remaining Space constraints 取 `[0.0, 0.025, 0.05, 0.075, 0.1]`；
  - Priorities constraints 取 `[0.0, 0.05^(1/n), 0.15^(1/n), 0.3^(1/n), 0.4^(1/n)]`，`n` 为 train 的 priority 数；
  - 5 x 5 共 25 组 constraints，每组运行 TPGA2，合并得到 non-dominated set；
  - 最受限环境是两个 epsilon 都为 0。
- 人工启发式基线：
  - 12 个 heuristics 模拟 terminal workers：从 train 一端开始逐 wagon 装载，再从另一端重复，取最好结果；
  - 不同 heuristics 只改变 Distance、Priority、Size、Inv Size 的排序优先级。

## 实验证据

- 实验数据：
  - 使用 private terminal 的匿名数据生成；
  - terminal layout 有 57 blocks/areas；
  - outbound trains 最大 25 wagons；
  - 每个 scenario 有 6 列 trains；
  - wagon capacity 包括 2、3、4 TEUs，containers size 为 1 或 2 TEUs；
  - Scenario 2 在 Scenario 1 基础上增加 containers 并分配 priority 1-6。
- Scenario 1：
  - 所有 containers 都可装入 wagons；
  - 所有 containers priority 相同；
  - 由于 size/capacity 不同，仍需同时处理 distance 和 space wastage；
  - 只比较 4 个相关 heuristics。
- Scenario 2：
  - containers 不保证都能装入 wagons；
  - containers 有不同 priorities；
  - 同时考验距离、容量和优先级；
  - 比较全部 12 个 heuristics。
- 运行设置：
  - Python 3.8.5，MacBook Pro M1，16 GB RAM；
  - GA population size 和 generations 保持较小，以满足现实短运行时间；
  - 每个 epsilon constraint group 运行 3 次。
- 主要结果：
  - Scenario 1 中，TPGA2 的 non-dominated solutions 在 6 列 trains 上均支配所有 heuristic solutions；
  - Train 1/2 在完全装载时剩余空间较大，TPGA2 主要体现为更短 distance；
  - Train 3-6 剩余容量较小，TPGA2 相对 Heur5 可同时改善装载量/space wastage/distance；
  - Scenario 2 中，TPGA2 在所有 trains 上也始终给出支配 heuristics 的 non-dominated solutions；
  - 每列 train 的 TPGA2 set 均能 full 或 almost fully utilize train capacity，最低达到 98.6%，并优先装载紧急 containers。
- 时间与经济性：
  - Scenario 1：TPGA2 平均每 train 10.76 s；25 组 constraints、每组 3 次时，完整 ND set 平均约 13.45 min；最受限 `epsilon1=epsilon2=0` 场景约 32.28 s；
  - Scenario 2：TPGA2 平均每 train 12.36 s；完整 ND set 平均约 15.45 min；最受限场景约 37.08 s；
  - 对按“装满并尽量少浪费空间”筛选出的方案，TPGA2 比 heuristic 平均少 7% travel distance；
  - 估算 Scenario 1 每年节省约 8288.95 EUR，Scenario 2 最现实场景约 9049.41 EUR。
- 证据边界：
  - Heuristics 几乎 0 s，TPGA2 需要秒级到分钟级，适合决策辅助但不等价于即时人工规则；
  - 距离使用 Euclidean distances，未计入绕过 container blocks 的实际路径，作者认为真实节省可能更高；
  - 当前测试只用 single vehicle，因为 terminal 现实中只有一台可用车辆；
  - 摘要/结论出现 three scenarios/new datasets 表述，但正文只定义两个 scenarios，可能是写作或数据集命名不一致。

## 局限与未来工作

- 作者未来工作：
  - 在 two vehicles 环境中进一步测试；
  - 分析 TPGA2 不同 operators 和 settings 对性能的影响；
  - 更深入理解 priority constraint values 对 outcome 的影响，以更精确控制目标 trade-offs；
  - 与 container reshuffling problem (CRP) 集成，把 reshuffling cost 纳入装载决策；
  - 建立包含 terminal 实际 coordinates 的 digital twin。
- 我们认为仍需确认的问题：
  - epsilon 阈值网格依赖 terminal worker 偏好，是否可由历史选择数据自动校准；
  - 当前以 distance 为主目标，若 fuel、时间窗、设备冲突或碳排放非线性，fitness 需要重构；
  - 仅使用 single vehicle，breakpoint segment 的多车潜力尚未充分验证；
  - 容量不可行 pair 被跳过可能造成解码偏差，需比较 repair 或 constructive decoder；
  - 未与 NSGA-II、MOEA/D、ALNS 等通用/问题特定多目标元启发式系统比较。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建设计知识：业务偏好约束的多段染色体搜索。它不同于“预测嵌入的中断感知供应链多目标规划”中的精确 MILP + ε-constraint，也不同于一般排列解码；本知识把业务上必须接近满足的目标转成 epsilon 阈值，并与多段组合染色体和 GA fitness 结合，生成业务可接受区域内的 Pareto-like 解集。
- 暂留在论文卡中的方法、原理或架构启发：
  - terminal 57 blocks、具体 trains 数据和 Zenodo 附表暂留本文卡，不单独建数据卡；
  - 12 个 heuristics 是业务基线，暂不单独建启发式卡；
  - annual savings 估算依赖 Portugal diesel 价格、78 trains/month 和 reach stacker 油耗，暂不泛化。
- 局部创新线索：
  - 用 adaptive epsilon grid 替代固定 5 x 5 阈值扫描；
  - 将 priority waste 从手工幂次权重改成由 missed deadline cost 或 customer penalty 学习；
  - 对容量不可行 pair 使用 repair/reinsertion，而不是直接跳过；
  - 在 breakpoint segment 上加入车辆负载均衡或 route-length balance 局部搜索；
  - 用真实 terminal path distance 或 digital twin 仿真距离替代 Euclidean distance。
- 结构创新线索：
  - 构建“业务偏好阈值层 + 多段组合染色体 + 主目标 GA 搜索 + epsilon grid Pareto 生成”的物流决策支持框架；
  - 迁移到车辆装载、拣选波次、集装箱堆场出库、仓储订单分配、港口装船配载等存在优先级/容量/路径成本的组合 MOO；
  - 与 TOS/WMS/API 集成，允许工作人员调整 priority/capacity epsilon 后快速获得候选方案集。
