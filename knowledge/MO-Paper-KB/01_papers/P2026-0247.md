# MORA-LLM: Enhancing Multiobjective Optimization Recommendation Algorithm by Integrating Large Language Models

## 一句话理解

论文提出 MORA-LLM，把 LLM 作为多目标推荐演化算法的语义辅助层：LEPS 用 embedding 模型从用户描述和交互中构造相似用户预测分数，缓解冷启动；LES 周期性调用 LLM 为单个用户生成候选推荐和自然语言理由，并据此修正预测分数；全局层再用 SDE 评价和竞争搜索推进 Precision、Novelty、Topic Diversity 三目标的 Pareto 搜索。

## 问题与动机

- 研究问题和场景：推荐系统需要同时优化准确率、novelty 和 topic diversity，不能只追求用户已偏好的热门物品；这类 Top-K 推荐可建模为多目标优化问题，解为所有用户的推荐列表矩阵。
- 现有 MOEA-based RS 的不足：
  - 冷启动用户缺少历史交互，传统 ProbS/UserCF 等预测分数不稳定；
  - 矩阵编码把所有用户作为整体搜索，用户和物品规模增大后搜索空间膨胀，多目标收敛不足；
  - 推荐结果通常缺少可解释推荐理由，影响用户信任；
  - 直接把 LLM 作为优化算子会带来输出不确定性，且过度依赖 LLM 生成。
- 本文希望解决什么：
  - 只把 LLM 用作辅助语义模块，而不是完全替代 MOEA 搜索；
  - 用 LLM embedding 改善冷启动预测分数和候选池；
  - 用 LLM reasoning/NLG 对每个用户做周期性 personalized search、输出推荐理由并修正分数；
  - 用竞争搜索和 SDE 继续维持多目标全局搜索的收敛与多样性。

## 核心理念与算法流程

- 核心理念：LLM 负责补足“语义理解、用户意图推断和解释生成”，MOEA 负责“种群搜索、目标折中和 Pareto 解维护”。这样既利用 LLM 的知识和推理能力，又避免让 LLM 直接承担整个随机优化过程。
- MORA-LLM 分两阶段：
  1. Prediction Score Stage / LEPS：
     - 把用户基本信息和历史交互输入 Mxbai-Embed-Large，得到用户 embedding；
     - 用 embedding cosine similarity 找相似用户；
     - 基于相似用户历史评分计算用户-物品预测分数；
     - 每个用户取 top-100 候选物品，并随机采样长度为 `K` 的推荐列表初始化 population。
  2. Evolutionary Optimization Stage / LES：
     - Personalized search：对每个用户，从当前 population 中分别选出 Accuracy、Novelty、Topic Diversity 最大的推荐列表，形成 `S1/S2/S3`；
     - 每隔 `cycle=20` 代构造 LLM prompt：输入 20 个历史交互物品、top-100 候选中的 20 个物品、当前 accuracy-optimal 列表，并要求 LLM 从候选中推荐 top-K 且给出理由；
     - 校验 LLM 输出是否属于候选列表，过滤越界物品；
     - 用 LLM 输出列表与当前 accuracy-optimal 列表做加权平均，修正预测分数；
     - Competitive search：把 `P` 与 personalized population 合并，用 SDE 计算 fitness，随机两两竞争，loser 向 winner 学习，执行 crossover、mutation 和 deduplication；
     - 环境选择从 `P ∪ Pp ∪ Pc` 中按 SDE 选择下一代。
- 可能被修改的位置：
  - LEPS embedding 模型可替换为领域文本 encoder、图推荐模型、知识图谱 embedding 或隐私保护用户画像模型；
  - LLM 调用周期、候选数、历史样本数和 prompt 模板可按成本/延迟自适应；
  - 分数修正可从简单加权平均换成置信度校准、Bayesian update、bandit feedback 或 user-in-the-loop 反馈；
  - 竞争搜索可替换为 NSGA-II、MOEA/D、RVEA、archive-based selection 或连续偏好编码搜索。
- 必须保留的核心：
  - LLM 输出必须被候选列表约束并通过推荐系统目标函数/种群搜索验证；
  - LLM 不直接决定最终 Pareto 搜索，而是用于候选分数、个体用户搜索和解释；
  - 多目标推荐仍保持 Precision、Novelty、Diversity 的显式折中；
  - 需要周期性/预算化调用 LLM，否则成本会破坏在线推荐可用性。

## 实验证据

- 实验设置：
  - 数据集来自 Movielens 和 Lastfm 四个 real-world datasets；Movielens-10M 采样 10000 用户，Lastfm 从 11946 tags 中选高频去重后的 2074 topics。
  - 对比七个多目标推荐算法：MOEA-Probs、PMOEA、NewCrossPMOEA、ComEA、MOREM、EMMR、LLM-NSGA-II。
  - 消融变体包括 MORA-LLM(-WOLLM)、MORA-LLM(-WOM)、MORA-LLM(-WOQ)、MORA-LLM(-WG)。
  - LEPS 使用 Mxbai-Embed-Large，LES 使用 Qwen-Turbo；最大迭代 100；每个算法独立运行 10 次。
  - 指标为 Precision、Novelty、Topic Diversity 和 IGD；因为真实 PF 难获得，作者用三目标最大值构造 3-D reference plane 计算 IGD。
- 主要结果：
  - Precision：在 16 个实例中，MORA-LLM 取得 12 个最优结果并综合排名第一。作者认为 LEPS 的语义相似用户信息缓解稀疏数据，LES 的竞争搜索避免高准确解丢失。
  - Novelty 与 Topic Diversity：MORA-LLM 在两类指标表中均取得 16 个最优结果，说明 LES 能在多目标之间保持较好平衡。作者说明 Novelty 全为 1 与其对 0 次或 1 次评价物品的统一处理有关。
  - IGD：MORA-LLM 在 16 个实例上均取得最好 IGD，作者将其归因于 personalized search 汇总单用户高质量列表、LLM 增强和 competitive search 提升种群稳定性。
  - 3-D 最终解分布显示 MORA-LLM 在保持高 Precision 的同时兼顾 Novelty 和 Topic Diversity。
  - 可解释性示例：MORA-LLM 能为具体电影推荐生成自然语言理由，例如把历史偏好和剧情特征联系起来。
- 进一步分析：
  - LLM 消融显示，完整 MORA-LLM 的 mean IGD 更好，证明 LLM 模块对推荐质量有贡献。
  - 不同 LLM 影响性能与延迟；作者推荐中等规模模型，如 Qwen2-Turbo 或 Qwen2-7B，以兼顾效率和低延迟。
  - Runtime 分析显示，含 LLM 的 MORA-LLM 运行时间增加，但仍明显好于 PMOEA、NewCrossPMOEA、ComEA 等传统多目标推荐算法。
  - LEPS 模型对比中，Mxbai-Embed-Large 在约 0.6 s 稳定延迟下取得最高 Precision；LES 中 Qwen-Turbo 比 GLM-4-Air 更适合高响应速度场景。
  - 分数修正权重 `alpha` 在 0.2-0.3 时 IGD 较优，作者推荐 `alpha=0.2`。
- 证据边界：
  - 表格多为图片占位，Markdown 无法保留全部精确数值。
  - 实验集中在公开推荐数据集，缺少真实在线 A/B、用户反馈和长期满意度验证。
  - LLM 推荐理由未受强约束，作者有意保留生成灵活性，但实际部署需控制幻觉、偏见和合规风险。

## 局限与未来工作

- 作者明确未来工作：
  - 探索 extreme cold start 场景下的鲁棒性；
  - 研究轻量化模型设计以便部署；
  - 引入 multimodal data；
  - 进一步研究 LLM-driven operator design，提高 EA 在动态优化场景中的适应性。
- 我们认为仍需确认的问题：
  - LLM 生成推荐理由的真实性、偏见和合规性如何评估；
  - 训练/调用商业或在线 LLM 时，用户隐私和数据泄露如何控制；
  - LLM 输出仅被候选列表约束，是否足以避免 popularity bias 或 exposure bias；
  - Online recommender 中延迟、并发调用成本和模型版本漂移会如何影响稳定性；
  - `cycle=20`、top-100、20 个历史样本等工程参数是否跨数据集稳健。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建设计知识：LLM 语义辅助的多目标推荐演化搜索。它不同于让 LLM 生成 MOEA 算子代码，也不同于连续偏好编码的推荐 MOO；重点是把 LLM embedding、候选约束 prompt、分数修正和竞争搜索嵌入推荐 Pareto 搜索。
- 暂留在论文卡中的方法、原理或架构启发：
  - Mxbai-Embed-Large、Qwen-Turbo、GLM-4-Air 等具体模型选择是实现细节，不单独建知识。
  - 电影推荐示例属于应用展示，不单独建场景卡。
- 局部创新线索：
  - 给任意 MOEA 推荐算法增加“候选约束 LLM personalized search”模块，只周期性调用以控制成本。
  - 用用户反馈校准 LLM score correction 中的 `alpha`，让它成为在线自适应参数。
  - 在 LLM 输出过滤中加入安全、版权、年龄分级、业务规则和 exposure fairness 约束。
  - 用多 LLM 或小模型蒸馏生成推荐理由，降低在线延迟。
- 结构创新线索：
  - 构建“语义 embedding 冷启动 -> MOEA Pareto 推荐 -> 周期性 LLM 个体用户修正 -> 可解释输出”的推荐优化框架。
  - 把 LLM 解释质量作为第四目标或约束，形成 accuracy-novelty-diversity-explainability 的多目标推荐。
