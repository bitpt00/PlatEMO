# Multimodal Multiobjective Neural Architecture Search for Lightweight and Failure-Resilient Time Series Forecasting

## 一句话理解

本文提出 M3NAS-TSF：先把时间序列编码成四通道图像并训练 TSF 专用 MoTS-Net，再用带架构距离生态位选择和架构多样性距离的 M3NAS 搜索准确、轻量且结构多样的 Pareto TSF 模型池，以支持资源受限部署和故障切换/集成。

## 问题与动机

- 研究问题和场景：
  - Time series forecasting 广泛用于金融、疾病传播、交通流等决策和风险预警；
  - 深度 TSF 模型精度提升同时带来参数量和 FLOPs 增长，阻碍嵌入式或资源受限设备部署；
  - TSF 部署过程可能遭遇传感器故障、恶意攻击、soft errors 或随机 bit-flips，影响预测稳定性。
- 现有方法为什么不足：
  - 模型压缩可降复杂度，但 pruning/quantization 可能因信息损失降低预测性能；
  - 手工设计 compact TSF 模型依赖专家经验，工程成本高；
  - 既有 one-shot NAS 多面向 CV 图像任务，super-net 输入结构和操作空间不适合低维、有长程依赖的 TSF；
  - 既有 NAS 搜索阶段常直接使用 NSGA-II，只维护目标空间多样性，忽略架构/决策空间多样性；
  - 若最终 Pareto 模型结构过于相似，发生随机故障时切换或 ensemble 的鲁棒性有限。
- 本文希望解决什么：
  - 自动搜索同时低 error、低 model size 的 TSF 模型；
  - 在 objective-space Pareto tradeoff 之外，保留多种结构不同但性能相近的架构；
  - 用 architecture diversity 支持 failure tolerance：主模型故障时可切换到替代模型，或通过模型池集成提升异常场景鲁棒性。

## 核心理念与算法流程

- 核心理念：
  - 把 TSF 输入先转换为图像，让卷积、残差和 dense connections 能用于捕捉时间模式；
  - 用一个模块化单路径 super-net 作为共享权重评估器，降低 NAS 成本；
  - 把 NAS 看作 multimodal multiobjective problem：多个不同架构可具有相近 forecasting error 和参数量，因此需要在 Pareto 前沿附近保留多个等价结构。
- M3NAS-TSF 总流程：
  - 将原始时间序列按 6:2:2 划分为 train/valid/test；
  - 多变量序列先沿 feature dimension flatten；单变量序列直接处理；
  - 用 GASF、GADF、MTF、RP 四种编码把时间序列转换为 `Sim x Sim` 四通道图像，实验中 `Sim=32`，look-back window `Lx=50`；
  - 构建并训练 MoTS-Net，之后每个子网络继承 super-net 权重进行快速评价；
  - 用 M3NAS 在 MoTS-Net 上搜索子网络，目标是最小化 forecasting error 和 number of parameters；
  - 输出一组 Pareto networks，可按最小 RMSE、最小 FLOPs 或 knee point 选择部署，也可作为模型池集成。
- MoTS-Net：
  - 层级模块化单路径 super-net；
  - 以 `w=10` 为例，`L1` 是固定 `3x3 conv`，`L10` 是 fully connected，`L2-L9` 为 searchable layers；
  - 每个 searchable layer 含 5 个候选节点，候选包括 shortcut、dense connection、identity mapping 或 standard convolution，卷积核可为 `1x1` 或 `3x3`，并区分 stride 1/2；
  - 每个候选子网络在每个 searchable layer 选一个节点，形成一条路径；`w=10`、每层 5 个节点时搜索空间为 `5^8=390,625`；
  - 搜索空间中网络范围约为 0.09M 到 0.6M parameters，0.25G 到 1.4G FLOPs。
- M3NAS：
  - 初始化：用 Latin hypercube sampling 采样网络路径；
  - 距离度量：
    - XOR-distance：按路径整数编码逐位 XOR 求和，快速粗粒度表示架构差异；
    - `tau`-distance：根据 operation type、kernel size 和 trainable parameters 的参考距离表，计算对应节点的功能差异；
  - AANS：随机选个体 `A`，再从当前种群抽取 `ceil(Fc*N)` 个 crowding-factor candidates；按 XOR-distance 和 `tau`-distance 找到与 `A` 最近的两个候选，和 `A` 组成局部架构生态位，再从该小池中选性能最好的两个父代。正文动机强调促进架构多样性，具体实现更像“随机生态位内竞争”，避免全局最优结构长期垄断 mating；
  - Genetic operators：single-point crossover 和 single-point mutation；
  - Fast nondominated sorting：按 forecasting error 和 parameters 划分 frontiers；
  - ADD：在同一 frontier 内计算每个个体到其他个体的 XOR-distance 和 `tau`-distance，归一化后取两个 nearest-neighbor 距离的平均；ADD 越大说明该个体在架构空间越孤立；
  - Elite selection：完整前沿直接保留，最后一层 critical frontier 用 ADD 替代 NSGA-II crowding distance，优先保留结构更独特的架构。
- NDH 与 SE：
  - Node Distribution Heatmap (NDH)：显示每层各候选节点被 Pareto population 选中的频率；
  - Structural Entropy (SE)：对每层节点选择频率计算归一化 entropy，再跨 searchable layers 平均；值越高表示节点使用越均匀、架构多样性越强。
- 可能被修改的位置：
  - 时间序列编码方式，可加入 wavelet、STFT、shapelet 或 learned patch embedding；
  - `tau` distance reference table，可按操作语义、硬件开销、鲁棒性或训练稳定性重新定义；
  - AANS 的 nearest-niche 选择可改为 nearest/farthest 混合、目标相似条件下的架构互补配对；
  - ADD 可扩展到 graph edit distance、path kernel、operation embedding 或 GNN-derived architecture distance；
  - 模型池权重可由线性层换成鲁棒 stacking、uncertainty-aware ensemble 或 fault detector 触发切换。
- 必须保留的核心：
  - 若作为基础算法复用，应保留“任务适配 super-net + 共享权重评价 + 目标空间 Pareto 搜索 + 决策/架构空间多样性选择”这个四层结构。

## 实验证据

- 测试问题和对比算法：
  - 数据集/案例：PM2.5、Bike Sharing、ETTh1、ETTh2、S&P500，单变量和多变量模式，4 个预测 horizon `Ly={48,96,168,192}`，共 40 cases；
  - 对比模型：CNN、LSTM、LSTNet、Informer、Crossformer、SOFTS；
  - 评价指标：RMSE、MAE、parameters、FLOPs、inference time、inference time per sample、peak GPU memory usage、CPU utilization；
  - 搜索设置：`Lx=50`，`Sim=32`，`Fc=0.4`，`g=30`，`N=30`，`pc=0.8`，`pm=0.2`，MoTS-Net `w=10`；主要实验用单张 RTX 3090。
- 主要实验结论：
  - 预测精度：M3NAS-TSF 在多个长 horizon 案例上表现最好；S&P500 单变量最大 RMSE 降低 12.93%，多变量最大 RMSE 降低 14.50%；
  - PM2.5 和 ETTh1 多变量/长 horizon 上，M3NAS-TSF RMSE 降低约 0.28%-2.90%；
  - Bike 单变量长 horizon 上，M3NAS-TSF 相比次优方法 RMSE 降低 1.39%、2.67%、1.91%；
  - 复杂度：M3NAS-TSF 的 RMSE/FLOPs/knee 三类选项能在 RMSE、FLOPs 和 parameters 之间给出更灵活 tradeoff；
  - CPU 推理：Device 1 上 M3NAS-TSF_RMSE 的 IT、ITS、CPU utilization 最低；Device 2 上 M3NAS-TSF_knee 的 IT、ITS、CPU load 最低。
- 机制与消融证据：
  - Super-net 评价可靠性：Bike `Ly=96` 单变量中，MoTS-Net-derived performance 与 fully trained performance 的 Spearman/Kendall 相关明显高于 random weights；但 ETTh2 `Ly=96` 只略有提升，说明权重共享排序可靠性有数据集边界；
  - Objective-space diversity：单目标 GA 只聚集在小区域，NSGA-II 与 M3NAS 都能形成更完整 accuracy-parameter tradeoff；
  - Decision-space diversity：NDH/SE 显示 M3NAS-TSF 的 SE=0.72，高于 NSGA-II-TSF 的 0.55、GARMSE-TSF 的 0.38、GAparams-TSF 的 0.32；
  - Multimodal solutions：在 Bike 和 S&P500 的局部 Pareto 区域中，不同 path 可获得近似 RMSE 和参数量，支持“等性能多结构”存在；
  - Fault robustness：PM2.5 多变量 `Ly=168` 中，10% model weights 随机置零时 M3NAS-TSF_pool 的 RMSE 最低；10% input missingness 时 M3NAS-TSF_pool 也最低；
  - Hyperparameters：`Fc=0.4` 在 S&P500 `Ly=48` 上 accuracy 最好；`w=10` 在 Bike `Ly=96` 上 knee RMSE 最低，FLOPs 随 `w` 增加单调上升。
- 证据边界：
  - M3NAS-TSF 并非所有数据集都最好，ETTh2 上 SOFTS 明显更强，作者也指出 MoTS-Net 单路径结构忽略低层和高层特征组合；
  - 模型池在 complete data 或低故障率下不一定优于单个 M3NAS-TSF_RMSE，因为弱 Pareto 架构会稀释性能；
  - GPU 平台上 LSTNet 或 SOFTS 在 latency/memory 上可能更好，M3NAS-TSF 的 GPU memory 约 518 MB，高于轻量 baseline；
  - one-shot NAS 的性能依赖 super-net 排序相关性，ETTh2 结果显示该相关性不总是稳健；
  - 故障鲁棒性实验只在 PM2.5 `Ly=168` 多变量上做两类人工故障，真实软错误/攻击/传感器故障仍需验证。

## 局限与未来工作

- 作者明确说明的局限：
  - 当前 MoTS-Net 是 single-path architecture search，忽略低层和高层特征组合，可能限制部分数据集性能；
  - 真实 Pareto set 难以获得，NDH/SE 只是架构多样性的间接评估。
- 作者未来工作：
  - 设计 TSF 专用 multi-path super-net，混合多尺度 temporal features；
  - 扩展到 concept drift 场景，例如消费者行为变化；
  - 将 explainable AI 技术整合到 NAS，以提升高风险应用中搜索架构的可信度。
- 我们认为仍需确认的问题：
  - `tau`-distance 的参考表是否能跨 NAS search space 泛化；
  - AANS 中“最近邻生态位选择”与“促进全局架构多样性”的关系，需要更细消融；
  - NDH/SE 只统计节点频率，无法完全刻画路径级结构差异和功能等价；
  - M3NAS-TSF_pool 的 ensemble 权重是否应依据故障类型动态调整；
  - 时序编码为图像是否会丢失连续值尺度、相位或外生变量结构，是否优于直接时序 patch/Transformer search space。
