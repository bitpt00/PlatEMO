# Multiobjective Multitasking Optimization With Decomposition-Based Adaptive Knowledge Transfer

## 一句话理解

论文提出 MMTEA-DAKT，在 MOEA/D 分解式多目标多任务优化框架中，根据子问题改进率动态分配跨任务迁移比例，并用滑动窗口记录迁移算子的 fitness improvement rate，从 `Sp/Uf/Geo/SBX/DE` 算子池中自适应选择当前更适合的知识迁移算子。

## 问题与动机

- 研究问题和场景：多目标多任务优化需要同时求解多个相关 MOP，并通过跨任务共享搜索经验提升收敛与资源利用效率；本文还把该框架迁移到 CIFAR-10/CIFAR-100 的神经架构搜索。
- 现有算法为什么不足：
  - 很多 MMTEA 通过 Pareto dominance、概率任务关系、transfer solution ranking、domain adaptation、辅助任务或知识类型选择来迁移，但没有显式量化不同任务复杂度和不同迁移算子能力的差异。
  - 固定或均匀的迁移资源分配会让已收敛的简单任务继续消耗函数评价，也会让尚未充分优化的任务得不到足够搜索机会。
  - 多数方法用单一 crossover operator 做跨任务迁移；作者实验显示同一算子在不同任务和同一任务不同阶段表现差异很大。
  - 分解式方法如 MTEA/D-DN 利用邻域关系实现隐式迁移，但作者认为它没有充分分析任务差异，仍会浪费计算资源。
- 作者如何推导动机：
  - 复杂度实验：用单任务 MOEA/D 求解 CEC2017，作者把达到 `IGD <= 1e-3` 所需 FEs 看作任务复杂度；同组两个任务的平均 FEs 在 CIMS、CILS、PIMS、PILS、NIHS、NIMS、NILS 等问题上差异显著，部分相差超过十倍。
  - 算子实验：在 CIHS/NIHS 上比较 `Sp/Uf/Geo/SBX/DE` 做知识迁移的效果；例如 SBX 在 CIHS1 第 150 代最好、在 NIHS2 第 150 代最差，Geo 在 CIHS1 早期更好。
  - 因此作者认为应同时做两件事：按子问题/任务状态调整迁移比例，按近期迁移收益选择迁移算子。

## 核心理念与算法流程

- 核心理念：把 MMTOP 分解成任务-子问题集合，把“哪些子问题值得迁移”和“用哪个迁移算子”都转化为基于近期改进率的在线选择问题。ASS 控制迁移资源投向，AKT 控制迁移实现方式。
- 主要流程：
  1. 初始化算子池 `op = {Sp, Uf, Geo, SBX, DE}`，并初始化记录算子及其 fitness improvement rate 的滑动窗口 `w`。
  2. 对每个任务初始化 MOEA/D population、weight vectors、neighborhoods 和 ideal point。
  3. 每代先运行 Adaptive-Subproblems-Selection：若上一代没有正迁移，则选择全部子问题；否则计算每个任务/子问题的 fitness improvement rate，并选出 `K*N/alpha` 个收敛速度最快的子问题。
  4. 对选中子问题，以迁移概率 `Tp` 决定是否执行跨任务 adaptive transfer evolution；否则执行任务内 DE。
  5. 跨任务时，Adaptive-Transfer-Evolution 遍历滑动窗口，累计各算子的 improvement rate，计算算子质量 `Q`，选择当前最优迁移算子 `opbest`。
  6. 从任务集合和子问题集合中随机抽取两个 parent solution，用 `opbest` 生成 transfer offspring，并随机选择不同于源任务的 target task。
  7. 在 target task 上评价 offspring，更新 ideal point、target population，并把本次算子和 fitness improvement rate 写回滑动窗口。
- 关键组成部分：
  - decomposition-based MMTOP framework；
  - ASS：按 Tchebycheff 聚合函数改进率计算子问题收敛速度，选择更值得迁移的任务-子问题；
  - AKT：用滑动窗口为 transfer operators 做成功反馈；
  - 多算子迁移库：single-point crossover、uniform crossover、geometrical crossover、SBX、DE；
  - intra-task DE fallback：未触发跨任务迁移时仍保留任务内邻域/全局搜索。
- 可能被修改的位置：
  - 子问题选择指标可由 Tchebycheff improvement 替换为 HV contribution、IGD improvement、constraint violation reduction、surrogate uncertainty 或多步 credit；
  - 算子池可扩展为 repair、mutation、domain adaptation、learned generator、surrogate-assisted offspring generator；
  - `Q` 的估计可从短滑动窗口改为 bandit、Bayesian credit assignment 或 source-target-subproblem 条件化模型；
  - target task 选择可从随机改为任务图、相似度矩阵或迁移收益预测。
- 必须保留的核心：
  - 多任务先分解为可比较的任务-子问题单位；
  - 迁移资源分配由子问题改进率或类似在线反馈驱动；
  - 跨任务 offspring 生成不绑定单一算子，而是从可替换算子池中按近期迁移收益自适应选择；
  - 每次迁移后要把改进反馈写回选择机制。

## 实验证据

- 测试问题和对比算法：
  - Benchmark：CEC2017 九个双任务 MMTOP，CEC2019 十个 CPLX 双任务问题，CEC2021 ETMOF1-ETMOF8 两/三任务问题，WCCI2020 MATP1-MATP5 many-task 问题。
  - 对比算法：MO-MFEA-II、MTEA/D-DN、MO-MFEA-SADE、EMTET、MTDE-MKTA；每个任务 population size 100、FEs 50000；IGD 为主指标，HV 结果放在 Supplementary。
  - 统计：50 次独立运行，Wilcoxon rank-sum / signed-rank test，Friedman ranking。
- 主要实验结论：
  - CEC2017：MMTEA-DAKT 相比 MO-MFEA-II、MTEA/D-DN、EMTET、MTDE-MKTA 分别在 18/18、18/18、17/18、18/18 个 case 上显著更好；对 MO-MFEA-SADE 只略优，因为后者的 subspace alignment 对该套问题有效。
  - CEC2019：相对四个 Pareto dominance 算法，MMTEA-DAKT 在 20、19、20、20 个 case 上更好，劣于它们的 case 为 0、1、0、0；相对 decomposition-based MTEA/D-DN 在全部 case 更好。
  - CEC2021：18 个 case 中 MMTEA-DAKT 获得 13 个最佳 IGD，其他算法最佳 case 分别为 0、1、4、0、0。
  - 综合 56 个 test instances，MMTEA-DAKT 的 Friedman average rank 为 1.31，作者据此认为综合性能最优。
  - Many-task：在 MATP1-MATP5 每题 50 任务上，MMTEA-DAKT 相比 MOMFEA-II、MTEA/D-DN、MO-MFEA-SADE、EMTET、MTDE-MKTA 分别更好于 120、141、247、193、137 个问题，劣于 57、67、3、53、4 个问题；MATP2/MATP5 的 Friedman rank 为 1.2 和 1.78。
  - 收敛曲线：MMTEA-DAKT 在 CPLX1_2 和 ETMOF8_2 上最快，在 PILS2、NIMS2、CPLX8_2、ETMOF2_1 上虽非最快但最终 IGD 最好，作者解释为 ASS+AKT 减少了达到较优 IGD 所需资源。
- 消融或机制证据：
  - 三个基础变体：MMTEA-ASS 只使用 adaptive subproblems selection，MMTEA-AKT 只使用 AKT，MMTEA-NO 只保留 decomposition-based framework。
  - MMTEA-NO 只在 PILS1 和 NILS2 上优于完整方法，整体上仅 2/18 更好、14/18 更差，说明没有知识迁移和资源分配会损失综合性能。
  - MMTEA-ASS 和 MMTEA-AKT 单独使用时分别有 14/18 和 13/18 个 case 劣于完整方法，说明两种机制存在互补性。
  - 替换消融：用 MTEA/D-DN 的分解框架替换 ASS 得到 MMTEA-DN，用 MOMFEA-SADE 的 adaptive DE 替换 AKT 得到 MMTEA-ADE；完整 MMTEA-DAKT 在 18 个问题中 15 个最佳，两个替代变体各仅 2 个最佳。
  - 参数分析：`Tp=0.1,0.3,0.7,0.9` 的 Friedman ranks 分别为 1.5、2.1、2.7、3.7；作者建议 `Tp=0.1`，并解释为任务差异越大，过多外部迁移越易负迁移。
  - 运行时间：作者称 MMTEA-DAKT 相比 MTEA/D-DN 在 CIMS 和 PIHS 用时更少，其他问题略多；总体在多数问题上有最少或第二少运行时间，同时性能最好。
- NAS 应用证据：
  - 搜索空间为 NAS-Bench-201，cell 有四个节点和六条边，每条边五种操作，共 15625 个结构；使用 one-shot weight-sharing supernet。
  - CIFAR-10/CIFAR-100 双任务，目标组合中 classification accuracy 权重 0.95、参数数量权重 0.05，population size 32，参数约束 `M=0.6 MB`，算子池包括 `Sp/Uf/Geo/DE`，滑动窗口为 5。
  - 所有算法先 warm-up 10 epochs，再 15 次迭代、每次 5 epochs，总计 85 epochs；平台基于 PA-DA 和 PyTorch 2.0。
  - MMTEA-DAKT 在 CIFAR-10 上 validation/test accuracy 为 91.15%/93.93%，在 CIFAR-100 上为 72.52%/72.11%，作者称优于列出的 NAS 方法且接近 B201 最优记录。
- 证据边界：
  - 多个表格在 Markdown 中是图片占位，逐项数值需要回查 PDF 或 Supplementary；
  - HV、更多收敛曲线、many-task 详细均值方差和部分替换消融细节在 Supplementary；
  - NAS 结果证明方法可迁移到真实应用，但只覆盖 NAS-Bench-201 和 CIFAR-10/100，并未证明对大规模开放搜索空间同样有效。

## 局限与未来工作

- 作者明确说明的局限：
  - 在 CEC2017 简单可分问题如 CIHS1、CILS1、PIHS1、PIHS2、NIHS2 上，动态适应机制可能扰动简单问题的直接收敛路径，因此未取得最好结果。
  - 过高迁移概率会降低性能，作者在参数分析中把原因归结为任务差异导致外部知识负迁移。
- 作者未来工作：
  - 在 MMTEA-DAKT 中加入 separability detection 和 complexity-based switching strategy，提高跨不同问题类型的泛化能力。
  - 继续研究 decomposition-based framework 与合适 adaptive transfer strategy 结合求解复杂 MMTOPs。
  - 设计更有效的 transfer operators，并研究 parallel computing mechanism 以提高复杂 MMTOP 和真实应用效率。
- 我们认为仍需确认的问题：
  - ASS 选择“收敛速度最快”的子问题有助于快速产出正迁移，但可能忽略停滞但潜力大的困难子问题；是否应混合 exploitation 与 exploration。
  - AKT 目前把算子 credit 主要按全局滑动窗口累计，未区分 source-target task pair、子问题区域和搜索阶段。
  - Target task 随机选择可能削弱任务相似性利用；若任务数量变大，应显式维护任务图或迁移边权。
  - `Tp=0.1` 的建议来自 benchmark 统计，真实工程或高相关任务中可能需要更高迁移率或任务边级迁移率。
  - NAS 应用把准确率和参数数加权处理，严格多目标前沿质量、约束处理和架构训练噪声仍需更细验证。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 补充已有设计知识：多邻域多知识的分解式多任务迁移。P2026-0243 给该知识补充了子问题改进率驱动的迁移比例分配，以及迁移算子池的滑动窗口 credit 选择机制。
- 暂留在论文卡中的方法、原理或架构启发：
  - 任务复杂度可用达到阈值 IGD 所需 FEs 估计，但该估计依赖离线单任务运行，在线算法中还需要近似指标。
  - `Sp/Uf/Geo/SBX/DE` 的算子解释可作为算子池构造启发，但每个算子的适用性需要随编码类型重新验证。
  - NAS 中 accuracy 与 parameter size 的 0.95/0.05 加权是应用设置，不单独升级为通用设计知识。
- 局部创新线索：
  - 将 ASS 从“最快收敛子问题优先”改成 UCB/Thompson sampling，在高改进和高不确定子问题之间平衡。
  - 为每个 source-target task pair 维护独立算子成功记忆，形成 task-pair-conditioned operator portfolio。
  - 用 separability、multimodality 或 landscape probing 触发不同迁移强度，减少简单可分任务上的干扰。
  - 把滑动窗口 credit 改为多尺度记忆：短期适应阶段变化，长期保留可靠算子。
- 结构创新线索：
  - 构建“任务图 + 子问题状态 + 算子组合器”的三层迁移控制器：任务图决定向谁迁移，子问题状态决定迁移多少，算子组合器决定如何迁移。
  - 将 ASS/AKT 用到动态 MOO 或 constrained MOO，把历史环境、约束松弛任务或辅助任务视作可迁移任务，并让算子 credit 随环境/约束阶段变化。
