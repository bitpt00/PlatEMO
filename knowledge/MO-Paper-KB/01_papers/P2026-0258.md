# A Fast Dominance Move Calculation Using Mixed-Integer Programming for Many-objective Optimization

## 一句话理解

论文提出一种紧凑 MIP formulation 来精确计算 Dominance Move (DoM) 指标：只显式建模每个点在各目标上的移动量 `z(i,m)` 和 moved point 是否覆盖 `q_j` 的二元变量 `x(i,j)`，用隐式 moved set 替代原 assignment-based MIP 的大量辅助变量，从而在 many-objective 解集比较中保持精确 DoM 值并显著缩短求解时间。

## 问题与动机

- 研究问题和场景：多目标和 many-objective optimization 中，经常需要比较两个算法输出的非支配解集。DoM 是 binary quality indicator，用最小总移动量衡量集合 `P` 需要移动多少才能支配集合 `Q`，不依赖参考点，并能同时反映 convergence、spread、uniformity 和 cardinality。
- 现有算法为什么不足：
  - Hypervolume 是强指标，但作者指出 exact HV 在 many-objective 场景计算昂贵，并对 reference point 敏感。
  - `epsilon`-indicator 计算较高效，但作者认为它通常只突出最差相对目标，可能丢失目标维度信息。
  - 原始 DoM 只给出 bi-objective 精确计算；后续 assignment formulation 可处理多目标，但当每个集合超过约 20 个解时可扩展性差。
  - 既有 MIP-DoM 能精确计算 multi-/many-objective DoM，但仍基于两层 assignment 视角，变量和约束数量巨大。例如 `M=5`、`|P|=|Q|=200` 时约有 202000 个连续变量、440200 个二元变量和 923400 个约束；某些 `|P|=|Q|=240`、`M=15` 实例需要超过 208 小时。
- 本文希望解决什么：保留 DoM 的 exact binary indicator 属性，同时把 MIP model 改成更紧凑的直接 dominance-move formulation，使 DoM 能更现实地用于 many-objective 解集评价，甚至未来进入 indicator-based evolutionary search。

## 核心理念与算法流程

- 核心理念：不要把 DoM 视为 assignment problem，而是直接表达“移动后的 `p'_i` 支配哪些 `q_j`”。移动后的点不作为独立连续变量出现，而由 `p'_i,m = p_i,m - z(i,m)` 隐式给出。
- 主要流程：
  1. 输入两个非支配解集 `P` 与 `Q`，目标维数为 `M`。
  2. 为每个 `p_i` 和目标 `m` 建立连续变量 `z(i,m)>=0`，表示该点在该目标上的改善/移动量。
  3. 为每对 `p_i,q_j` 建立二元变量 `x(i,j)`，表示移动后的 `p'_i` 是否负责支配 `q_j`。
  4. 最小化所有 `z(i,m)` 的总和，即 `P` 移动到 `P'` 的 Manhattan 总距离。
  5. 用 dominance constraints 保证当 `x(i,j)=1` 时，所有目标上都有 `p_i,m - z(i,m) <= q_j,m`。
  6. 对每个 `q_j` 加覆盖约束，要求至少一个移动后的 `p'_i` 支配它。
  7. 用 Big-M 或 solver indicator constraints 表达条件支配关系；作者给出紧的 `U_i,m = p_i,m - min_j(q_j,m)` 上界。
  8. MIP 求解后输出 exact `DoM(P,Q)`，并可由 `z` 重构 moved set `P'`。
- 关键组成部分：DoM binary indicator、compact MIP formulation、movement variable `z(i,m)`、coverage variable `x(i,j)`、implicit moved set、tight Big-M upper bound、indicator constraints、runtime scaling analysis。
- 可能被修改的位置：离线性能评价、binary indicator 计算模块、indicator-based environmental selection、archive pairwise comparison、DoM-guided variation/restart。
- 必须保留的核心：`z` 表示每个原始点在每个目标的移动量；`x` 只表示移动后的覆盖/支配关系；每个 `q_j` 至少被一个 `p'_i` 支配；目标函数必须是总移动量最小化，否则就不再是精确 DoM。

## 实验证据

- 测试问题和对比算法：
  - Validity test：将 compact formulation 与 former MIP-DoM 在相同测试实例上比较，核验 MIP-DoM objective value 是否一致。
  - Many-objective comparison：复现实验比较 MOEA/D 与 NSGA-III 的解集，测试问题来自 DTLZ 和 WFG family；Table I 报告 DTLZ1/2/3/7 与 WFG1/2/3/9，两种方向 `(MOEA/D, NSGA-III)` 和 `(NSGA-III, MOEA/D)`；解集大小 `L=100,170,240`，目标数 `M=5,10,15`。
  - Runtime vs solution-set size：DTLZ1，50 个随机实验，`L=50,100,200,300,400`，目标数 `M=5,10,15`。
  - Runtime vs objectives：DTLZ1，`L=200`，`M=7,10,12,15,20,25,30`，每个 `M` 做 50 次独立运行。
  - Solver 与硬件：Gurobi 2025；24 virtual processors、96 GB RAM workstation。
- 主要实验结论：
  - Validity：compact formulation 与 former formulation 得到相同的 final objective value，即 exact MIP-DoM value。作者同时说明，某些实例的 optimal moved set `P'` 不同，这是多最优解导致，不影响 DoM 值。
  - Table I：所有测试场景中 compact formulation 都更快，没有出现比 former formulation 更慢的实例。一个 DTLZ1 例子中，former model 近 117 小时，compact formulation 为 194 秒。原文还引用 WFG1、`L=240`、`M=15` 的 former formulation 近 208 小时案例作为动机。
  - Fig. 1：随解集规模增长，former formulation 的经验复杂度约为 `O(L^2.999)`、`O(L^3.137)`、`O(L^2.888)`，对应 `M=5,10,15`；compact formulation 约为 `O(L^1.972)`、`O(L^2.134)`、`O(L^2.500)`，说明其对解集规模增长更稳。
  - Fig. 2：随目标数增长，former formulation 的经验斜率约为 `O(M^0.768)`，compact formulation 约为 `O(M^2.012)`。作者解释 compact model 因每个目标维度都要建立 Big-M dominance constraints，所以目标数敏感度更高；但其绝对运行时间仍在所有测试实例中低几个数量级。
  - 作者观点：相比 exact HV 在目标维数上的指数式困难，compact MIP-DoM 表现出经验多项式增长，使 DoM 在高维空间中更可作为 exact indicator 使用。
- 消融或机制证据：
  - 论文没有传统算法消融，但机制证据来自 formulation size reduction 和两组 runtime scaling。
  - Big-M 机制的风险和替代：作者说明若 `U_i,m` 较弱会放松 LP relaxation、扩大 branch-and-bound search tree，因此推荐数据相关紧上界或 solver indicator constraints。
  - `P'` 的差异说明 formulation 改变了解空间表示方式，不改变 DoM 最优值；这对未来用 moved set 指导 genetic operators 时很重要，因为具体 `P'` 可能不是唯一。
- 证据边界：
  - 实验主要验证 exact computation speed，不是提出新的 MOEA，也没有把 DoM 真正嵌入 selection loop 做优化性能实验。
  - 运行时间依赖 Gurobi、硬件、solver 参数、Big-M/indicator implementation 和输入解集分布；跨 solver 复现仍需验证。
  - Table I 的 Markdown 抽取严重错位，关键结论已按 PDF 表格目视核验，但不保存全部数值。
  - 当前是 IEEE author version，出版前公式排版、实现链接或实验细节可能调整。

## 局限与未来工作

- 作者明确说明的局限：
  - compact formulation 仍然需要求解 MIP；在更大 `|P|,|Q|` 或更高 `M` 下仍会产生非平凡计算成本。
  - compact formulation 对目标数的经验增长斜率比 former formulation 更高，原因是 dominance constraints 数量随 `|P|*|Q|*M` 增长，且高维下 Big-M relaxation 可能变弱。
  - Big-M 选择不当会带来数值不稳定或松弛过弱问题。
- 作者未来工作：
  - 作者在结论中指出，compact MIP-DoM 的效率可能让 DoM 从离线 quality indicator 转变为 evolutionary many-objective optimization 的驱动机制。
  - 具体方向包括 DoM-based selection strategies，以及利用 explicit moved set `P'` 的几何信息指导 genetic operators。
- 我们认为仍需确认的问题：
  - indicator constraints 与 Big-M formulation 在不同 solver 上的速度、稳定性和最优性证明日志是否一致。
  - 当 `P` 或 `Q` 中存在大量已支配/重复/近重复点时，预处理会对 runtime 和 `P'` 解释产生多大影响。
  - DoM 是有方向的 binary indicator，`DoM(P,Q)` 与 `DoM(Q,P)` 不对称；多算法排名需要设计 pairwise aggregation 或 tournament 规则。
  - 若把 DoM 嵌入每代 selection，MIP 求解频率必须受预算控制，可能需要 warm start、近似筛选或分层调用。
  - `P'` 多最优性会影响“用 moved set 指导算子”的稳定性，需要 tie-breaking 或 ensemble 规则。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建设计知识：紧凑 MIP 的 Dominance Move 精确计算。它不是新的搜索算子，而是一个可移植的 exact indicator computation formulation，可直接用于离线评价、indicator-based selection 和 archive/variation 反馈。
- 暂留在论文卡中的方法、原理或架构启发：
  - `U_i,m = p_i,m - min_j(q_j,m)` 是一个简单但重要的数据相关 Big-M 上界，可作为其他 dominance implication MIP 的建模模板。
  - `P'` 多最优性提醒：当指标求解器不仅输出分数，还输出“解释性移动方案”时，需要区分分数唯一和解释不唯一。
  - DoM 与 HV 的关系可用于 future comparative indicator study，但本文只引用前作相关性结论，不在本论文中重新实验。
- 局部创新线索：
  - 在 archive 更新中只对 critical pair 或候选替换对调用 compact MIP-DoM，避免全量 pairwise MIP。
  - 用 cheap indicators 先筛候选，再对边界决策调用 exact DoM，形成 hybrid indicator selection。
  - 对连续多代相似 `P,Q` 使用 warm start，把上代 `x,z` 作为 MIP 初值。
  - 用 `z(i,m)` 的稀疏模式识别解集缺失的目标方向，指导局部变异或 reference vector 调整。
- 结构创新线索：
  - 构建 DoM-driven indicator population：dominance/decomposition 种群负责生成候选，DoM archive 负责少量高价值 pairwise selection。
  - 将 compact MIP-DoM 与昂贵优化结合：真实评价前用代理预测的 objective sets 计算近似 DoM，真实评价后再用 exact DoM 校准档案。
  - 利用 moved set `P'` 作为几何目标，生成能让当前档案更接近支配 reference archive 的 targeted offspring。
