# 动态优先级与协作子代生成的约束多目标优化

## 一句话理解

DPCMOEA 不把多个约束一次性揉成总 CV，也不在初始阶段固定约束处理顺序。它在搜索进入稳定状态时用 EID 估计“当前种群与每个候选约束 PF 的不一致程度”，动态决定下一个该处理的约束；再把与当前约束一致的约束跳过或少分配资源，并用每个约束的档案参与后续子代生成，让处理一个约束时得到的好解也能服务其他约束。

## 研究问题

- CMOP 中约束数量和约束景观复杂度增加后，传统 CMOEA 很难同时平衡目标优化、可行性恢复和多样性。
- 多阶段 constraint-handling priority 方法把复杂多约束问题拆成逐个约束处理，降低了难度，但已有方法通常在 Stage I 初始估计后静态决定约束顺序。
- 初始阶段只看 UPF 与各约束的关系，可能无法准确反映处理若干约束后的 CPF-CPF 关系。
- 现有优先级方法往往独立处理约束，忽略了约束之间的耦合：处理约束 A 可能已经部分解决约束 B，也可能产生对约束 B 有帮助的个体。

## 方法框架：DPCMOEA

DPCMOEA 包含三个核心模块：

- **Dynamic priority determination (DPD)**：用 EID 动态更新未处理约束的优先级。
- **Automatic resource allocation (ARA)**：根据 EID 判断约束关系，跳过已经一致的约束，并决定下一阶段是否保留当前种群或随机重初始化。
- **Constrained cooperative offspring generation (COG)**：为每个约束维护 archive，把满足其他约束的解用于未来对应约束的子代生成。

算法整体仍是三阶段思路：

- Stage I：不考虑约束，先让种群靠近 UPF，并更新各约束档案。
- Stage II：按动态优先级逐个处理约束；每到 active state 重新计算未处理约束的 EID 和关系。
- Stage III：所有约束处理完成后，回到原始 CMOP 上继续优化目标和可行性。

## 关键机制

### Active state

- DPCMOEA 不在任意时刻都重排约束，而是在 active state 触发。
- active state 表示当前阶段种群已经基本稳定：可行非支配解足够，且最近一段时间平均 fitness 变化低于阈值。
- 这样做的假设是：只有当当前阶段搜索足够稳定时，种群分布才能较可靠地反映当前 CPF 与剩余约束之间的关系。

### EID 动态优先级

- EID 用当前种群在第 `i` 个约束下的可行比例估计：

```text
EID(i, P) = 1 - feasible_rate(i, P)
```

- feasible rate 越低，说明当前种群与该约束对应的 CPF 越不一致，EID 越大，该约束优先级越高。
- Stage I 的 EID 反映 UPF 与各 CPF 的关系；Stage II 的 EID 反映当前已处理约束 CPF 与剩余约束 CPF 的关系。
- 处理过的约束从优先级列表中移除；未处理约束按 EID 排序。

### 约束关系分析与 ARA

DPCMOEA 将当前阶段与候选约束的关系分为三类：

- **Type I consistency**：`EID = 0`，当前种群已完全满足候选约束。该约束可视为已被同时处理，不再分配额外资源。
- **Type II partial inconsistency**：`0 < EID < 1`，当前种群部分满足候选约束。说明已有搜索对该约束有帮助，但仍需后续处理。
- **Type III complete inconsistency**：`EID = 1`，当前种群完全不满足候选约束。说明该约束需要单独重点处理。

重初始化策略：

- 若下一约束下当前种群可行比例较高，即 EID 小于阈值 `zeta=50%`，则从当前种群和档案中保留满足下一约束的解，节省评价资源。
- 若 EID 大于等于 50%，可行解过少且可能集中，算法随机重初始化，避免低多样性可行片段拖累下一阶段。
- 若某约束 EID 为 0，它会直接加入 processed constraints 集合，等价于跳过该约束。

### 约束间协作子代生成

- 为每个约束 `Ci` 维护 archive `A[Ci]`，存储满足该约束的非支配解。
- 额外维护 `A[All]`，保存满足全部约束的解；`A[Cur]` 保存满足已处理约束的解。
- 每个 archive 大小不超过 `N`，只保留非支配解；若超出规模，用 crowding distance 截断。
- 当正在处理约束 `i` 时，环境选择基于 `P union O union A[Ci]`，让过去在其他阶段发现的、满足约束 `i` 的解参与子代生成和选择。
- 处理一个约束时产生的解，只要满足其他约束，也会被写入对应 interconstraint archive，用于后续阶段。

## 实验设置

- 对比算法：C3M、PPS、MSCMO、MCCMO、CMOES、MTCMO。
- 为公平比较，DPCMOEA 与所有对比算法都使用 DE 和 polynomial mutation 作为遗传算子。
- benchmark：MW、DASCMOP、LIRCMOP、DOC、C-DTLZ、DC-DTLZ、CF，以及三个真实问题。
- 真实问题：voltage transformer ratio error estimation、bulk carrier design、car side impact。
- 设置：30 次独立运行；population size `N=100`；可扩展测试问题维度 `D=30`；总评价预算 `FEs=3E6`。
- 指标：benchmark 用 IGD，真实问题用 HV；Wilcoxon rank-sum test 显著性水平 0.05。

## 主要结果

- 整体 benchmark：DPCMOEA 在 72 个 benchmark problems 中取得 41 个最佳结果；C3M、PPS、MSCMO、MCCMO、CMOES、MTCMO 分别为 2、8、1、13、3、4 个。
- 约束数较多时优势更明显：
  - DOC 和 DASCMOP 含 6-14 个约束，DPCMOEA 在 18 个问题中 11 个最佳；
  - 作者归因于动态优先级、约束关系分析和 COG 在复杂多约束场景中更有用。
- 小可行域问题：
  - LIRCMOP 和 MW 上 DPCMOEA 仍有竞争力；
  - 但 LIRCMOP1-4 这类 feasibility difficulty 强的问题中，PPS、CMOES、MTCMO 有时更强，因为它们更充分利用不可行信息逼近小可行域。
- CF、C-DTLZ、DC-DTLZ：
  - DPCMOEA 在 26 个问题中取得 16 个最佳；
  - 这类问题中真 CPF 常是 UPF 的一部分，因此 UPF-first 与约束关系分析都有帮助。
- Runtime：
  - DPCMOEA 总运行时间排第二，仅慢于 MSCMO；
  - 在六类测试集合中的三类运行时间最短；
  - EID 关系分析能识别不必处理的约束，并通过 ARA 减少资源浪费。
- 真实问题：
  - 三个真实 CMOP 上 DPCMOEA 的 HV 均为最好。

## 消融与机制证据

- 去掉 DPD，改用 MSCMO 的 static priority determination 后，有限评价预算下容易把资源花在不重要约束上；预算充足时，顺序影响变小。
- 去掉 ARA 后，DPCMOEA 在 DASCMOP 上 5/9 个问题显著优于无 ARA 版本，且早期收敛更快。
- 去掉 COG 后，完整 DPCMOEA 在 7/9 个 DASCMOP 问题上显著更好，说明约束间协作生成对性能贡献很大。
- EID 估计实验显示，在若干 3-4 约束 benchmark 上，DPCMOEA 对 EID 的预测误差多数在 1%-6% 范围。
- 总是保留当前可行解的 reinitialization 变体 DPCMOEA_RF 在 DASCMOP 上 7/9 个问题更差，说明低可行比例阶段强行保留局部可行解会损害多样性。

## 局限与阅读边界

- EID 只用单约束可行比例，信息很轻量，但不能区分约束违反程度、可修复性和目标空间贡献。
- active state 与 `zeta=50%` 阈值依赖经验设置，复杂问题上可能需要自适应或学习式触发。
- COG archive 只存满足单个约束的非支配解，多约束间的“组合可修复性”没有被显式建模。
- 若可行域极小，单纯按 EID 排序仍可能不如强不可行信息利用方法。
- benchmark 表格多为图片占位，精确数值需查 PDF 或 supplementary。
- 正文称 six benchmark test suites，但列举中包含 MW、DASCMOP、LIRCMOP、DOC、C-DTLZ、DC-DTLZ、CF；阅读时应把 constrained DTLZ 组的计数口径单独确认。

## 可复用知识与创新线索

- 可复用机制：
  - 用可行比例定义约束-PF 不一致度，对未处理约束动态排序；
  - 根据一致、部分不一致、完全不一致三类关系决定跳过、保留或重初始化；
  - 为每个约束维护 interconstraint archive，使处理约束 A 时顺手产生的约束 B 有用解不被浪费；
  - 把重初始化从固定随机改成由下一约束可行比例控制。
- 局部创新线索：
  - 将 EID 扩展为 `feasible_rate + CV distribution + repair success + HV contribution` 的多指标约束优先级；
  - 用 bandit/RL 学习约束顺序和阶段切换，而不是单纯排序；
  - 为约束档案加入约束组合标签，例如同时满足 `Ci,Cj` 的解优先用于耦合约束；
  - 把 DPCMOEA 的约束级档案接入不可行边界辅助或代理辅助 CMOP，让“约束优先级”和“不可行解质量”共同决定资源分配。
