# An asynchronous parallel symbolic regression approach based on multiobjective genetic programming with GPU acceleration

## 一句话理解

本文把符号回归建成“拟合误差 + 模型规模”的二目标 GP 搜索，用全局/局部子数据集把原任务拆成多个异步 MoGP 子任务，并通过外部 model pool 共享精英表达式；同时把表达式评价迁移到 GPU，以提升大数据符号回归的模型探索率。

## 问题与动机

- 研究问题和场景：大规模数据上的 GP-based symbolic regression 要同时搜索表达式结构和系数，容易出现盲目搜索、模型膨胀、种群多样性丢失和评价成本过高。
- 现有算法为什么不足：
  - 普通 GP/SR 串行演化，模型评价随数据量和表达式规模变大而成为瓶颈。
  - 普通并行 GP 只并行多个小种群，未必能快速产生高质量模型。
  - 早期 cross-parallel MoGP 周期性收集并重分发个体，本质上仍有串行同步阶段，打断了子任务的连续演化。
  - 单纯 GPU 加速若只加速评价而演化仍串行，CPU/GPU 之间还可能有较重通信开销。
- 本文希望解决什么：让多个分解子任务持续异步演化，同时用 model pool 进行精英共享，以改善泛化、多样性和效率；再用 CPU-GPU 架构加速表达式评价，减轻大数据评价压力。

## 核心理念与算法流程

- 核心理念：符号回归可以拆成多个“全局建模”和“局部修正”子问题；不同子任务产生的精英表达式包含互补结构信息。不要等所有子任务同步停顿再交换，而应让精英通过外部池异步流动。
- 主要流程：
  1. 将 SR 建模为二目标问题：最小化训练 RMSE，同时最小化表达式节点数。
  2. 从原始数据 `D` 采样全局代表子数据集 `D_g` 或局部区间子数据集 `D_l`，形成多个 SR 子任务。
  3. 创建 `K+1` 个线程：`K` 个线程运行子任务 MoGP，一个线程维护 model pool。
  4. 每个子任务独立演化；每隔固定代数，从 model pool 随机取若干模型 seed 当前子任务，扰动搜索方向。
  5. 每个子任务周期性把精英模型加入队列；pool 线程异步取队列中的模型并更新 model pool。
  6. model pool 未满时直接加入；已满时让新模型与池中随机模型竞争，保留更优者。
  7. GPU 版本中，CPU 负责模型演化，GPU 保存数据并执行表达式树的后缀表示栈式评价和 reduction 求 RMSE。
- 关键组成部分：
  - MOPSR：`RMSE(f,D)` 与 `SIZE(f)` 两目标共同控制精度和可读性。
  - Global/local regression decomposition：用全局子样本模拟 model casting，用局部子样本模拟 model polishing。
  - Model pool：外部精英池作为异步通信机制，避免所有子任务同步停顿。
  - Queue-based pool update：新精英先进入队列，pool 线程异步消费，降低频繁全量非支配更新压力。
  - Hybrid CPU-GPU evaluation：表达式树序列化为后缀 Polish 表示，GPU 对数据实例并行执行栈式计算并 reduction 汇总误差。
- 可能被修改的位置：子数据集采样方式、子任务类型、model pool 更新策略、扰动频率、扰动模型数、精英比较准则、GPU 表达式编码和异常保护。
- 必须保留的核心：若作为基础算法，应保留“分解子任务连续异步演化 + 外部精英池共享”机制；只保留二目标 GP 或只做 GPU 评价，不等同于本文的异步并行框架。

## 实验证据

- 测试问题和对比算法：消融实验使用 6 个 ground-truth 与 3 个 black-box benchmark，50 次独立运行；比较 gplearn、EFS、GSGP、GSGP-GD、GSGP-Red、ML-PIE、DGP、DGP+、MoGP、MoGP+ 等。SRBench 比较覆盖 130 个 ground-truth 和 122 个 black-box regression problems。GPU 实验使用 Pagie-1 不同数据规模和 4 个 black-box 大数据集。
- 异步框架效果：
  - Fig. 10 显示 DGPMP 相比 MoGP 和 DGP 更快收敛到更低 train/test RMSE。
  - Table 4 中，DGPMP-2 和 DGPMP-6 相对标准 MoGP 在多数问题上 train/test RMSE 显著更好，Pagie-1 是明显例外。
  - Fig. 12 显示 DGPMP 在多数问题上得到相对简洁模型；作者认为其搜索能力较好。
  - SRBench 结果中 DGPMP 不是所有指标第一；作者报告 ground-truth 和 black-box 上 DGPMP 综合排名第三，GP-GOMEA 和 SBP-GP 在 `R2_test` 与 solution rate 上更好。
- 运行效率：
  - 作者在贡献段报告 CPU-only DGPMP 六子任务相对标准 MoGP 在 ground-truth 上加速 `6.36-48.78x`，black-box 上加速 `6.12-6.91x`。
  - GPU 实验中，HDGPMP 在大规模 ground-truth 和 black-box 上相对 MoGP 的 MER 加速分别达到 `365.46x` 和 `188.36x`；相对 DGPMP 为 `28.18x` 和 `15.24x`。
  - HMoGP 在小数据 `fri_c3` 上可能慢于 CPU MoGP，作者归因于 CPU-GPU 通信开销。
- 证据边界：
  - 并行收益强依赖数据规模、表达式评价成本、线程/硬件配置和实现。
  - GPU 加速证据在 GTX 1080 Ti、CUDA 11.4、Numba 0.55.1 环境下给出。
  - DGPMP 部分运行出现算术异常，如除零或对负数取对数，导致 test RMSE 计算失败。

## 局限与未来工作

- 作者明确说明的局限：
  - DGPMP 在提取和利用子任务演化模型中的 informative parts 方面仍有不足。
  - CPU-GPU/分布式性能受子任务间数据传输能力和异构设备协调能力限制。
  - 子任务用小子数据集评价模型，可能导致 GPU 利用率偏低。
- 作者未来工作：
  - 引入更高效的子任务协作或信息融合技术，提高高质量模型产生能力。
  - 改进异构分布式资源组织和数据传输。
  - 更合理地部署 GPU 或其他高性能计算资源。
- 我们认为仍需确认的问题：
  - model pool 的随机竞争替换是否会丢失稀有但有潜力的结构。
  - 子数据集上表现好的表达式迁移到全数据时如何避免过拟合或异常表达式。
  - 多 GPU 资源如何按子任务数据规模和模型复杂度动态调度。
  - 该异步精英池是否能迁移到非 SR 的程序搜索、NAS 或组合结构进化。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 异步子任务精英池协同进化：可用于分解式 GP、程序搜索、结构搜索或多子任务 MOEA。
- 暂留在论文卡中的方法、原理或架构启发：
  - 表达式树序列化为后缀 Polish 表示，再在 GPU 上用栈式解释器并行评价。
  - 用 reduction 汇总每个数据实例的平方误差，减少 CPU-GPU 数据往返。
  - 用 RMSE/size 二目标控制符号回归模型性能和可读性。
- 局部创新线索：
  - 用非随机 pool 替换策略，如按拥挤度、结构新颖性、跨任务泛化表现或异常风险保留模型。
  - 给精英模型迁移增加可行性/安全检查，避免传播除零、非法 log 等表达式。
  - 按子任务近期收益自适应调整扰动频率和扰动模型数量。
- 结构创新线索：
  - 构建“子问题采样 -> 异步结构搜索 -> 精英池共享 -> 异构评价加速”的通用结构进化框架。
  - 将 model pool 视为跨任务结构记忆，可与图神经网络、语法约束或代理评分结合。
