# Deep Reinforcement Learning-Assisted Automated Operator Portfolio for Constrained Multi-Objective Optimization

## 一句话理解

论文提出 CMOEA-AOP：不是让强化学习每代只选一个遗传/差分算子，而是用 DDPG 根据当前种群的 convergence、diversity、feasibility 和 evolutionary stage 输出多个算子的使用比例，让一个 generation 内同时使用多种搜索范式，以提高 CMOEA 在复杂可行域上的稳健性。

## 问题与动机

- 研究问题和场景：constrained multi-objective optimization problems (CMOPs)。约束会改变搜索空间形状并产生 infeasible regions，目标是在 feasible regions 中找到兼具 convergence 与 diversity 的 Pareto solutions。
- 现有算法为什么不足：
  - 多数 CMOEA 已设计大量 CHT、multi-stage、multi-population 或 multi-task 机制来平衡 objective optimization 与 constraint satisfaction，但 offspring generation 常仍使用固定 variation operator。
  - No free lunch 意味着单一 variation operator 无法适配所有 CMOP。GA/SBX、DE/rand/1、DE/best/1 等算子分别偏向 multimodal search、decision dependency exploration、diversity 或 convergence。
  - 既有 adaptive operator selection 和 DRL operator selection 通常每代推荐单个 operator，容易让一代搜索过度偏向 exploration 或 exploitation，也可能因随机高 reward 过度推荐某个算子。
  - CMOP 同时要考虑 constraints 与 objectives，单一 operator paradigm 更容易陷入局部可行区域或难以进入 feasible regions。
- 本文希望解决什么：将 operator adaptation 从“选一个算子”扩展为“推荐 operator portfolio ratio”，让同一 generation 内不同 offspring 由不同比例的算子生成，并用 DRL 根据 population state 学习长期收益。

## 核心理念与算法流程

- 核心理念：把当前 population state 到 operator ratio vector 的映射交给 DDPG actor-critic 学习。Action 是连续的 operator portfolio，而不是离散单算子；reward 是当前 population 相对上一代的 HV improvement；state 同时包含 optimization-related 和 constraint-related features。
- 主要流程：
  1. 输入 population size `N` 与 maximum function evaluations `FEmax`。
  2. 初始化 RL agent、experience pool `EP` 和所嵌入 CMOEA 的初始 population。论文实验中嵌入 EMCMO。
  3. 每代提取当前 population state `s=(con, div, fea, lambda)`。
  4. DDPG actor 输出当前 action，即候选算子使用比例。候选算子为 GA/SBX、DE/rand/1、DE/best/1。
  5. 按 action 指定比例生成 offspring，并用所嵌入 CMOEA 的环境选择产生下一代。
  6. 用 population HV 相对上一代的 improvement 作为 reward，记录 `(s_t,a_t,r_t,s_{t+1})` 到 experience pool。
  7. 从 `EP` mini-batch 训练 critic 与 actor，并用 target actor/critic soft update 稳定训练。
  8. 循环直到评价预算耗尽，输出 final population。
- 关键组成部分：operator portfolio action、DDPG actor-critic、population state `(con, div, fea, lambda)`、HV improvement reward、experience memory pool、target networks、CMOEA plug-in wrapper。
- 可能被修改的位置：CMOEA 的 offspring generation controller、多算子比例分配、策略层状态特征、reward 设计、约束信息编码。
- 必须保留的核心：action 必须是多个算子的比例或组合，而非单一算子；state 必须同时表达优化状态和约束状态；reward 应反映算子组合对 population convergence/diversity 的后续贡献。

## 实验证据

- 测试问题和对比算法：
  - Benchmark suites：CF 10 个、LIR-CMOP 14 个、DAS-CMOP 9 个，共 33 个 test instances。
  - 目标与变量：CF1-7 为 `M=2,D=10`，CF8-10 为 `M=3`；LIR-CMOP1-12 为 `M=2,D=30`，LIR-CMOP13-14 为 `M=3`；DAS-CMOP1-6 为 `M=2,D=30`，DAS-CMOP7-9 为 `M=3`。
  - Baselines：EMCMO、Bico、AGEMOEA-II、TSTI、DRLOS。DRLOS 是同类 RL-assisted single-operator selection baseline。
  - 平台与设置：PlatEMO；population size 100；maximum 100000 function evaluations；30 independent runs；IGD 指标，使用 10000 reference points；Wilcoxon rank-sum test 0.05。
  - CMOEA-AOP 嵌入 EMCMO；discount factor `gamma=0.98`，batch size `BS=32`。
- 主要实验结论：
  - Table I：CMOEA-AOP 在 33 个实例中 23 个取得最佳 IGD。
  - 统计检验：CMOEA-AOP 相对 EMCMO、Bico、AGEMOEA-II、TSTI、DRLOS 分别在 26、25、31、30、20 个实例上显著更好。
  - Fig. 3 LIR-CMOP12：该问题 feasible region narrow 且 separated；作者观察 AGEMOEA-II 陷入局部可行区域，TSTI 只找到边缘部分，CMOEA-AOP 得到更多且更均匀的可行解。
  - Fig. 4 DAS-CMOP8：CMOEA-AOP 能识别可行解并保持较均匀分布。
  - Fig. 5：在 CF6、LIR-CMOP3、LIR-CMOP4 上，CMOEA-AOP 收敛更快；作者指出 50000 FEs 的结果可与多个 baseline 100000 FEs 的结果竞争。
  - 与 EMCMO 对比：两者 constraint handling 机制一致，性能差异主要来自 AOP 控制 offspring operator portfolio。
- 消融或机制证据：
  - Motivation Fig. 1：EMCMO 只用 GA、只用 DE、GA/DE 半半的最佳表现随 CF2、CF6、CF9 不同，说明固定 portfolio 不具普适性。
  - Table II ablation：与只用 genetic operator、DE/rand/1、DE/best/1 的三个变体相比，CMOEA-AOP 显著更好次数为 28、16、16。单算子变体可能在少数问题上最好，但整体泛化差。
  - 相比 DRLOS：DRLOS 每代只学并推荐一个 operator；CMOEA-AOP 学比例组合，在复杂可行域上更稳健。
- 证据边界：
  - AOP 只在 EMCMO 中做主实验，虽然作者称可嵌入多数 CMOEA，但跨框架移植证据仍不足。
  - Candidate operator 只有三类，尚不清楚大动作空间、带修复算子或代理生成算子时 DDPG 是否稳定。
  - Reward 使用 HV improvement，但最终报告指标为 IGD；HV 需要 reference point，实际 CMOP 中 reference point 和 feasible HV 计算细节需复核。
  - State 的 feasibility 只用 average CV，没有区分每个 constraint；作者也将 per-constraint feature 作为未来工作。

## 局限与未来工作

- 作者明确说明的局限：
  - 当前 feasibility state 使用每个解的整体 CV，未分别考虑每个 constraint function。
  - RL 训练神经网络需要较多时间资源。
  - 当前实验集中在 CMOP benchmark，未扩展到 unconstrained MOP 或真实工程场景。
- 作者未来工作：
  - 将 automated operator portfolio 扩展到 unconstrained MOP。
  - 将 feasibility feature 从整体 CV 扩展到每个 constraint function。
  - 探索 pre-trained large language models 用于 automated operator portfolio。
- 我们认为仍需确认的问题：
  - DDPG 的训练成本相对 100000 FEs 是否在昂贵真实问题中划算。
  - Action 输出比例如何离散到具体 offspring 数量，四舍五入或小种群下是否产生偏置。
  - HV reward 在不可行解较多或参考点选择不稳时会不会误导。
  - 是否需要把 operator cost、repair success、feasible offspring ratio 加入 reward。
  - 多约束问题中 average CV 可能掩盖少数关键约束，per-constraint state 可能很重要。

- 暂留在论文卡中的方法、原理或架构启发：
  - 用 softmax actor 输出 operator proportions，可作为“策略网络输出资源分配比例”的模板。
  - Motivation Fig. 1 提醒：固定半半 portfolio 也只是静态配置，真正可复用的是按 population state 调比例。
  - 如果训练成本高，可以把 DDPG 换成 bandit/Dirichlet policy/轻量 actor，只保留 portfolio action idea。
- 局部创新线索：
  - 将 action 扩展为 `(operator ratio, parameter ratio, repair ratio)` 的联合连续控制。
  - Reward 加入 feasible offspring ratio、CV reduction、IGD surrogate 或 operator cost penalty。
  - State 从 population average 扩展为 per-reference-vector 或 per-constraint summary。
  - 在 early stage 强制 entropy floor，避免 actor 过早把比例集中到单一算子。
- 结构创新线索：
  - 构建 CMOEA policy layer：state encoder 读取目标/约束/阶段，actor 输出算子、修复、局部搜索和评价预算比例，environmental selection 保持可替换。
  - 与多任务 CMOEA 结合：主任务和辅助任务各自维护 portfolio actor，或共享 actor 但输入 task-specific state。
  - 将 AOP 用于昂贵优化：actor 输出代理搜索、真实评价和局部修复的比例，而不只是 variation operators。
