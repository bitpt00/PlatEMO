# A hybrid NSGA-II and delayed local search approach for home healthcare scheduling and routing optimization

## 一句话理解

本文针对多目标上门医疗调度与路径问题，将 NSGA-II 的全局探索先运行到中期，再在第 500 代插入跨护理人员患者交换的 first-improvement 局部搜索，用“延迟强化”在 Pareto 多样性、总工作/行驶时间和计算成本之间取得折中。

## 问题与动机

- 研究问题和场景：Home Healthcare Scheduling and Routing Problem (HHCSRP)，需要为有限护理人员安排患者服务顺序和路线，满足时间窗、技能匹配、班次/工作时长与路径连续性等约束。来源：Sec. 3.1-3.2，PDF 4-5。
- 现有算法为什么不足：
  - HHCSRP 是 VRPTW 的更复杂扩展，加入患者偏好、护理人员技能匹配、服务时间窗和多利益相关者目标，实际规模下 NP-hard。来源：Sec. 3、Sec. 5.2.1。
  - 许多研究使用 scalarization，需要专家设置权重，现实中主观且不便。来源：Sec. 1。
  - 既有 HHCSRP 研究常强调患者偏好、服务成本或单一利益方，较少把护理人员工作负载公平性与旅行/等待效率一起建模。来源：Sec. 1、Table 1。
  - NSGA-II、MOEA、SPEA2 等非支配排序方法能避免权重，但在 HHCSRP 中与局部搜索的系统集成仍不足；已有局部搜索混合方案也未明确何时插入 LS。来源：Sec. 2、Sec. 3。
- 本文希望解决什么：同时最小化护理人员行驶/工作时间、等待时间和负载不平衡，并验证中期局部搜索比过早或过晚局部搜索更能避免早熟、改善解集质量和多样性。

## 核心理念与算法流程

- 核心理念：局部搜索不是越早越好。先让 NSGA-II 用非支配排序和 crowding distance 形成足够多样的搜索分布，再在中期对整个人群做问题特定的跨护理人员 swap 局部搜索，使局部强化发生在已有全局覆盖之后，减少过早陷入局部最优。
- 主要流程：
  1. 用患者-护理人员 assignment pairs 编码染色体，每个患者出现一次；按 caregiver ID 排序，使同一护理人员的任务连续。来源：Sec. 4.1，PDF 5。
  2. 用 tournament selection、SBX 和 polynomial mutation 生成子代；交叉可能产生重复/缺失患者，因此保留首次出现并把重复项修复为具备技能且满足容量/时间窗的可行护理人员。来源：Sec. 4.1。
  3. 用标准 NSGA-II 的 fast non-dominated sorting 和 crowding distance 选择下一代，评价目标为行驶/工作时间、等待时间和负载均衡。来源：Sec. 4.1、Algorithm 1。
  4. 在中代固定触发局部搜索，实验主方案为 generation 500；伪代码写为 `gen % LS_interval == 0` 时对下一代应用 `applyMidGenerationLS`。来源：Sec. 4.3、Algorithm 1。
  5. 单解局部搜索采用跨护理人员 swap：随机选择两个护理人员，各选一个患者并交换分配；若满足时间窗、技能和工作量容量等约束，则评价；若新解 Pareto 支配当前解，则 first-improvement 接受并重启邻域扫描。来源：Sec. 4.2.1、Algorithm 2。
  6. 使用 hypervolume 停滞早停：若连续 `P` 代 HV 改善低于阈值 `epsilon`，提前停止；否则最多运行 `Gmax` 代。来源：Algorithm 1。
- 关键组成部分：
  - 延迟/中期 LS 触发：避免初始化或早期 LS 过度开发；
  - 问题特定 swap 邻域：只在护理人员之间交换患者分配，保留 assignment 编码；
  - 可行性过滤：时间窗、技能适配和工作量容量必须通过；
  - Pareto dominance first-improvement：只接受支配当前解的首个邻居，控制局部搜索成本；
  - NSGA-II 多样性外壳：非支配排序与 crowding distance 继续维护 Pareto front；
  - HV 停滞早停：避免后期无效迭代。
- 可能被修改的位置：
  - generation 500 可替换为自适应触发，例如 HV plateau、front size 停滞、crowding 退化或可行率稳定；
  - swap 邻域可扩展为 insert、2-opt、route segment exchange、skill-aware reassignment 或 VNS/ALNS destroy-repair；
  - LS 接受准则可从纯支配关系扩展为 epsilon dominance、HV contribution、参考向量改善或可行性优先；
  - LS 可以只作用于精英、稀疏区代表、拥挤区代表或随机子集，而不是全体种群；
  - 可用 bandit/RL 控制 LS 触发频率和邻域类型。
- 必须保留的核心：先全局探索、再中期局部强化、最后继续 NSGA-II 选择维护 Pareto 多样性的阶段逻辑。若把 LS 放在初始化或早期，论文证据显示会过度开发；若只有后期 LS，剩余代数不足以扩散收益。

## 实验证据

- 测试问题和对比算法：
  - 39 个 adapted Solomon instances：small 25 patients/2 caregivers、medium 50/3、large 100/4，每类 13 个实例。来源：Sec. 5.1.2。
  - 对比/变体：NSGAII baseline、NSGAII-ILS（初始化+200/400/700 代 LS）、NSGAII-MLS（generation 500 LS）、NSGAII-LLS（200/400/700 代 LS，正文称 later generations 但命名略混乱）、Gurobi-MILP、K-NSGAII。来源：Sec. 5.1.3。
  - 参数：population size 100，crossover rate 0.9，mutation rate 0.2，local search probability 0.15，1000 generations；每实例 20 次独立运行。来源：Sec. 5.1.4-5.1.6。
  - 运行平台：Intel i7-1355U、16 GB RAM、Windows 11、C++17、Visual Studio 2022 `/O2`、Gurobi 11.0.3。来源：Sec. 5.1.1。
- 主要实验结论：
  - Gurobi validation：C101.25.4 在 8.6 s 得到最优 TWT `246.9`；C101.25.2 被判 infeasible；C101.100.4、C107.100.4、C206.50.3 在 600 s time limit 下无法给出保证最优，支持大规模 HHCSRP 的元启发式必要性。来源：Table 3，PDF 7。
  - 局部搜索插入时机：generation 500 的 NSGAII-MLS 在 Table 6 中 Avg_HV `0.76`、DeltaHV `0.34`，相对 baseline NSGAII 的 DeltaHV `0.39` 稳定性更好；早期 ILS 的 DeltaHV `0.45`，过度开发风险较高；LLS DeltaHV `0.28` 但 Avg_HV 低至 `0.66`。来源：Sec. 5.2.3、Table 6。
  - C101-100-4 讨论：NSGAII-MLS 的 TWT 从 NSGAII-LLS 的 `5806.37` 降至 `3536.80`，约 39% 降低，HV `0.76` 接近 baseline `0.77`，|FP| `38.5`，说明中代 LS 用 TWT 改善换取可接受的 HV。来源：Sec. 5.3。
  - 统计一致性：C104/C101 100-4 统计表给出 TWT mean `3628.49`、std `54.74`、95% CI `[3555.15,3701.83]`，WLB mean `207.09`、CV `5.0%`，HV mean `0.77`、CV `14.6%`。来源：Table 7。
  - Pareto front 质量：Table 10 给出 front size mean `38.5`、spacing mean `0.089±0.017`、HV mean `0.82±0.05`；front size 与 spacing 呈负相关 `r=-0.567, p<0.01`，作者解释为较大 front 并非简单聚簇。来源：Sec. 5.2.5、Table 10，PDF 12。
  - Solomon sample：代表实例中 HV 覆盖 `0.63-0.86`，如 C101.100.4 的 FP `38.50`、HV `0.76`，R109.100.4 的 HV `0.86` 但 FP `4.21`。来源：Tables 8-9。
  - K-NSGAII 对照：NSGAII-MLS 生成的 Pareto front size 通常比 K-NSGAII 高 6-9 倍，如 C101.100.4 为 `38.50` vs `5.75`；但 K-NSGAII CPU 时间低 50-80%，且在部分 clustered instances 上 HV/TWT 略优。来源：Sec. 5.2.6、Table 11。
- 消融或机制证据：
  - 四种 LS 插入配置的 Table 4-6 是本文核心机制证据，显示早期 LS 容易早熟、过晚 LS 不能充分利用改进，中代 LS 提供较稳折中；
  - Gurobi 小/大实例对照说明问题规模上升后 exact solver cliff；
  - K-NSGAII 对照说明 NSGAII-MLS 的主要优势是解集丰富度和 unstructured/mixed 情况适应性，代价是更高 CPU。
- 证据边界：
  - 本文主要证据来自 adapted Solomon HHCSRP，不代表所有 VRP/调度问题；
  - generation 500 是手工/预实验选择，没有自适应触发机制；
  - 局部搜索只使用一种 swap 邻域，缺少 VNS/ALNS/insert/2-opt 等邻域消融；
  - 表格和正文有多处命名/口径不一致，精确逐实例数值应回查 PDF 或原始数据；
  - K-NSGAII 在速度和部分 clustered cases 上更强，因此本文方法适合优先需要多样 Pareto 备选而非最低运行时间的场景。

## 局限与未来工作

- 作者明确说明的局限：
  - NSGAII-MLS 有 runtime penalty，K-NSGAII 在计算速度上通常快 50-80%；
  - 随机/混合实例中存在前沿多样性有限和 spacing 不均，如 random instances 的 Avg_FP 较低、部分 WT spacing 较大；
  - 复杂实例中仍有 workload imbalance，例如 C201-100-4 Avg_WLB `174.39`；
  - 当前模型优先验证静态结构化 routing，对动态/不确定场景尚未处理。来源：Sec. 5.3、Sec. 6。
- 作者未来工作：
  - 集成 adaptive local search 或与其他方法 hybridization，以降低计算成本并改善 random-instance variability；
  - 扩展到 e-commerce、public transport 等行业；
  - 处理 patient health uncertainty 下的 dynamic home healthcare scheduling and routing。来源：Sec. 6。
- 我们认为仍需确认的问题：
  - 中代 LS 的最佳触发点是否与实例类型、可行率、HV 停滞或 front density 相关；
  - 局部搜索概率 `0.15` 与全体/子集应用策略是否有系统调参；
  - 使用 Pareto dominance first-improvement 是否过于保守，可能拒绝有长期价值但暂不支配的邻居；
  - PSKL 在结果表中作为 penalty 出现，但正文主目标为三目标，约束/惩罚如何进入环境选择需要更清晰；
  - 与 K-NSGAII 的对比是否在完全相同目标定义、约束惩罚和停机条件下进行。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建“延迟中代局部搜索的 memetic MOEA”：把局部搜索插入时机本身抽象为可迁移的探索-开发阶段调度机制。
- 暂留在论文卡中的方法、原理或架构启发：
  - 对调度/路径类 MOO，局部搜索触发位置可能比邻域本身同样重要；
  - first-improvement Pareto LS 是一种低成本、保守的局部强化方式；
  - 用 Gurobi 小实例验证模型、大实例证明求解 cliff，可作为应用型 MOEA 论文证据结构；
  - 输出丰富 Pareto front 比单个快解更适合医疗排班管理者做政策权衡。
- 局部创新线索：
  - 用 HV/crowding/front-size 反馈动态触发 LS，而不是固定第 500 代；
  - 按 Pareto 区域选择 LS 邻域：TWT 极端区用 route/2-opt，WLB 极端区用 workload swap，WT 极端区用 time-window insert；
  - 对随机/混合实例引入多样性保护或 slack-aware repair；
  - 将 LS 接受从支配关系扩展到 epsilon-dominance + constraint improvement + diversity contribution。
- 结构创新线索：
  - “global MOEA exploration -> delayed problem-specific local search -> diversity-preserving environmental selection”的结构可迁移到 VRP、MRTA、生产调度、能源调度和其他离散组合 MOO；
  - 与成功率反馈或 DRL 算子选择结合，可将“是否启用 LS、用哪个邻域、作用于哪些个体”统一成策略调度问题。
