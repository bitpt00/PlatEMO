# Multi-objective optimization in autonomous foraging using swarm robots

## 一句话理解

论文把群机器人觅食行为从“手工设定局部交互规则”改成一个六目标优化问题：用 RAOI 行为区参数控制 repulsion、attraction、orientation 和 influence，机器人数量也作为决策变量；每个候选配置通过随机仿真评价 completion time、travel distance/energy、workload balance、delivery efficiency、uncollected objects 和 swarm size。作者用 MOEA/D 与 NSGA-III 生成 Pareto 配置，并引入 dynamic table：对归一化参数空间中足够相近的候选复用历史仿真指标，以减少重复昂贵仿真。

## 问题与动机

- 研究问题：
  - 群机器人 foraging 需要在无中心控制、无直接通信和有限感知下完成 search-collect-deliver；
  - 局部交互规则的参数会同时影响避碰、协同运输、搜索覆盖、能耗和机器人数量；
  - 单一“最快完成”或“最少机器人”目标会牺牲其他性能；
  - 仿真评价随机、耗时，并且每个候选参数集需要多次 replicas 才稳定。
- 现有方法为什么不足：
  - 手工调 RAOI/boids 类局部规则难以解释多指标折中；
  - 只优化固定 swarm size 会忽略机器人数量与协同效率之间的冲突；
  - PSO/GA 等单目标或少目标调参容易给出单点解，而不是可供任务选择的 Pareto 配置；
  - 昂贵仿真若每个相近候选都重复跑 50 次 replicas，会浪费大量计算。
- 本文希望解决什么：
  - 将 RAOI 交互区半径和 swarm size 作为 MOO 决策变量；
  - 用六个 objective 显式刻画 foraging 性能；
  - 比较 MOEA/D 和 NSGA-III 得到的 Pareto 配置一致性；
  - 用 dynamic table 缓存近邻参数配置的评价结果，减少冗余仿真。

## 核心模型与算法流程

- RAOI 行为模型：
  - `ZOR` / repulsion：半径 `rr`，优先级最高，用于避碰；
  - `ZOA` / attraction：半径 `ra`，让机器人靠近邻居，形成协作或链式运输；
  - `ZOO` / orientation：半径 `ro`，让机器人与邻居方向对齐；
  - `ZOI` / influence：半径 `ri`，表示 nest/object 等任务相关刺激，解耦 peer attraction 与 task stimulus attraction；
  - 机器人根据活跃区域计算 repulsion、attraction、orientation、influence 方向向量，并按权重组合；
  - 如果新方向与当前方向夹角超过最大转角，则受物理转向约束截断。
- 机器人与任务：
  - 使用 differential wheeled mobile robots (WMRs) 仿真，机器人有 DC motor 动力学；
  - 机器人不能直接通信，也不知道全局运动方向，只能通过本地邻居、边界和环境刺激感知；
  - foraging 用 search/delivery 两状态有限状态机表示；
  - gripper open `rho_i=0` 为搜索状态，gripper closed `rho_i=1` 为搬运/返回状态；
  - 机器人在搜索区发现 object 后携带回 nest，再重新搜索。
- 仿真环境：
  - 10 m x 10 m 方形区域；
  - 机器人初始在 2 m x 2 m nest 内随机放置，nest influence radius 为 4 m；
  - 20 个 objects 放在以 `(7.5, 7.5)` 为中心的 2 m x 2 m search square 内，search influence radius 为 2.5 m；
  - swarm size 取 5-20；
  - reference time limit `kappa_ref = 3600 s`；
  - 考虑有限感知范围、视场、距离/角度扰动、线速度/角速度/转向约束和运动随机扰动；
  - 每个配置运行 replicas，作者用收敛判据确定约 50 次 replicas 后响应稳定。
- 六个目标函数：
  - `f1`：completion time，最小化；未完成则惩罚为 `kappa_ref`；
  - `f2`：energy consumption proxy，平均 travel distance per robot，最小化；
  - `f3`：balanced workload，机器人运输物体数量的标准差，最小化；
  - `f4`：swarm efficiency，delivery time 相对 total completion time 的比例，最大化；
  - `f5`：uncollected objects，时间结束后未收集物体数，最小化；
  - `f6`：swarm size / `TR`，最小化。
- 优化设置：
  - 决策变量为 `rr`、`ro`、`ra` 和 swarm size；`ri = 2 m` 固定；
  - `rr` 范围 `0.01-0.4 m`；
  - `ro` 范围 `0.2-1.2 m`；
  - `ra` 范围 `0.2-3 m`；
  - swarm size 范围 `5-20 robots`；
  - 使用 MOEA/D 和 NSGA-III；
  - objective functions 数量为 6；
  - total generations 为 25；
  - repository size 为 100；
  - 每个 solution 的 replicas 为 50；
  - 三次 independent optimization experiments，各自保留 100 个非支配解，合并得到 300 个非支配可行解；
  - Python 3.8.12，2.9 GHz Intel Core i7-7500U CPU，8 GB RAM。
- dynamic table：
  - 存储已评价参数配置及其 performance metrics；
  - 新候选先映射到归一化参数空间；
  - 用 Euclidean distance 查询已存配置；
  - 如果距离小于阈值，则复用历史 metrics，不重新运行 50 次 replicas；
  - 如果无近邻命中，则运行 swarm simulation 并更新表；
  - 该机制不训练 surrogate，而是近邻缓存复用。

## 实验证据

- 仿真和优化设置：
  - 20 个 objects，5-20 个 robots；
  - 每个候选配置约 50 次 replicas；
  - 每次优化 repository size 为 100；
  - 三次独立优化合并得到 300 个非支配可行解；
  - MOEA/D 和 NSGA-III 的 Pareto fronts 分别在 Fig. 7 和 Fig. 9 中展示。
- objective 范围：
  - Table 3 报告 `f1` 范围 `673.46-3490.22 s`；
  - `f2` 范围 `154.97-780.23 m`；
  - `f3` 范围 `0-0.8044`；
  - `f4` 范围 `0.1910-0.4085`；
  - `f5` 范围 `0.4656-1.6720`；
  - `f6` 范围 `5-20`。
- Table 4 的代表性 RAOI 配置：
  - Solution 1：`rr=0.3144`、`ro=0.2000`、`ra=1.5897`、7 robots，`f1=1530.53 s`、`f2=348.45 m`、`f4=0.3509`、`f5=0`；
  - Solution 3：`rr=0.3341`、`ro=1.2000`、`ra=0.7762`、9 robots，`f1=1029.26 s`、`f2=227.14 m`、`f4=0.4085`；
  - Solution 7：`rr=0.4000`、`ro=1.2000`、`ra=1.6904`、12 robots，`f1=956.58 s`、`f2=212.04 m`；
  - Solution 8：`rr=0.2153`、`ro=0.6804`、`ra=0.4000`、12 robots，作者认为约 10-12 robots 附近可形成较好 swarm efficiency；
  - Solution 9：`rr=0.1900`、`ro=0.9641`、`ra=1.9768`、13 robots，`f1=874.18 s`、`f2=198.35 m`；
  - Solution 10：`rr=0.4000`、`ro=0.3021`、`ra=0.8652`、14 robots，`f1=1012.30 s`、`f2=224.51 m`。
- 机制观察：
  - 更多 robots 通常降低 completion time 和 travel distance，因为更紧密互动促进协作；
  - 机器人太少时，workload 分配更不均衡，其他目标也更难接近最优；
  - swarm efficiency 在过少或过多 robots 时都不稳定，约 10-12 robots 的中间规模有较好折中；
  - `f1` completion time 和 `f2` travel distance/energy 表现出强相关；
  - 多数 objective 在 parallel coordinates 中相对 harmonious，但 minimization of swarm size 与其他性能目标冲突。
- MOEA/D 与 NSGA-III：
  - NSGA-III 产生的 Pareto front 分布与 MOEA/D 类似；
  - 作者据此认为 RAOI 参数优化结果不依赖单一 MOO 算法。
- dynamic table：
  - 作者明确称 dynamic table 可减少计算负担并避免重复评价；
  - 论文没有给出具体命中率、节省时间百分比或阈值敏感性，证据以方法说明和定性结论为主。

- 与非优化默认 RAOI、随机搜索、贝叶斯优化、代理辅助 MOO 等对比不足，性能提升主要来自 Pareto 可视化和配置分析。
- 实验为仿真研究，物理 swarm 只引用 RAOI 规则已有实现，本文优化配置尚未在实体机器人上验证。

## 局限与未来工作

- 作者明确局限/未来方向：
  - 需要在真实 swarm robots 上验证优化参数；
  - 未来考虑多个 targets 和多个 influence stimuli；
  - 开发 task allocation criteria，加入更多 influence mechanisms；
  - 由于优化耗时，可探索 surrogate modeling 或 machine learning 加速。
- 我们认为仍需谨慎的问题：
  - 近邻缓存复用可能把细微但重要的 RAOI 差异抹平；
  - 六目标中部分目标高度相关，真实 many-objective 难度可能被放大或冗余化；
  - `f4` 为最大化而其他目标多为最小化，归一化和选择方向需要在实现中明确；
  - swarm size 既是决策变量又是 objective，容易形成“更多机器人更好但成本更高”的简单主导结构；
  - 仿真环境较规整，实际环境中的障碍、通信干扰、定位误差和硬件故障可能改变 Pareto 配置。

## 可迁移设计要点

- 群体行为的局部规则半径和权重可以显式作为 MOO 决策变量，而不是经验固定；
- 任务刺激最好与 peer attraction 分离，这样同一局部规则可以服务 search、delivery、nest homing 等不同状态；
- swarm size 可以同时作为变量和目标，让优化器暴露“多机器人协作收益 vs 设备成本”的折中；
- 随机 swarm 仿真评价应先做 replicas 稳定性分析，避免把仿真噪声当作真实 Pareto 差异；
- 对昂贵仿真，先用 normalized parameter-space cache 做近邻复用，是比训练代理更轻量的第一层加速。
