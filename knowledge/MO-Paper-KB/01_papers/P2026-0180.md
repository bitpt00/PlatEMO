# Evolutionary Multiobjective Neural Architecture Search for Binary Neural Networks by Two-Stage Optimization

## 一句话理解

本文把 BNN 架构搜索建模为同时最小化分类错误和模型规模的多目标 NAS，并用“两阶段辅助目标环境选择”先保护尚未充分训练的大模型、再回到真实精度-规模 Pareto 搜索，以缓解 OSNAS/权重共享下的 small model trap。

## 问题与动机

- 研究问题和场景：
  - Binary neural networks (BNNs) 将权重和激活限制为 `+1/-1`，理论上可把存储降到浮点网络的约 `1/32`，并在合适硬件上用 bitwise operations 加速推理；
  - 现实部署需要多个不同参数规模和精度水平的 BNN，而不是单个最高精度模型；
  - 作者希望用 evolutionary multiobjective NAS 一次搜索出分类错误和模型规模之间的 Pareto architectures。
- 现有算法为什么不足：
  - 多数 BNN 来自对全精度网络直接量化，主要靠降低量化梯度误差提升性能，没有充分搜索 BNN 专属结构；
  - 手工轻量网络或复杂卷积结构未必适合二值化和硬件部署；
  - 普通 NAS/EA-NAS 成本高，OSNAS 权重共享能降本，但在 BNN 多目标搜索中会产生 delayed training rewards；
  - 作者指出，在 OSNAS 的早期训练中，小模型往往更快得到看似更低的验证错误，同时模型规模目标又天然偏好小模型，导致含参数较多的大模型在尚未充分训练前被淘汰，形成 small model trap。
- 本文希望解决什么：
  - 在不显著增加搜索成本的前提下，让参数化操作和较大模型在早期有充分训练机会；
  - 最终仍输出真实目标 `classification error` 与 `model size` 上的 Pareto architectures；
  - 让 CIFAR10 上搜索到的架构能迁移到 ImageNet 进行重建和训练。

## 核心理念与算法流程

- 核心理念：
  - 把 BNN NAS 看成双层优化：上层用 EA 搜索架构编码并优化 `f1` 验证错误、`f2` 模型规模；下层在权重共享超网中用 mini-batch training 更新候选架构权重；
  - small model trap 的关键不是单纯多样性不足，而是早期评价偏差和规模目标选择压力共同导致大模型过早死亡；因此先用辅助目标排序保护大模型，再在后期回到真实目标排序。
- 主要流程：
  - 初始化规模为 `M` 的架构种群，每个个体由 cell/node 编码表示；
  - 直接计算模型规模 `f2`，通过 mini-batch gradient descent 在训练集上训练候选架构；
  - 用 improved mini-batch evaluation 在验证集上估计分类错误 `f1`；
  - 通过 node-based crossover 和 bit-based mutation 生成 offspring；
  - 合并 parent/offspring 后执行两套非支配排序：
    - `F1`：按真实目标 `f1, f2` 排序，用于得到高性能小模型和最终 Pareto tradeoff；
    - `F2`：按辅助目标 `fa, fb` 排序，用于保留较大且误差相近的模型。Markdown 中公式为图片占位，正文例子显示 `fb = 1 - f2`，`fa` 按 `f1 * (1 - f2)` 计算，用于校正大模型早期误差劣势；
  - 第一阶段 `t < T/2`：主要从辅助目标排序 `F2` 中选父代，避免 small model trap，让含参数操作被充分训练；
  - 第二阶段 `t >= T/2`：从真实目标排序 `F1` 和辅助目标排序 `F2` 交替选个体，同时追求真实 Pareto 解和规模多样性；
  - 第二阶段加入 path dropout，随机屏蔽多分支操作并对未 dropout 分支按比例放大，减轻 one-shot 超网过拟合。
- 关键组成部分：
  - Binarized NAS-Bench-201 style search space：保留简洁操作并加入 `3x3 max pooling`，避免 DARTS 中复杂大卷积在 BNN 下成本高且少被选择；
  - 架构编码：normal cell 和 reduction cell 堆叠，cell 由两个输入、四个中间节点和一个输出组成；每个 node code 由四个整数表示操作和连接，整体架构用 32 个整数编码；
  - Improved mini-batch evaluation：按种群规模均分验证集，使每代验证集只遍历一次，每个个体只在一个 mini-batch 上估计 fitness；
  - Two-stage environmental selection：第一阶段辅助目标排序，第二阶段真实目标和辅助目标交替排序；
  - Path dropout：只在第二阶段加入，避免初期超网权重不稳定时进一步增加训练噪声。
- 可能被修改的位置：
  - 辅助目标形式和规模目标归一化方式；
  - 第一/第二阶段切换时间，不一定固定为 `T/2`；
  - 第二阶段 `F1/F2` 交替比例；
  - mini-batch validation 的个体分配方式，可用重复采样、uncertainty 或历史平滑降低噪声；
  - cell 重建策略，尤其是 CIFAR 搜索后迁移 ImageNet 时 normal/reduction cell 对参数量贡献不同的问题。
- 必须保留的核心：
  - 若把本文算法作为基础算法，核心不是 path dropout 或具体 BNN 操作集合，而是“早期用辅助目标抵消小模型选择偏置，后期再回到真实性能-规模目标并保留辅助排序补充多样性”的环境选择逻辑。

## 实验证据

- 测试问题和对比算法：
  - 数据集：CIFAR10 和 ImageNet；
  - CIFAR10 search：训练集按 8:2 划分训练/验证，population size 40，mutation probability 0.02，crossover probability 1，epoch/generation 300，normal cells 1，initial channels 16；
  - CIFAR10 evaluation：将搜索架构 normal cells 堆叠 3 次，initial channels 48；
  - ImageNet evaluation：迁移 CIFAR10 搜索到的架构，网络前加入三个 downsampling full-precision convolutional layers，initial channels 64；
  - 指标：分类 error/accuracy、Params 或 Mbit、BOPs、FLOPs、OPs、HV，以及搜索时间；
  - 对比对象包括人工 BNN、gradient-based binary NAS、EA-based NAS 和作者引用的 CARS-style selection。
- 主要实验结论：
  - 搜索过程在单张 NVIDIA RTX 3090 上约 0.26 天完成，并一次得到五个不同规模的 Pareto architectures；
  - CIFAR10 上模型参数约从 0.87M 到 7.82M，提供多种部署选择；Ours-D 以 3.43M 参数达到 90.85% accuracy，Ours-B 以 5.67M 参数达到 92.16% accuracy，Ours-A 达到 92.46% accuracy；
  - ImageNet 上较小网络约 17.38 Mbit、top-1 61.67%，较大网络约 23.28 Mbit、top-1 64.13%；作者认为 Ours-C 与 Bi-Real-Net-34 精度相近但参数明显更少；
  - 与许多 EA-based NAS 相比，0.26 天搜索成本较低。
- 消融或机制证据：
  - Small model trap 可视化：直接应用多目标算法会搜索出包含大量 parameterless operations 的退化 cell；本文策略搜索到的 normal/reduction cell 更合理；
  - Improved mini-batch evaluation：原验证策略时间随 population size 增大而增加，改进策略使验证集每代只遍历一次，时间基本稳定；但 population size 增大时单个个体验证 batch 变小，accuracy fluctuation 增加；
  - CARS-style reciprocal parameter objective：作者观察到保留了小模型和大模型，但缺少 medium-size models；本文两阶段策略在最终结果中保留更好的规模多样性；
  - Depth/width ablation：在 CIFAR10 重建中，提高 initial channels 比增加 normal cells 更有效，作者解释为 cell 内连接已提供一定深度；
  - Stage division ablation：`T/3` 切换虽然 HV 可好，但仍容易落入 small model trap，且模型规模多样性差；综合时间、收敛和多样性后使用 `T/2`。
- 证据边界：
  - 辅助目标、path dropout、search space、mini-batch evaluation 和 BNN training recipe 同时变化，综合结果不能全部归因于辅助目标；
  - CIFAR10 搜索迁移到 ImageNet 暴露 normal/reduction cell 参数贡献不一致问题，说明小搜索网络上的规模目标不一定等价于重建后大网络规模；
  - validation mini-batch evaluation 引入噪声，论文主要通过消融说明总体可用，但未系统建模评价不确定性；
  - 主要证据来自 BNN NAS，迁移到普通 CNN NAS、模型压缩或其他性能-资源 MOO 需要重新验证。

## 局限与未来工作

- 作者明确说明的局限：
  - CIFAR10 上 Ours-A 比 Ours-B 更大且 error 更低，但在 ImageNet 重建后模型规模关系可能反转；
  - 原因是搜索阶段只用 1 个 normal cell/reduction cell 和较小 channels，加宽加深后 normal cell 对总体规模贡献更大；若 binarized convolution 多出现在 reduction cell，重建后的规模和复杂度不会按搜索阶段预期增长；
  - 作者明确表示这种特殊情况是算法未来需要改进的地方。
- 作者未来工作：
  - 改进搜索阶段与重建阶段之间的规模一致性，使 CIFAR10 搜索出的规模 Pareto 关系更可靠地迁移到 ImageNet 或大模型重建。
- 我们认为仍需确认的问题：
  - `fa = f1 * (1 - f2)` 和 `fb = 1 - f2` 对目标归一化高度敏感，跨任务使用时需要确认 `f2` 的尺度和边界；
  - 第一阶段完全偏辅助目标是否会在某些任务中过度保留大模型，浪费训练预算；
  - 第二阶段 `F1/F2` 交替比例能否自适应，而不是固定一比一；
  - improved mini-batch evaluation 是否会因类别分布或 batch 随机性误判架构，应考虑重复验证或不确定性估计；
  - 对硬件部署而言，参数量不等于 latency、energy 或 memory peak，辅助目标可扩展到真实硬件指标。

- 结构创新线索：
  - 构建“资源潜力保护期 -> 真实 Pareto 收敛期”的通用性能-资源搜索框架，可用于 NAS、模型压缩、特征选择和硬件感知设计；
  - 把小模型陷阱建模为评价时滞问题，引入 delayed-reward compensation、multi-fidelity recheck 或 slow-start architecture archive；
  - 搜索阶段直接评估重建后规模代理，例如估计 `normal cell` 堆叠后的参数/OPs，而不是只用小搜索网络规模；
  - 将辅助目标从参数量扩展到真实 latency/energy bins，并与复杂度分组 archive 结合。
