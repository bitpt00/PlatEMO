# A hybrid evolutionary framework assisted by reinforcement learning for mixed multi-objective optimization features

## 一句话理解

论文提出 RL-MOEA：把 NSGA-II、MOEA/D-DE 和 MOEA/D-M2M 作为三个候选完整优化器，用强化学习在每个演化阶段选择当前最适合的算法，并在算法切换时用一个 diversity population 重置部分当前种群，从而处理同时包含 separable、interacting 和 imbalanced variables 的混合特征 MOP。

## 问题与动机

- 研究问题和场景：
  - 真实 MOP 往往混合多种变量结构和搜索难点，而不是只表现出单一 benchmark 特征。
  - Pareto-based、decomposition-based 和 indicator-based MOEA 在不同问题特征上各有优势，但没有一个固定框架能普适处理所有特征。
  - 需要一种 meta-framework 在搜索过程中根据种群状态动态选择更合适的优化器。
- 现有方法为什么不足：
  - NSGA-II 对 ZDT 类 separable variables 较稳，但面对变量交互和不平衡结构可能失效。
  - MOEA/D-DE 适合 interacting variables，但不一定适合 separable 或 imbalance 特征。
  - MOEA/D-M2M 对 imbalanced variables 有优势，但并不是所有阶段都应使用。
  - 固定混合或人工阶段切换难以适配不同问题和不同演化阶段。
- 本文希望解决什么：
  - 构建可扩展的算法组合框架，让 RL agent 按阶段选择候选 MOEA。
  - 设计能暴露混合特征的新测试问题 ZUM1-ZUM5。
  - 检验只在一个训练实例上训练的 DQN 是否能迁移到其他混合特征和经典 benchmark。

## 核心理念与算法流程

- 候选算法组合：
  - `a=1`：NSGA-II with SBX，侧重 separable variables。
  - `a=2`：MOEA/D-DE，侧重 interacting variables。
  - `a=3`：MOEA/D-M2M，侧重 imbalanced variables。
  - 作者指出该 action set 可扩展到更多优化器。
- 阶段式决策：
  - 总演化过程被划分为 `T = [gmax / G]` 个阶段。
  - 每隔 `G` 代选择一次 action，而不是每一代都切换。
  - training mode 中使用 `epsilon`-greedy，随机探索概率为 0.1，贪心选择概率为 0.9。
  - optimization mode 中直接使用训练好的 agent 选择 greedy action。
- 双种群维护：
  - `Pc` 是当前种群，用于生成 offspring 和执行所选 MOEA。
  - `Pd` 是 diversity population，用于在算法切换时维护多样性。
  - 从 `Pc` 中提取非支配解集合 `PN`，优先选取与 `Pd` 距离最远的解加入 `Pd`。
  - 若 `a_t != a_{t+1}`，保留 `Pc` 中最优的 `N-Nd` 个体，并用 `Pd` 中的解替换剩余个体，降低算法切换导致的多样性损失。
- MDP 设计：
  - 状态为 `(s1_t, s2_t)`。
  - `s1_t` 表示 `Pc` 中所有解的平均目标值，用于粗略刻画收敛状态。
  - `s2_t` 将 objective space 划分为 `K` 个区域，统计少于 `gamma` 个解的稀疏区域数量，用于刻画分布/多样性。
  - reward 在中间阶段为 0，终端 reward 为当前种群的 HV。
  - Q-learning 版本需要离散化 `s1`，DQN 版本可直接用状态-动作对预测 Q value。
- 训练与复用：
  - DQN 在 ZUM2、20 维实例上训练，最大 300 generations。
  - 训练后的 agent 被直接用于其他 ZUM 问题和经典 benchmark，不再重新训练。

## 新测试问题 ZUM1-ZUM5

- 设计目标：
  - 构造同时包含 separable variables、interacting variables 和 imbalanced variables 的 MOP。
  - 让单一算法只擅长其中一部分特征，从而测试动态算法选择是否有价值。
- 变量空间：
  - 前 `D1 = alpha * D` 个变量对应 ZDT-style separable part。
  - 接着 `D2 = beta * D` 个变量对应 UF-style interacting part。
  - 剩余变量对应 MOP1-MOP6 style imbalanced part。
  - ZUM1-ZUM5 的 `(alpha, beta)` 分别为 `(0.3,0.4)`、`(0.4,0.5)`、`(0.5,0.6)`、`(0.6,0.7)`、`(0.7,0.8)`。
- 参考价值：
  - 真实 PF/PS 可知，便于计算 IGD 和 HV。
  - 同一问题中混合多个特征，比单独 ZDT、UF 或 MOP family 更适合测试算法组合能力。

## 实验证据

- 论文实验直接支持：
  - RL-MOEA 在 ZUM 混合特征 benchmark 上的 IGD/HV 全面领先，支持“阶段式算法组合 + diversity population handover”能处理混合特征；
  - 经典 benchmark 结果显示策略有一定迁移能力，但并不在所有专长问题上压过对应单一算法，因此证据边界应保留。
- 基本设置：
  - 实现基于 PlatEMO。
  - 20 次独立运行，Wilcoxon rank-sum test，显著性水平 0.05。
  - 指标为 IGD 和 HV。
  - 种群规模 `N=100`。
  - `G = gmax/10`，MOEA/D 邻域规模为 `0.2N`。
  - SBX 和 polynomial mutation distribution index 均为 20；DE 参数 `F=0.5`、`CR=1.0`。
  - DQN / Q-learning 使用 learning rate `0.1`、discount factor `0.9`，多样性状态划分 `K=6`。
- 经典 benchmark：
  - 在 UF1-UF7、ZDT1-ZDT4、ZDT6 和 MOP1-MOP6 上测试。
  - RL-MOEA 在 17 个实例中 7 个获得最优 IGD。
  - 相比 MOEA/D-DE、MOEA/D-M2M 和 NSGA-II，分别在多个实例上显著更好，但并非所有标准问题都优于对应专长算法。
  - 这说明策略具有一定泛化能力，但不能理解为普适最优算法。
- ZUM 混合特征 benchmark：
  - 在 ZUM1-ZUM5 的 10 维和 20 维共 10 个实例上，RL-MOEA 获得最低平均 IGD。
  - HV 结果中 RL-MOEA 同样在全部 10 个 ZUM 实例上表现最好。
  - 收敛曲线显示 RL-MOEA 在所有 ZUM 实例上收敛最快；NSGA-II/SBX 早期可能较快，但中期后容易停滞，而 RL-MOEA 继续改善。
- Q-learning 与 DQN：
  - 两者都在 ZUM2 20 维上训练。
  - 在 ZUM 系列上二者接近，DQN 在个别训练相邻实例上不一定最好。
  - 在 17 个经典 benchmark 上，DQN 相比 Q-learning 在 9 个问题上更优、6 个相当、1 个更差，显示更好的跨问题泛化。
- `Nd` 敏感性：
  - 测试 `Nd=10,20,30,40,50`。
  - 整体性能对 `Nd` 不太敏感，但 `Nd=30` 最好，`Nd=10` 最弱。

## 复杂度与实现成本

- 在线复杂度主要由当前被选择的 MOEA 决定：
  - NSGA-II 约为 `O(MN^2)`。
  - MOEA/D-DE 约为 `O(MNT)`，其中 `T` 为邻域大小。
  - MOEA/D-M2M 约为 `O(MN^2/K)`，其中 `K` 为子种群数量。
- DQN 每步前向/训练带来额外 `O(LU^2)` 量级开销，但论文强调训练主要离线完成。
- 额外内存主要来自 replay buffer、DQN 参数和 diversity population。
- 工程实现难点在于：
  - 不同 MOEA 之间 population representation、selection 和 variation 接口需要统一。
  - action switch 时要避免过度重置导致已获得收敛性丢失。
  - 训练实例选择会影响 agent 的迁移能力。

## 局限与未来工作

- 作者明确说明的方向：
  - 将框架用于实际工程和经济问题建模。
  - 融入更多领域知识和约束处理机制。
  - 扩展候选算法集合和适用场景。
- 我们的判断/仍需确认的问题：
  - 只在 ZUM2 20 维训练，训练分布较窄；不同目标数、强约束、噪声或昂贵评价场景下泛化性未知。
  - reward 只在终端使用 HV，反馈稀疏，可能增加训练不稳定性。
  - 状态只有平均目标值和稀疏区域数，可能不足以区分复杂 PF 形状或局部 PS 结构。
  - 候选 action 只有三个完整算法，尚未证明大规模算法组合或多目标数场景下稳定。
  - ZUM 是人工混合特征，能证明压力测试价值，但不能直接等同真实工程混合难点。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建设计知识：RL 阶段式 MOEA 组合选择与多样性重置。它将 RL 控制粒度从“选择算子/参数”提升到“选择完整 MOEA 框架”，并用 diversity population 处理算法切换带来的分布断裂。
- 暂留在论文卡中的方法、原理或架构启发：
  - 训练算法选择策略时，可用人工混合特征 benchmark 作为 curriculum，而不必直接在所有真实问题上训练。
  - Action switch 不只是换算子，也需要同步设计 population handover 机制。
  - 泛化测试应同时报告专长 benchmark 和混合特征 benchmark，避免只证明 agent 记住训练场景。
- 局部创新线索：
  - 将 action 扩展为 `MOEA + constraint handling + archive policy` 的组合。
  - 用在线 bandit 或 meta-learning 替代完全离线 DQN，适应新问题。
  - 把 ZUM 类混合特征参数随机化，用作 RL-MOEA 的训练分布而不是单一训练实例。
  - 在状态中加入参考向量覆盖、约束可行比例、变量交互估计或 operator success statistics。
