# Multiparty Multiobjective Optimization for Discrete Problems: A Case Study on Multistakeholder Recommendation

## 一句话理解

本文面向离散 multiparty multiobjective optimization，用一个 multiparty population 搜索多方共同解、多个 single-party populations 分别强化各方目标，再通过早期子代共享、后期父代共享和离散双搜索机制，在多利益方推荐任务中取得更好的共同非支配解。

## 问题与动机

- 研究问题和场景：MPMOP 中多个 decision makers 只关心各自的一组目标，目标之间既有协作也有竞争；本文关注离散编码问题，并以 multistakeholder recommendation 作为案例。
- 现有算法为什么不足：已有 MPMOEA 多面向连续问题，且多数用单种群直接搜索共同 Pareto 解；这忽略了 multiparty optimization 与 single-party optimization 的联系，也难以适应不同 DM 的偏好差异。
- 本文希望解决什么：构造 multiparty population 与 single-party populations 的协同框架，让单方目标搜索为共同解搜索持续提供信息，同时避免过早强交叉造成负迁移。

## 核心理念与算法流程

- 核心理念：多方共同优解往往位于各单方 Pareto 搜索的信息交汇处；早期应让单方子代参与 multiparty 环境选择以扩大探索，后期再让单方优秀父代与 multiparty 父代交叉以增强局部开发。
- 主要流程：
  1. 初始化一个 `MP` 种群和多个 `SP_i` 种群，本文二方示例中 `MP` 规模为 `N`，两个 `SP_i` 规模为 `N/2`；
  2. 弱合作阶段：`MP` 与 `SP_i` 各自产生子代，`MP` 环境选择时合并 `MP, OP, OP_1, OP_2`，`SP_i` 环境选择时合并 `SP_i, OP_i, OP`；
  3. 根据单方子代在 `MP` 中的 survival rate 和参数 `beta` 判断弱合作是否仍有效；
  4. 强合作阶段：按 `MP` 与 `SP_i` 在单方目标上的 success rate 动态确定互换父代数量，允许跨种群父代参与交叉；
  5. 对 `MP` 执行 dual-search：若 elite-guided search 能增加 Pareto optimal 个体，则保留；否则对 suboptimal 个体执行 self-perturbation search；
  6. 终止后从 `MP` 输出 common nondominated solutions。
- 关键组成部分：multiparty/single-party 多种群结构、weak cooperation、strong cooperation、弱强切换条件、elite-guided search、self-perturbation search、multistakeholder recommendation matrix encoding。
- 可能被修改的位置：离散 MPMOEA 的种群组织、跨种群迁移/交叉、子代生成、推荐/组合编码的局部搜索。
- 必须保留的核心：`MP` 负责共同目标，`SP_i` 负责单方目标；早期只共享 offspring，后期共享 parents；强合作转入不能只靠固定代数，需由弱合作成功度触发。

## 实验证据

- 测试问题和对比算法：六个 Movielens/Netflix 子数据集；对比 NSGA-II、MOEA/D、SMS-EMOA、OptMPNDS3、MOEA/D-MP、SMS-MPEMOA，并设计七个 MP-HCEA 变体用于消融。
- 主要实验结论：Fig. 5 中 MP-HCEA 在六个数据集上得到的共同非支配解优于六个 baseline；Table VI 报告 MP-HCEA 在所有数据集上取得最佳 meanHV。
- 消融或机制证据：主文给出 `beta` 参数分析，`beta=0` 或 `beta=1` 均较差，说明双阶段合作有必要；`beta=0.2` 平均较好，作者解释为离散稀疏、大规模搜索空间中应给弱合作更多代数。七个变体的详细结果在补充材料。
- 证据边界：Table VI、VII 为图片占位，主文 Markdown 无精确数值；MPIGD 和七个变体结果主要放在补充材料，本地卡片未补读补充文件；provider-item 关系由随机分配生成，推荐应用的现实约束证据有限。

## 局限与未来工作

- 作者明确说明的局限：MP-HCEA 已在 MPMOP 上有效，但仍有约束复杂性和动态需求变化场景未处理。
- 作者未来工作：扩展到 constrained MPMOPs，以及处理不同 DMs 需求随时间变化的 dynamic MPMOPs。
- 我们认为仍需确认的问题：强合作父代互换在更多方、多目标更高维时是否导致过强同质化；`beta=0.2` 是否只适合推荐数据；随机 provider 赋值可能弱化真实平台的供给侧结构；离散推荐矩阵编码如何加入去重、业务规则和公平约束。
