# A Multi-Objective Genetic Algorithm for Large-Scale Integrated Berth Allocation and Quay Crane Assignment Problem With Maintenance Activities

## 一句话理解

本文把集装箱码头的连续泊位分配、岸桥指派和岸桥预防性维护放进同一个双目标模型，并提出 RTAA：染色体只编码船舶优先级、岸桥层级权重、泊位位置和维护计划，评价时按时间步递归执行 berth allocation 与 crane assignment，再用岛模型、farthest candidate 和约束支配原则提升大规模可行搜索和 Pareto 多样性。

## 问题与动机

- 研究问题和场景：
  - 港口需要同时决定船舶停靠位置、服务开始时间、每个时间步哪些岸桥服务哪些船，以及岸桥维护开始时间和维护泊位；
  - 岸桥沿同一轨道移动，覆盖范围有限，且不能真实交叉；
  - 维护活动会占用岸桥和泊位区间，维护时间窗是软约束，提前或推迟都会产生 penalty；
  - 目标是最小化船舶总 turnaround time 与 unscheduled maintenance penalty。
- 现有方法为什么不足：
  - 先解 BAP 再解 QCAP 会割裂 berth decision 与 crane availability，容易得到次优或不可行调度；
  - 既有维护模型常使用硬时间窗或固定维护位置，缺少对维护提前/推迟的多目标决策支持；
  - ε-TPIH 等方法先估计平均岸桥数量再排泊位，无法处理同一时间多船竞争岸桥导致的完成时间推迟；
  - 直接编码 start time、berth、crane assignment 的搜索空间巨大，约束违反比例高；
  - 普通 NSGA-II 的 crowding distance 和单种群搜索在大规模强约束调度中收敛慢且多样性不足。
- 本文希望解决什么：
  - 为带维护的 BACAP 建立 mixed integer bi-objective model；
  - 通过启发式时间步解码减少不可行个体；
  - 在 NSGA-II 中结合 farthest candidate、island model 和 CDP，提升多样性、并行性和可行搜索效率；
  - 在 100 vessels、40 berth segments、40 quay cranes 等大规模场景下仍能输出多样 Pareto 解。

## 核心理念与算法流程

- 核心理念：
  - 不直接演化完整时空分配矩阵，而是演化会驱动解码器的关键优先级和位置变量；
  - 每个个体用一个 recurrent temporal decoder 从 `t=1` 到 `T` 逐步构造可行调度；
  - temporal berth allocation 决定哪些已到达船舶能进入空泊位区间；
  - temporal crane assignment 根据 coverage、当前工作船舶和 hierarchy function 动态分配岸桥；
  - 维护活动把连续泊位/岸桥轨道切分成若干独立子区间，从而用 divide-and-conquer 处理维护导致的不可交叉约束。
- 双目标模型：
  - 目标 1：最小化所有船舶的总 turnaround time；
  - 目标 2：最小化岸桥维护提前或推迟的 penalty；
  - 关键约束包括服务开始/结束边界、泊位边界、船舶泊位区间不重叠、每台岸桥每个时刻至多服务一艘船、船舶累计获得的岸桥服务量满足 workload、岸桥覆盖范围与船舶泊位相交、岸桥不交叉、维护区间与船舶/其他维护不冲突。
- RTAA 染色体：
  - `EV_i[priority]`：决定已到达船舶尝试分配泊位的顺序；
  - `EV_i[hierarchy]`：参与动态计算船舶获得岸桥服务的权重；
  - `EV_i[berth]`：船舶目标泊位左端；
  - `EQM_k[start]`：维护实际开始时间；
  - `EQM_k[berth]`：维护占用泊位区间。
- 时间步解码：
  - 维护信息先更新：开始维护的岸桥进入维护集合，结束维护的岸桥移除；如果维护泊位被船舶占用，则个体不可行；
  - 已到达但未开始服务的船舶进入 arriving set；
  - 按 priority 排序尝试泊位分配，目标泊位区间完全空闲才进入 working set；
  - 对每个时间步内的 working vessels，根据岸桥覆盖范围和 hierarchy function 逐台分配岸桥；
  - 船舶累计获得足够岸桥服务量后记录 finish time 并从 working set 移除；
  - 所有时间步结束后计算两个目标，若调度失败则返回不可行 fitness。
- 维护下的 divide-and-conquer：
  - 无维护时，作者证明计算上出现的岸桥交叉可通过交换服务船舶消除；
  - 有维护时，维护岸桥在固定泊位占用轨道，会阻断左右两侧岸桥交换；
  - 因此每个时间步按维护泊位把 berth interval 切分为若干子区间，并在各子区间内按无维护版本执行 temporal allocation/assignment。
- NSGA-II 改造：
  - farthest candidate approach 替代 crowding distance，在同一前沿中每次选择离已选点最远的候选，改善 PF spread；
  - island model 把种群分成多个子种群独立进化，通过迁移 best individuals、移除 worst individuals 保持多样性并支持并行；
  - CDP 用可行性优先、不可行时比较 constraint violation、都可行时按 Pareto dominance 的规则处理约束；
  - 交叉和变异作用在 priority、hierarchy、berth 和 maintenance 编码变量上。
- 必须保留的核心：
  - RTAA 的可复用部分不是“NSGA-II + island”本身，而是“低维优先级/位置编码 -> 时间步递归资源解码 -> 维护/不可用资源切分子问题 -> 约束支配与多样性选择”的组合。

## 实验证据

- 数据与设置：
  - 真实数据来自中国某集装箱码头，包含 22 vessels、12 quay cranes、12 berth segments；维护岸桥数 `|QM|=3`，维护可占用泊位长度 `P=3`；
  - 另生成 300 个不同规模实例，规模从 `(10,6,6)` 到 `(100,40,40)`，三元组表示 vessels、berth length、quay cranes；
  - 每组中维护岸桥数取 `{2,3,4}`，维护泊位长度取 `{1,3}`，每个规模生成 5 个数据集；
  - RTAA 使用 C++，Intel Core i7 3.00GHz、8GB RAM；population size 20，islands 8，maximum generations 300，HV 50 代不变早停；
  - crossover rate 0.9，mutation rate 0.1；ε-TPIH 的 step length `δ=1`；unmodified NSGA-II 使用相同参数但 1800 generations 且无早停。
- 真实数据结果：
  - ε-TPIH 生成的 Pareto front 比普通 NSGA-II 更多样，但 RTAA 在多样性和目标值上更好；
  - 普通 NSGA-II 的 PF 只有两个点，且 HV 收敛慢、随机种子敏感；
  - 作者将差距归因于直接编码产生大量不可行染色体，而 RTAA 解码能显著减少不可行解。
- 小规模实例：
  - RTAA 相对 ε-TPIH 的 HV 差值全部为正；
  - 平均 HV 提升为 8218.38；
  - 平均 `epsilon` 为 0.71，平均 `C` 值为 0.99，说明 RTAA 解集几乎覆盖/支配 ε-TPIH 解集。
- 大规模实例：
  - 从 `(20,10,10)` 到 `(100,40,40)`，RTAA 平均 HV 比 TPIH 高 7703.3；
  - 8 核并行下，平均计算时间从 818.5 秒降到 150.5 秒，约 82% reduction；
  - RTAA 在所有大规模实例中成功生成可行解，而 TPIH 在维护复杂度更高的配置中多次无法在时限内生成可行解；
  - 在 `(100,40,40)` 配置中，RTAA 在不同维护岸桥数下仍保持稳定，TPIH 多数实例无法完成。
- 与通用调度算法比较：
  - 与 FIFS 相比，RTAA 在 `(12,6,6)` 仅提升约 2.6%，但在 `(80,30,30)` 和 `(100,40,40)` 分别提升 52.5% 和 58.8%，平均提升 45.2%；
  - 与 I2HCSO 相比，RTAA 在作者设定下平均提升 73.9%；
  - 但作者明确说明 I2HCSO 原论文使用 berth length 3000，而本文设置 `B <= 40`，大 berth length 会对 RTAA 搜索空间造成更大挑战。
- 消融与敏感性：
  - farthest candidate 平均 HV 为 31135.5，比 crowding distance 版本高 1384.6，平均运行时间少 11.0 秒；
  - 去掉 island model 后，随着数据规模增大性能差距加大，说明并行子种群对速度和多样性关键；
  - 用 `EV[start]` 替代 `EV[priority]` 的方案劣于 priority encoding；
  - 三种 hierarchy function 中，带平方根的 `phi_3` 平均 HV 3617.2，优于 `phi_1` 的 3586.7 和 `phi_2` 的 3589.2；
  - 参数敏感性显示 `Pc=0.9`、`Pm=0.1` 表现最好，低 mutation rate `Pm=0.01` 因多样性不足 HV 明显更差。
- 证据边界：
  - 表格细节在 Markdown 中为图片占位，精确逐实例数据需回查 PDF；
  - I2HCSO 比较不完全同分布，作者自己说明 berth length 设置不同；
  - RTAA 假设岸桥移动不耗时，且岸桥每个时间步末可换到另一船，即使当前船未完成；
  - 船舶到达和维护时间被视为确定性。

## 局限与未来工作

- 作者明确说明的局限：
  - 船舶到达时间和岸桥维护时间被假设为 deterministic，现实中可能随机或不确定；
  - 岸桥可在每个时间步末移动到其他位置服务其他船，且不计移动时间，这可能限制现实适用性。
- 作者未来工作：
  - 加入 vessel arrivals 与 maintenance schedules 的 uncertainty；
  - 使用 stochastic 或 robust optimization；
  - 增加岸桥能耗、船舶优先级、环境和可持续性目标。
- 我们认为仍需确认的问题：
  - 时间步粒度如何影响可行性、计算成本和真实调度精度；
  - 维护活动若有人员、备件或安全区资源约束，简单 berth interval 切分是否足够；
  - farthest candidate 在高维目标或大量近似重复解中是否稳定；
  - 岛模型迁移频率、迁移规模和并行开销对性能的敏感性；
  - `B <= 40` 的离散泊位单位能否覆盖更长连续泊位或更细空间粒度。

  - soft maintenance penalty 是应用模型组件，先不单独建维护调度卡。
- 局部创新线索：
  - 把 hierarchy function 改为 learned dispatching score，输入 vessel workload、remaining work、等待时间、priority 和 crane coverage；
  - 将维护切分从硬分区扩展为安全区/通行时间/移动成本约束；
  - 用 adaptive island migration，根据各 island 的 HV contribution 或 feasibility rate 调整迁移；
  - 将 farthest candidate 与 constraint violation diversity 结合，避免只在目标空间分散而约束结构相似。
- 结构创新线索：
  - 构建“低维优先级编码 + 时间步仿真解码 + 子区间分解 + Pareto island search”的通用资源调度框架；
  - 可迁移到机场机位-登机桥-维修、仓储 dock-door 与装卸设备、制造产线设备维护、医院床位/设备分配等场景；
  - 与 robust optimization 结合：对多个 arrival/maintenance scenario 执行时间步解码，目标改为期望/风险/最坏情形 Pareto。
