# Stable and efficient rescheduling for flight task testing with multi-objective consideration

## 一句话理解

本文面向民机飞行试验中的动态任务重调度，把稳定性定义为任务-飞机分配偏差和任务顺序偏差，把效率定义为飞机完成时间；用 RMAJ-LR 只滚动调整受扰动影响的多个局部区域，再用 MOEA-MSOS 的问题驱动多阶段算子生成 Pareto 重调度方案。

## 问题与动机

- 研究问题和场景：Dynamic Flight Test Task Scheduling (DFTTS)，需要把带前序约束、可执行飞机集合和制造完成时间约束的试验任务分配到多架试飞飞机上，并在扰动后重新安排任务。来源：Sec. 3.1，PDF 4。
- 动态事件：aircraft malfunctions、new task insertions、task re-executions；故障会中断正在执行任务并要求返工，新任务会插入计划，返工任务还会使依赖它的后续任务重新执行。来源：Sec. 3.2，PDF 4。
- 多目标定义：
  - Task-Aircraft Deviation (TAD)：衡量重调度后任务-飞机分配变化；
  - Task Order Deviation (TOD)：衡量同一飞机上任务相对顺序变化；
  - Aircraft Completion Time (ACT)：衡量所有飞机完成试验任务的总完成时间。
  - TAD/TOD 表示 stability，ACT 表示 efficiency，三者用 Pareto 方式优化而不是固定加权。来源：Sec. 3.3，PDF 4。
- 现有方法为什么不足：
  - Right Shift Rescheduling (RSR) 保持稳定但牺牲效率；
  - Complete Rescheduling (CR) 重新优化全部未完成任务，效率可能好但扰动大、计算成本高；
  - Local Rescheduling (LR) 只调整局部任务，计算较快但影响范围难定，单一区域缺少跨区域协调；
  - 既有 DFTTS 工作缺少显式稳定性指标，容易产生大量 task-aircraft reassignment 或 sequence changes。来源：Sec. 1、Sec. 2、Sec. 4。
- 本文希望解决什么：在多类动态事件下，既限制不必要的计划变动，又避免过小局部窗口导致效率下降；同时用问题驱动 MOEA 提升三目标 Pareto 解质量。

## 核心理念与算法流程

- 核心理念：把重调度空间分成固定不动、需要优化、只右移三类区域。通过依赖关系触发最小必要扩张，让 middle area 逐步覆盖真正受影响的任务；再并行/顺序求多个不同大小的 middle area，把不同稳定-效率折中合并成 Pareto 方案。
- RMAJ-LR 流程：
  1. Area Division (AD)：先按 rolling window 划分 executed、executing、unexecuted tasks；再用 Task Activation 把未执行任务分为 activated/non-activated；结合动态事件，把已稳定任务列为 LATs，受影响和可立即处理任务列为 MATs，未激活后续任务列为 RATs。来源：Sec. 4.1-4.2。
  2. Area Expansion (AE)：当当前 MATs 太小会限制可行/有效优化时，按原计划完成时间顺序假设一个后续任务进入 LATs，并通过 Task Activation 把新激活后继加入 MATs，同时从 RATs 删除；扩张目标是最小必要扩张，不是尽量扩大范围。来源：Sec. 4.3、Algorithm 1。
  3. Multi-Area Joint Search Strategy (MAJSS)：构造多个 Single Area (SA)，每个 SA 在当前 MATs 大小上求解；把多个 SA 的解集合并并选择最佳非支配重调度集。来源：Sec. 4.4、Algorithm 2。
  4. 参数含义：`x` 为生成的 SA 数量，`y` 为每个 SA 求解前的扩张次数，`z` 为每个 SA 的优化迭代数；`x=1` 时退化为 SA/LR，`x>1` 时为 MA/RMAJ-LR，`y -> infinity` 接近 CR，`y=0` 接近 RSR。来源：Sec. 4.4。
- MOEA-MSOS 流程：
  1. 用随机 task-sequence chromosome 初始化，再通过 decoding 转换为多 aircraft chromosome segments，以满足任务可执行飞机和优先约束。来源：Sec. 5.1、Algorithm 3-4。
  2. Crossover：对 aircraft segments 成对交换任务，先检查任务-飞机可执行约束，只在可行候选中交换。来源：Sec. 5.2。
  3. Mutation：随机确定 segment transfer direction，把每个 segment 中可转移任务沿路径移动到下一 segment，以探索任务-飞机分配变化。来源：Sec. 5.2。
  4. Selection：非支配排序和 crowding distance 的 elitism 保留高质量个体。来源：Sec. 5.2。
  5. Multi-stage strategies：AGS 在解码时优先分配给最早可用飞机以优化 ACT；TRAS 在 crossover 中优先让任务回到原飞机以降低 TAD；TORS 按原计划 start time 对 segment 内任务重排序以降低 TOD。来源：Sec. 5.3。
- 关键组成部分：
  - LAT/MAT/RAT 三分区；
  - dependency-driven minimal area expansion；
  - multi-area solution integration；
  - TAD/TOD/ACT 三目标显式建模；
  - task-to-aircraft chromosome segmentation；
  - AGS/TRAS/TORS 三个目标对齐的阶段式算子。
- 可能被修改的位置：
  - AD/AE 中的任务激活规则可替换为关键路径、冲突传播图、资源 slack 或仿真敏感度；
  - MAJSS 的 `x,y,z` 可由在线 budget、扰动严重度或风险等级自适应设定；
  - `area_solve` 可替换为 NSGA-II、MIP、CP-SAT、ALNS、LNS 或代理辅助 MOEA；
  - AGS/TRAS/TORS 可扩展到 crew、fuel、weather window、test combinability 等领域约束；
  - selection 可加入决策者偏好或稳定性阈值，输出更易执行的少量方案。
- 必须保留的核心：稳定/效率分目标建模、LAT/MAT/RAT 区域语义、依赖驱动的最小扩张、多区域解集合并。若只做 CR 或单一区域 LR，就失去本文通过区域尺度覆盖稳定-效率折中的核心；若只保留 MOEA 算子而不保留 RMAJ-LR，计算成本和计划扰动控制会弱很多。

## 实验证据

- 测试设置：
  - 所有实验独立运行 20 次；硬件为 AMD Ryzen 5 5600H、16 GB RAM、Windows 11；Python 3.11 实现；Wilcoxon signed-rank test 显著性水平 `alpha=0.05`。来源：Sec. 6。
  - 主实验基线为 80 个 flight tasks；MOEA-MSOS 参数为 population size 50、crossover probability 0.7、mutation probability 0.5、100 iterations。来源：Sec. 6.2。
  - 指标为 HV、IGD、SP 和 average Pareto front；HV/IGD 评估 convergence，SP 评估 distribution uniformity。来源：Sec. 6.1。
- RMAJ-LR 与重调度策略对比：
  - RSR 得到 `TAD=0`、`TOD=0`，但 `ACT=1538.00`，说明稳定但效率差。来源：Table 2。
  - CR 的 `HV=8.97e-01`、`IGD=4.20e-03`、`SP=2.55e-02`、time `31.70s`；RMAJ-LR MA1 的 `HV=9.76e-01`、`IGD=1.31e-03`、`SP=1.00e-02`、time `24.23s`，同时 `ACT=1495.72`、`TAD=2.84`、`TOD=2.20`。来源：Table 2。
  - MA1-MA4 在 HV/IGD/SP 上总体优于 CR，且计算时间低于 CR；Gantt 和 Pareto front 显示 RMAJ-LR dominates CR。来源：Sec. 6.2.1、Fig. 7-8。
  - RWDHR-H1/H2/H3 计算很快但性能显著低于 CR 和 RMAJ-LR，说明仅靠 rolling heuristic 不足。来源：Sec. 6.2.1、Algorithm 5。
- MAJSS 机制证据：
  - MA4 即便是 MAs 中表现较弱者，仍在 solution convergence 上优于所有 SAs；其他 MAs 也优于 SAs，说明多区域联合搜索有效。来源：Sec. 6.2.2、Table 3。
  - 随 `x*y` 增大，solution convergence 和 diversity 逐渐变差，因为 RMAJ-LR 行为越来越接近 CR。来源：Sec. 6.2.2。
  - SA 任务数从 7 增到 65 时，时间从 `21.43s` 增至 `31.70s`，说明搜索区域大小直接驱动计算成本。来源：Table 4。
- MOEA-MSOS 与算法对比：
  - 对比算法为 MODE、NSGA-II、NSGA-III；总 function evaluations 统一为 18,000。来源：Sec. 6.3.1。
  - 平均单次 runtime：MODE `18.34s`、NSGA-II `17.89s`、NSGA-III `18.47s`、MOEA-MSOS `31.70s`，MOEA-MSOS 更贵但解质量更好。来源：Sec. 6.3.1。
  - 在 CR/SA6 下，MOEA-MSOS HV 为 `8.97e-01`，NSGA-II/NSGA-III/MODE 分别为 `4.05e-01/3.93e-01/3.59e-01`；IGD 为 `4.20e-03`，显著优于三种对比算法。来源：Table 5-6。
  - 在 MA1-MA4 下，MOEA-MSOS 在 HV 和 IGD 上整体优于对比算法；SP 优势不总显著，作者认为 RMAJ-LR 本身带来了搜索多样性。来源：Sec. 6.3.1、Table 5-7。
- 消融证据：
  - 移除 AGS、TRAS 或 TORS 都会使 HV/IGD 变差：完整 MOEA-MSOS `HV=8.97e-01`，no AGS/no TRAS/no TORS 为 `8.52e-01/7.85e-01/8.28e-01`；IGD 从 `4.20e-03` 变为 `7.45e-03/2.53e-02/2.56e-02`。来源：Table 8。
  - 无 AGS 时早期 ACT 明显较差；无 TRAS/TORS 时 TAD/TOD 收敛更慢。来源：Sec. 6.3.2、Fig. 16。
  - MOEA-MSOS 中 TAD 和 TOD 呈显著正相关，RMAJ-LR 加入后所有算法中 TAD/TOD 也呈正相关，说明恢复飞机分配和恢复顺序可协同改善。来源：Sec. 6.4、Table 9。
- 多扰动和大规模验证：
  - 新任务插入场景中，CR `HV=7.42e-01`、time `31.30s`；RMAJ-LR MA1 `HV=9.51e-01`、time `23.45s`，且 TAD/TOD/ACT 更低。来源：Table 11。
  - 任务返工场景中，CR `TAD=6.89`、`TOD=6.07`、`ACT=1492.70`；RMAJ-LR 各 MA 的 TAD/TOD 明显更低且 ACT 约 `1477-1482`。来源：Table 12。
  - 三类事件同时发生时，CR `HV=7.26e-01`、`IGD=3.51e-02`、time `32.89s`；RMAJ-LR MA1/MA3 的 HV 约 `9.05e-01/9.04e-01`，time 约 `25.66/25.54s`。来源：Table 13。
  - 真实大规模 case 包含 581 tasks 和 5 test aircraft；CR time `1732.50s`，RMAJ-LR 多个 MA 的 time 为 `1022.74-1398.92s`，并在 HV/IGD 上优于 CR；作者指出扩大配置下仍可节省约 `429/333s`。来源：Sec. 6.5.2、Table 14。
- 证据边界：
  - MOEA-MSOS 运行时间高于 NSGA-II/NSGA-III/MODE；
  - SP 多样性优势在 MAs 中不总显著；
  - 真实大规模 case 由于计算负担只运行 10 次；
  - 部分参数灵敏度和真实任务细节在 Supplementary Materials 中。

## 局限与未来工作

- 作者明确说明的局限：
  - 当前模型未包含 task time windows、task combinability、aircraft load、fuel consumption、crew availability 等实际约束。
  - 只关注三类典型动态扰动，真实飞行试验还可能存在更复杂和更不确定事件。
  - 大规模场景下计算时间显著增加，MOEA population evaluation 和多目标 selection 会带来较高开销。
- 作者未来工作：
  - 扩展建模框架以覆盖更丰富 operational constraints 和 uncertainty sources；
  - 开发更 adaptive 和 computationally efficient 的 rescheduling strategies。
- 我们认为仍需确认的问题：
  - `x,y,z` 参数如何在不同扰动强度和实时算力预算下自动设定；
  - TAD/TOD 是否充分代表真实协调成本，是否需要加入 crew、机场、天气窗口和安全审查代价；
  - RMAJ-LR 在连续多次扰动下是否会累计偏离基线；
  - Pareto 解如何交给试飞调度员快速选择和解释；
  - 大规模 case 仅 10 次运行是否足以支撑稳定性结论。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建“滚动多区域稳定保持重调度”：抽象为 LAT/MAT/RAT 区域划分、依赖驱动最小扩张、多区域联合搜索、稳定性-效率三目标和阶段式恢复算子。
- 暂留在论文卡中的方法、原理或架构启发：
  - 用 `y=0 -> RSR`、`y -> infinity -> CR` 解释区域扩张参数的策略连续谱；
  - 把不同 MATs 规模的 SA 解集合并，可自然形成稳定性和效率的 Pareto 折中；
  - 将每个目标绑定到一个领域算子：AGS 对 ACT，TRAS 对 TAD，TORS 对 TOD；
  - RMAJ-LR 可作为 strategy wrapper，内部 `area_solve` 可替换为不同优化器。
- 局部创新线索：
  - 根据扰动严重度、关键路径 slack 或预计收益自适应选择 `x,y,z`；
  - 用 LNS/CP-SAT 求解 MATs，用 MOEA 只做跨区域解集选择；
  - 对 TAD/TOD 加入任务重要度、试验团队切换成本或安全风险权重；
  - 让调度员通过 aspiration/reservation levels 交互式选择 Pareto 方案；
  - 用在线学习预测某次 AE 是否值得执行，减少无效扩张。
- 结构创新线索：
  - “固定左区 + 优化中区 + 右移右区 + 多尺度中区合并”可迁移到制造重调度、机场地服、卫星任务、维修排程和应急资源调度；
  - 可与“故障子问题辅助的双种群协同重调度”结合：RMAJ-LR 定义多个 MATs，辅助种群分别在每个 MATs 上局部修复，主种群做全局 Pareto 汇总。
