# LightMix: Multi-Objective Search for Lightweight Mixed-Scale Convolutional Neural Networks

## 一句话理解

面向轻量 CNN 的精度-复杂度双目标架构搜索，论文把可搜索的 LightMix 混合尺度卷积块、NASWOT 零成本性能估计和按复杂度子空间分组的环境选择结合起来，避免搜索只偏向过低复杂度架构。

## 问题与动机

- 研究问题和场景：在资源受限设备上部署 CNN，需要同时优化预测精度和模型复杂度，论文主要使用 `#Params`、`#MAdds/#FLOPs` 与分类错误率的折中来表达轻量架构搜索问题。
- 现有算法为什么不足：
  - 作者认为 DW-Sep convolution 虽能降低参数量和计算量，但空间维与通道维信息流被解耦，模型表达能力和性能会下降。
  - MixConv 强化了多尺度空间特征，但主要处理空间侧；ShuffleNet 强化通道交互，但主要处理通道侧；MUXConv 同时考虑空间与通道信息复用，但子/超像素操作固定且单一卷积操作不一定能灵活捕获合适空间信息。
  - 既有多目标 NAS 可用 Pareto dominance 同时考虑准确率和复杂度，但复杂度目标更容易优化，算法容易通过删层、降通道数来过度优化低复杂度，忽略高性能架构区域。
  - EMPCNAS 的 performance-preferred selection 能部分缓解难度失衡，但作者认为其超参数强任务相关且敏感。
- 本文希望解决什么：
  - 设计一个更紧凑且表达力更强的轻量 CNN building block；
  - 用训练-free 的多目标 NAS 快速搜索 LightMix-based CNN；
  - 在环境选择中保护不同复杂度区间内的潜力架构，使最终 archive 保留更宽复杂度尺度上的高质量候选。

## 核心理念与算法流程

- 核心理念：不要只把轻量化交给 DW-Sep 或单一复杂度压缩，而是在 block 层同时增强多尺度空间融合和通道信息流；在 NAS 层用零成本 proxy 降低评价成本，并用复杂度子空间内独立排序抵消“低复杂度更容易”的搜索偏置。
- 主要流程：
  1. 构建 LightMix block 搜索空间，每个 block 编码 split ratio `s`、expansion rate `e`、filter scaling factor、SE attention ratio 和 kernel-size combination。
  2. 随机采样初始架构种群，评价复杂度目标和 NASWOT 分数；目标为最小化架构复杂度以及 `-NASWOT`。
  3. 按复杂度阈值把目标空间划分为多个子空间，初始种群在各子空间内取非支配架构形成 archive。
  4. 每代通过二元锦标赛选择、multi-point crossover 和 mutation 生成 offspring。
  5. 将 offspring 与上一代 archive 投影到复杂度子空间，在每个子空间内分别做非支配保留，更新无容量限制 archive。
  6. 根据 archive 大小选择下一代种群；若 archive 太大，则先保留全局非支配架构，再用锦标赛补足；若不足，则对 `A_{g-1} ∪ Q_g` 排序补足。
  7. 搜索结束后，从 archive 的前四个复杂度组中分别选择 `f2` 最小的架构，命名为 LightMixNet-1 到 LightMixNet-4，并进行完整训练验证。
- 关键组成部分：
  - LightMix block：两分支混合尺度深度卷积、identity feature reuse、外部 channel division 与 channel shuffle。
  - NASWOT：在未训练网络上通过激活状态 Hamming distance 构造 kernel matrix，使用 `log |K_H|` 作为表达力 proxy。
  - Population grouping：沿复杂度目标划分子空间，允许局部子空间内有潜力但全局被支配的架构进入 archive。
- 可能被修改的位置：
  - 复杂度划分阈值可换成自适应分位数、目标预算或硬件 latency 桶；
  - NASWOT 可换成其他 zero-cost proxy、短训 proxy 或多 proxy ensemble；
  - LightMix block 可替换为任务特定结构块，保留“结构搜索 + 复杂度分组选择”的 NAS 控制层。
- 必须保留的核心：
  - 同时评价性能 proxy 与复杂度；
  - 环境选择不能只看全局 Pareto dominance，而要在复杂度分段内独立保留潜力架构；
  - 若用于轻量 CNN，LightMix 的多尺度融合、channel division 和 shuffle 共同构成主要结构贡献。

## 实验证据

- 测试问题和对比算法：
  - 数据集为 CIFAR-10、CIFAR-100 和 ImageNet；
  - CIFAR 搜索空间为三阶段、最多 30 个 LightMix blocks；ImageNet 为五阶段、最多 24 个 blocks；
  - CIFAR 使用 `#Params` 分组阈值 `[0.5M, 1M, 1.5M, 2M]`，ImageNet 使用 `#MAdds` 阈值 `[200M, 300M, 400M, 500M]`；
  - 种群大小 `T=40`、代数 `G=40`、NASWOT mini-batch size 为 128、crossover probability 为 0.8、mutation probability 为 0.2。
- 主要实验结论：
  - CIFAR-10 搜索成本为 0.02 GPU days，报告最优 LightMixNet 达到 `2.52%` test error 和 `1.78M` 参数；
  - CIFAR-100 报告 `17.19%` test error 和 `1.81M` 参数；
  - ImageNet 上，直接搜索 0.3 GPU days 得到的架构达到 `22.1%` Top-1 error、`4.8M` 参数和 `488M` MAdds；
  - 作者认为 LightMixNets 在 CIFAR 和 ImageNet 上相对大量手工/自动轻量模型取得更好的精度-复杂度折中，且搜索成本很低。
- 消融或机制证据：
  - Evolutionary trajectory 显示 archive 的 trade-off curve 随代数推进而改进，早期非支配分布有限，后续分布多样性增加；作者将其主要归因于 population grouping。
  - 搜索架构分析显示更高复杂度的 LightMixNet 使用更多 blocks，轻量架构倾向减少后期 stage blocks；多数 block 使用两个以上 kernel size，支持 mixed-scale module 的使用价值。
  - Training-free proxy 对比中，DARTS+NASWOT 也能低成本搜索，但架构明显更大；作者认为 LightMix block 与多目标搜索空间共同决定了更轻的架构。
  - 与 EPCNAS 的低保真或 MeCo 替代相比，NASWOT 具有很高效率；MeCo 搜到的架构 MAdds 更低但准确率略低，说明不同 proxy 会对复杂度产生不同偏置。
  - Dynamic mixed-scale module vs. MBConv：把 LightMixNet-4 中 mixed-scale module 替换为 MBConv 后，单一大 kernel 可提升表达力但增加参数；LightMixNet 比最大 kernel 变体 test error 低 `0.3%` 且参数少 `0.08M`。
  - Channel division 消融：移除外部 channel division 后四个变体参数分别增加，带 channel division 的架构参数减少 `32%/38%/42%/36%`，MAdds 减少 `16%/17%/16%/20%`；后两个复杂度较高场景下，带 division 的更轻架构反而性能更好。
  - Population grouping 消融：不分组时最终 archive 只保存全局非支配解，搜索偏向低复杂度区域，最终没有 `#Params > 1.1M` 的架构；分组后能探索更高复杂度区域，并在 `0.5M <= #Params <= 1.0M` 重叠区域发现更优架构。
- 证据边界：
  - Markdown 中核心表格多为图片占位，精确逐项对比数值需回查 PDF 图表；
  - NASWOT 与最终性能的相关性依赖激活单元数量和搜索空间，论文也观察到 EPCNAS 中 pooling layer 因无 activation 容易被忽略；
  - 实验集中在图像分类 CNN，尚不能直接证明对检测、分割、Transformer 或非视觉 NAS 的普适性；
  - 复杂度主要使用 `#Params`/`#MAdds`，真实硬件 latency、memory traffic、operator fragmentation 等部署指标尚未系统纳入。

## 局限与未来工作

- 作者明确说明的局限：
  - 论文结论中指出，未来需要考虑更多影响模型复杂度和实际硬件部署难度的因素，以提升模型实用性。
- 作者未来工作：
  - 将真实部署难度、更多复杂度因素或硬件相关指标纳入 LightMix/NAS 搜索。
- 我们认为仍需确认的问题：
  - Population grouping 的阈值当前是手工给定，跨任务、跨硬件预算、跨搜索空间是否需要自适应；
  - NASWOT 与真实训练性能在 LightMix 搜索空间中表现良好，但在含 pooling、attention、skip-heavy 或 activation 稀疏结构的搜索空间中可能有偏；
  - External archive 无容量上限，若搜索空间或代数扩大，存储与排序成本是否需要压缩策略；
  - LightMix 的双分支与 channel shuffle 是否在真实移动硬件上比参数/MAdds 指标显示的收益更小，需要 latency/energy 实测。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 已关联设计知识：复杂度分组的目标子空间排序。可复用核心不是 LightMix 这个 CNN block 本身，也不是 NASWOT proxy 本身，而是“按复杂度/资源子空间独立排序并保留局部潜力解”的环境选择机制。
- 暂留在论文卡中的方法、原理或架构启发：
  - LightMix block 的多尺度双分支融合、identity reuse、外部 channel division 与 shuffle 对轻量 CNN 很具体，但目前主要是单篇视觉 CNN 结构证据，暂作为论文内结构启发保留。
  - NASWOT 对 activation 数量敏感，因此在设计搜索空间时应避免 proxy 对某类 operation 产生系统性盲区。
  - `s=0` 让 block bypass，可以把深度搜索统一进每层局部参数编码，而不用单独维护变长架构长度。
- 局部创新线索：
  - 把复杂度固定阈值换成当前 archive 的分位数、硬件 latency 桶或用户预算级别；
  - 在每个复杂度 group 内使用不同 proxy 或不同训练预算，例如低复杂度组偏 latency，高复杂度组偏 accuracy proxy；
  - 对全局被支配但 group 内优质的架构设置老化或重评机制，避免 archive 无界增长。
- 结构创新线索：
  - 构建“目标难度诊断 -> 易优化目标分桶 -> 桶内 Pareto 保留 -> 跨桶预算调度”的通用多目标搜索框架，可用于 NAS、程序搜索、算法配置或材料配方等存在成本/性能难度不均衡的场景。
  - 将 LightMix 的多尺度/通道复用思想迁移到非 CNN block 时，应先保留“廉价路径复用 + 表达力路径搜索 + 后置信息混合”的结构模式，而不是照搬卷积细节。
