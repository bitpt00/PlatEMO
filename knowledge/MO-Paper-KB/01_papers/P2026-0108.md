# A parallel evolutionary approach for multi-objective bus transit network design in multi-modal transit systems integrating with timetable synchronization

## 一句话理解

论文把多模式公交网络设计从“只设计公交线路与时刻表”扩展为同时考虑公交、轨道、BRT 与共享单车影响的 MBTND-TS，并提出 PEA-MBTND-TS：多个并行子种群通过共享精英路线池协同进化，使用分层路线/站点交叉变异、同步时刻表构造和权重向量非支配选择来生成 Pareto 方案。

## 问题与动机

- 研究问题和场景：
  - 面向城市多模式公共交通系统，需同时设计公交路线布局、发车时刻表，并与轨道/BRT 等既有模式同步。
  - 目标涉及乘客成本、运营成本、网络布局成本和时刻表同步质量，天然是多目标冲突问题。
- 现有研究为什么不足：
  - 早期 BTND、frequency setting 和 timetabling 往往顺序求解，难以获得整体最优。
  - 许多 BTND-T 研究只考虑公交系统，忽略轨道、BRT、共享单车等多模式网络对乘客流分布和换乘等待的影响。
  - 现有 MBTND-T 通常把乘客成本和运营成本分开优化，但没有显式考虑跨模式 timetable synchronization。
  - 权重和法把多目标压成单目标，难处理目标冲突，也依赖人工权重。
- 本文希望解决什么：
  - 提出带时刻表同步的多目标公交网络设计模型 MBTND-TS；
  - 在目标中加入最大同步次数和最小路线重复系数；
  - 设计适合路线-时刻表组合解的并行进化算法；
  - 用真实城市路网案例验证同步时刻表和并行协同机制的贡献。

## 模型结构

- Timetable synchronization：
  - 对 bus、rail 和 shared-BRT 定义换乘同步窗口。
  - bus/rail 换乘窗口为步行时间加最大等待时间，例如 `Delta t in [w_ij, w_ij + u]`。
  - shared-BRT 与普通 bus 同站换乘时，需要额外满足最小车头间隔 `epsilon`，避免普通公交进入 BRT 车道时干扰 BRT 运行，窗口为 `Delta t in [epsilon, u]`。
- Upper-level model：
  - 决定公交 route layout 与 timetables。
  - 传统目标包括乘客相关成本 `F_passenger` 和运营成本 `F_operator`。
  - 本文新增 `F_sync`：最大化 synchronization count `N_sync`，并最小化 network repetition coefficient `N_coef`。
  - 为统一最小化形式，最大化 `N_sync` 被写成负项。
  - 约束包括路线长度、无环路、最大发车间隔、车辆数量，以及 shared-BRT 车道上避免 bunching 的最小间隔约束。
- Lower-level model：
  - 使用 multi-modal dynamic transit assignment (MMDTA) 估计多模式网络中的乘客流分布。
  - 乘客流反过来影响上层的乘客成本和时刻表构造。

## 核心算法 PEA-MBTND-TS

- 解表示：
  - 两层 priority-based chromosome。
  - 第一层表示公交路线布局，每条路线由站点优先级编码。
  - 第二层表示对应时刻表，每个 `t_lk` 是 0-1 变量，表示 route `l` 是否在时间 `k` 从终点发车。
- 并行子种群：
  - 初始化种群 `S` 后随机划分为 `Q` 个等规模子种群，每个子种群在一个 parallel evolutionary stream 中演化。
  - 每轮演化后合并父代和子代，使用基于权重向量的非支配选择形成新总种群，再重新随机划分子种群。
- 共享精英路线池：
  - 不只共享 elite solutions，而是共享解内部的 elite routes。
  - 精英路线评分为 `d_l = p_l / delta_l`：`p_l` 为登车乘客数，`delta_l` 为路线非线性系数，即实际长度与起终点欧氏距离之比。
  - 高登车量和低绕行程度的路线更可能保留在共享池 `E`。
  - 各子种群通过 crossover/mutation 使用 `E`，也把自身新产生路线写回 `E`，超出容量 `E_max` 时按路线评分淘汰低分路线。
- 分层交叉：
  - Route crossover：在两个父代个体之间交换整条路线。
  - Inter-route stop crossover：在两条 crossable routes 之间交换连续站点片段，并用既有去重规则保持 priority 编码可行。
  - 共享精英路线参与交叉：父代中的路线可与 `E` 中的精英路线交换片段，实现跨子种群组件迁移。
- Multi-polar-angle overlap：
  - 共享站点法会漏掉没有共同站点但空间上耦合的路线；距离阈值法又难设阈值。
  - 作者把 TSP 中的 polar-angle overlap 扩展为多参考极点：先构造两条路线站点的最小包围矩形，选取四个参考极点，再检查两路线相对四极点的极角范围是否都重叠。
  - 满足所有极点重叠的路线才被视为适合站点片段交叉。
- 分层变异：
  - Route-level mutation：append route、delete route、replace route；其中 replace route 会用共享精英路线替换个体中的某条路线。
  - Stop-level mutation：route extension、route shortening、route optimization，用于扩展终点、缩短路线或消除明显绕行。
- Synchronized timetable construction (STC)：
  - 路线交叉/变异只产生路线布局，还需构造时刻表。
  - STC 在给定乘客流分布下先构造同步次数最大的 timetable，再求解 MMDTA 更新乘客流，循环到 user equilibrium gap 足够小。
  - 在仿真式 timetabling 中，每个候选发车时刻用 `E_lk = alpha p_lk + beta s_lk` 评分，其中 `p_lk` 是等待乘客数，`s_lk` 是同步次数；只有超过阈值的候选班次才进入 HTN 调度判断。
- 选择和最终推荐：
  - 使用 Das-Dennis 权重向量和 weighted Chebyshev aggregation 辅助非支配排序，提高三目标解集分布均匀性。
  - 最终 Pareto 解集可用 entropy-weighted TOPSIS 推荐一个综合方案给规划者。

## 实验证据

- 案例与设置：
  - Yiwu 路网：80 个点、334 条边；Wuhan 路网：79 个点、396 条边。
  - 每个网络包含 1 条 BRT 线和 1 条 rail line。
  - 研究时段为 8:00-18:00；公交边旅行时间随时间变化。
  - 由于缺少真实 OD，OD demand 随机生成；Yiwu 为 146 个 OD、6446 名乘客，Wuhan 为 105 个 OD、4468 名乘客。
  - PEA-MBTND-TS 的迭代数和种群规模均为 100；Java 实现，硬件为 3.6 GHz Intel Core i5 与 32 GB RAM。
  - 指标为 HV 和 IGD，20 次运行平均。
- MBTND-TS vs MBTND-T：
  - 不考虑同步次数的 MBTND-T 多数解被 MBTND-TS 解支配。
  - Table 1 中 MBTND-TS 在 waiting time、unserved passengers、running time 和 synchronization count 等多项上更好。
  - Table 2 中 MBTND-TS 的 HV/IGD 在两城市均优于 MBTND-T：Yiwu 为 HV 806,196、IGD 23.51；Wuhan 为 HV 134,912、IGD 8.23。
- 联合设计 vs 两阶段设计：
  - 两阶段方法先做 network design/frequency setting，再用本文同步时刻表生成。
  - Fig. 13 显示两阶段多数解被 PEA-MBTND-TS 支配。
  - Table 4 中 PEA-MBTND-TS 在两城市 HV 和 IGD 均优于两阶段方法。
- 与 MOEA/D、NSGA-II、NSGA-III 比较：
  - Table 5 中 PEA-MBTND-TS 在两城市 HV 和 IGD 均最佳。
  - 加入 HCM 后，MOEA/D-HCM、NSGAII-HCM、NSGAIII-HCM 多数优于各自原算法，说明分层交叉/变异对路线-时刻表问题有独立贡献。
- 消融：
  - 无 coordinated evolution mechanism (CEM) 时，解集分布更聚集、多样性变差。
  - Table 6 中去掉 CEM 后，Yiwu HV 下降 4.24%、IGD 变差 5.02%；Wuhan HV 下降 9.38%、IGD 变差 30.38%。
  - Multi-polar-angle overlap 优于 shared-stop (SS) 和 inter-route distance (ID) 判定；Table 7 中 SS/ID 在两城市 HV/IGD 均弱于 PEA-MBTND-TS。

## 局限与未来工作

- 作者未来工作：
  - 探索随机旅行时间对网络优化的影响；
  - 将人工智能技术与优化算法进一步结合。
- 我们认为仍需确认的问题：
  - OD demand 是随机生成，不是真实出行调查数据；真实需求分布下同步目标的收益还需验证。
  - 两个城市案例都只含一条 BRT 和一条 rail line，多线路、多枢纽和更复杂换乘网络中的可扩展性仍需验证。
  - 论文称 parallel evolutionary approach，但主文更强调并行子种群协同，缺少 wall-clock speedup、CPU core 数敏感性或通信开销分析。
  - MMDTA 本身是估计模型，若乘客路径选择模型偏差较大，乘客成本和同步效果评价会受影响。
  - Entropy-weighted TOPSIS 的最终推荐仍是后处理，未把规划者真实偏好反馈进搜索过程。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建设计知识：共享精英路线池的并行协同进化。它适用于 route/task/module 组合型 MOO：多个子种群并行搜索完整解，但通信单位是高质量组件，组件池同时参与交叉、替换变异和跨子群知识复用。
- 暂留在论文卡中的方法、原理或架构启发：
  - 对多模式交通问题，路线设计和时刻表同步不宜完全顺序化，否则前期网络设计可能只适配峰值需求，导致后期发车表难以修复未服务乘客和换乘等待。
  - 组件质量评价不必等同完整解目标，可用领域 proxy，例如 passenger volume / detour ratio。
  - 空间组合问题中的交叉应先判断两个组件是否空间耦合，否则随机交换片段可能多数无效。
- 局部创新线索：
  - 将 `p_l / delta_l` 扩展为多目标组件贡献，例如增加拥挤度、鲁棒性、碳排或公平性。
  - 将 multi-polar-angle overlap 替换为图嵌入相似度、OD 流相关性或 learned route compatibility。
  - 让 `E_max`、共享频率和精英路线使用概率随子种群多样性自适应调节。
  - 在 TOPSIS 推荐后将规划者反馈回流为 preference-guided selection。
