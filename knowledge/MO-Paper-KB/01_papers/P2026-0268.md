# Two-Stage Optimization for Multi-Objective Dynamic Vehicle Routing Problem with Time Windows under Uncertainty

## 一句话理解

论文把不确定行驶时间/需求与动态客户请求放在同一个 MODVRPTW-U 框架中处理：初始稳健阶段不仅最小化车辆数和距离，还用 Slack Time Distribution Index 主动把等待松弛量做大且分散；动态阶段再用时空插入和 key-route VND 快速接入新请求，从而在鲁棒性、低成本和动态适应之间取得折中。

## 问题与动机

- 研究问题和场景：
  - Multi-Objective Dynamic Vehicle Routing Problem with Time Windows under Uncertainty (MODVRPTW-U)；
  - 固定客户在出车前已知，动态客户在执行过程中到达；
  - 不确定性来自 travel time perturbations 和 customer demand variations；
  - 所有动态请求必须接受，已执行或正在前往的路线段不能重路由。
- 现有方法为什么不足：
  - 鲁棒 VRPTW 方法会保留容量或时间 buffer，但通常不考虑这些 buffer 是否利于未来插入动态客户；
  - 动态重优化方法能响应新请求，但常忽略 travel time / demand uncertainty，更新后路线容易很快违反时间窗或容量；
  - 过度保持鲁棒性会减少可插入位置，过度追求动态插入又会消耗鲁棒 buffer，二者天然冲突。
- 本文希望解决什么：
  - 在初始计划中主动预留可被动态阶段消耗的 slack；
  - 用低成本鲁棒指标支持大量局部邻域评价；
  - 在动态请求到达时只对关键路线做快速、可行性优先的精修。

## 核心理念与算法流程

- 两阶段模型：
  - Robust stage：为固定客户生成初始计划，目标为最小车辆数、最小总距离、最大 STDI；
  - Dynamic stage：每次新客户到达后更新当前路线，目标为当前已知客户集合下的车辆数和总距离；
  - 已执行弧在动态阶段作为固定参数，未执行部分才允许调整。
- STDI 主动松弛分布：
  - 对固定客户定义 slack time `sigma_i = max(e_i - t_i, 0)`，表示车辆早到并等待的计划松弛；
  - 只增加总 slack 容易让等待时间集中在少数客户，无法覆盖新请求可能出现的服务区域；
  - STDI 同时考虑归一化总 slack 和 slack 分布均匀性；
  - 最大化 STDI 会与车辆数和距离冲突：更多或更均匀的等待时间可能需要更多车辆或非最短路线。
- 低成本鲁棒评价：
  - Monte Carlo 约束违反指标 `Vio` 准确但昂贵，只用于低频决策，如策略切换和环境选择；
  - disturbance tolerance degree-based `Rob` 由 travel time tolerance 和 demand tolerance 组成；
  - travel time tolerance 衡量每个客户在时间窗被破坏前还能吸收多少累计延迟，整体用 harmonic mean 强调脆弱客户；
  - demand tolerance 衡量每条路线剩余容量能吸收多少需求扰动，整体同样用 harmonic mean；
  - `Rob` 用于局部搜索和 KRVND 中的高频鲁棒性评价。
- TSO robust stage：
  - 采用 route-based encoding，解为多条从 depot 出发并返回的车辆路线；
  - 初始化混合 greedy insertion 和 random assignment；
  - 使用 simplex-lattice 权重向量和邻域分解；
  - 双种群协同：`P_opt` 按名义场景 optimality 更新，`P_rob` 按 Monte Carlo `Vio` 和 PBI 更新；
  - route-based crossover 保留父代完整路线片段，mutation 包括 swap、relocate 和 reverse；
  - CORLS 在早期按权重偏好的目标做 optimality-first local search，后期若 `Vio>0` 切换到 robustness-first local search，否则继续优化。
- Rapid dynamic response：
  - 新请求到达时，只能插入未固定的剩余路线段；
  - 用 spatio-temporal distance 同时考虑空间距离和时间窗匹配，而不是只看 cheapest insertion 的成本增加；
  - 若存在可行插入点，从可行集合中选最小时空距离；若无可行点，先选最接近的不可行插入点再尝试修复；
  - KRVND 只在 key routes 上执行 VND：key routes 来自单位客户距离最高的路线和 `Rob` 最低的路线；
  - 邻域算子从低成本单路线操作到跨路线强操作依次展开；
  - 接受准则为优先提升 `Rob`，若 `Rob` 持平则降低距离；
  - 若 KRVND 后仍不可行，则丢弃本次插入和精修，为新客户新增一条车辆路线。
- 可能被修改的位置：
  - STDI 可替换为容量 slack、充电 slack、时间-容量联合 slack 或地理覆盖 slack；
  - `Rob` 可加入 chance constraint、CVaR、预测分布或在线延误估计；
  - key routes 可由历史插入失败率、客户密度、路线剩余时窗、车辆载重或地理覆盖缺口定义；
  - CORLS 的策略切换可改为 bandit/RL controller。
- 必须保留的核心：
  - 初始阶段要显式优化未来动态适应性，而不是只做静态鲁棒；
  - 动态阶段要把已执行决策锁定，并在有限时间内做局部高价值修复；
  - 高精度鲁棒评估和高频低成本鲁棒评估需要分工；
  - slack / buffer 不能只看总量，还要看分布覆盖。

## 实验证据

- Benchmark 和设置：
  - 使用六个 Solomon VRPTW 问题 R101、R201、C101、C201、RC101、RC201；
  - 使用三个 real-world MOVRPTW 问题 50-d0-tw4、50-d1-tw4、50-d2-tw4；
  - 每个问题组合三个 uncertainty levels 和三个 Degree of Dynamism，共九个场景；
  - Solomon 问题 DoD 为 `{0.25,0.5,0.75}`，50-customer 真实问题 DoD 为 `{0.2,0.5,0.8}`；
  - 每个算法每个场景独立运行 20 次。
- 对比算法：
  - 动态路线算法：ALNS-D、MOPSO-VNS；
  - 鲁棒算法加动态处理：RMOPSO-SoS-VND、ALNS-R-SoS-VND；
  - 鲁棒算法的动态处理由 sum-of-squares insertion 和 standard VND 组成。
- 鲁棒性结果：
  - TSO 在所有场景的 20 次运行中都找到可行解；
  - 多数对比算法在 R101、C101、RC101、RC201、50-d1-tw4 中可行次数低于一半；
  - 在 50-d2-tw4 中，除 MOPSO-VNS 外所有竞争算法在各场景都找不到可行解；
  - 随 uncertainty level 和 DoD 增加，对比算法可行次数持续下降，TSO 保持稳定。
- 最优性结果：
  - Figs. 5-13 用车辆数 NV 和总距离 TD 展示可行解中位表现；
  - 除一个场景外，TSO 均取得非支配或支配性能；
  - 27 个场景中 23 个场景 TSO 完全支配所有对比算法；
  - 唯一例外是 50-d0-tw4 的低 dynamism 场景，ALNS-D 和 ALNS-R-SoS-VND 因不主动保 slack 而有更低目标值；
  - 在 medium/high DoD 下，上述高风险策略失效，TSO 依靠初始 slack 完全支配它们。
- 可视化案例：
  - R101、C101、50-d2-tw4 的 medium uncertainty / medium DoD 案例中，对比算法路线出现时间窗或容量违反；
  - TSO 对应路线无违反，说明动态插入后仍保持可行性。
- 消融实验：
  - 四个变体：`TSO w/o STDI`、`TSO w/o DP`、`TSO w/o CORLS`、`TSO w/o RDR`；
  - 完整 TSO 在鲁棒性上优于所有变体；
  - 最优性上除一个场景外，完整 TSO 对变体非支配或支配；
  - 27 个场景中 22 个场景完整 TSO 完全支配所有变体；
  - 低 dynamism 的 50-d0-tw4 中 `TSO w/o STDI` 支配完整 TSO，说明 slack 的代价在动态请求很少时可能没有被充分使用；
  - medium/high DoD 下完整 TSO 显著更好，支持 STDI 对高动态场景的价值。
- 复杂度与运行时间：
  - TSO 总复杂度为 `O(Nf^3 + Nkr^2)`；
  - ALNS-D 为 `O(Nf^3 + Na^3)`，MOPSO-VNS 为 `O(Nf^4 + Na^4)`，两个 robust-plus-VND 变体为 `O(Nf^3 + Na^2)`；
  - 对 100-customer 实验，代表值可为 `Nf=50, Na=50, Nkr=20`；
  - KRVND 将动态阶段搜索空间从所有当前客户 `Na` 缩小到 key routes 中的 `Nkr`；
  - 作者报告 TSO 在 high-dynamism 场景运行效率优势明显，且大规模 VRPTW 中仍能保持高质量可行解。
- 证据边界：
  - 主文多处详细表格和参数敏感性在 supplementary material；
  - 不确定性采用最大扰动度区间表示，没有验证重尾、多峰或突变随机分布；
  - 假设所有动态请求必须接受，未比较允许拒单或服务外包时的策略；
  - TSO 的优势来自 STDI、双种群、CORLS、KRVND 和鲁棒指标组合，单个模块的独立边际收益仍需更多拆分实验。

## 局限与未来工作

- 作者明确说明的局限：
  - 最大扰动度区间表示实用，但可能难以刻画 heavy-tailed distributions 等复杂随机模式；
  - 区间鲁棒可能过度优化极端边界，造成计算和运营资源浪费；
  - 当前假设所有动态请求必须接受，在可拒单场景中对比算法可能通过拒绝困难请求获得更好表现。
- 我们认为仍需确认的问题：
  - STDI 中总 slack 与均匀性的乘积形式是否总是优于加权、min-coverage 或地理网格 coverage；
  - slack 分布只在固定客户上计算，动态客户高发区域若与固定客户分布不同，STDI 可能不匹配真实需求；
  - `Rob` 使用 harmonic mean 强调短板，但是否过于保守需与 CVaR、chance constraint 比较；
  - KRVND key-route 比例 `pkr=0.2` 是否应随动态请求密度、路线数量和实时响应时限自适应；
  - 多目标场景下最终只选一个 initial robust solution，实际部署中可否保留多方案在线切换。

- 暂留在论文卡中的方法、原理或架构启发：
  - route-based crossover、swap/relocate/reverse mutation 是 VRPTW 常规组合算子，暂不单独建卡；
  - ideal point compromise selection 是常见折中选解策略，暂留本文卡；
  - Solomon + real-world MOVRPTW 的动态/不确定 benchmark 构造可作为测试参考，暂不建 benchmark 卡。
- 局部创新线索：
  - 将 STDI 扩展为空间覆盖加权：动态请求高发区域或历史热点附近的 slack 权重更高；
  - 在 KRVND 中把 key routes 从固定 top `pkr` 改为预算感知集合，响应时间越短路线集合越小；
  - 用在线观测的 travel delay / demand residual 更新 `Rob` 的扰动上界；
  - 对不可行插入先尝试局部时间窗压缩、等待时间重新分配或小 MILP 修复，再决定新增车辆。
- 结构创新线索：
  - 构建“初始计划主动预留可消耗 slack -> 在线请求消耗 slack -> 鲁棒短板反馈重塑后续 slack”的闭环；
  - 与需求预测结合：预测未来请求的空间-时间分布，用 STDI 的均匀性替换为 demand-aware slack coverage；
  - 与数字孪生结合：用仿真流量和车辆状态在线校正 `Rob`，动态阶段只在高风险路线触发强修复；
  - 与拒单/外包决策结合：把新客户接受、延迟服务或外包作为动态阶段的附加 Pareto 选择。
