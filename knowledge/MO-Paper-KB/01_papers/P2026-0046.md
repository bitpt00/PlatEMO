# On discovering and analyzing variable dependencies to construct an effective and efficient optimizer dedicated to solving the new real-world multi-objective resource-allocation problem

## 一句话理解

论文提出短期用工行业的三目标人力资源槽位排序问题 MOHRAP-STE，并不是直接凭业务定义手写算子，而是先用排列版 empirical linkage learning 分析变量依赖，发现真实与人工实例几乎全连接高 epistasis 后，放弃 linkage 分解，构造参数少的 MO-P3-O2：P3 金字塔种群管理 + 随机权重标量化 + donor-like PMX 排列混合，最终输出非支配解。

## 问题与动机

- 研究问题和场景：EWL Group 短期就业业务中，每天要把有限且事先不确定数量的候选人推荐到客户工厂岗位。客户需求通常大于可用候选人，决策者既想优先高利润岗位，又要照顾紧急/重要客户，还要让所有客户至少部分被满足。
- 现有算法为什么不足：
  - 标准 HRAP/RAP 往往是直接 resource-to-task 或 task-to-resource assignment；MOHRAP-STE 不是直接把某个员工分配给某个岗位，而是生成一个 slot-processing sequence，作为“如果今天有 1、2、...、c 个候选人时依次填哪些槽位”的计划。
  - 常见 MOHRAP 用 NSGA-II、MOEA/D、MO-PSO、GA 或 exact optimizer，但 permutation-based 组合问题更需要保留和重组排序片段。
  - P3/P4 和 linkage learning 在离散问题中有效，但既有 P3 主要面向单目标二进制或排列问题，尚未与多目标排列优化和 PMX 这类排序算子结合。
  - 作者强调：变量依赖结构会决定应使用哪类优化机制。若高 epistasis 导致每个变量依赖大多数变量，那么依赖分解、DSM clustering 或 linkage mask 未必有益。
- 本文希望解决什么：
  - 定义 MOHRAP-STE：profit、priority、balance 三目标 slot sequence optimization；
  - 用 empirical linkage learning 自动分析真实实例的变量依赖网络；
  - 基于分析结果选择更适合高重叠依赖的搜索结构，而不是盲目使用 linkage operators；
  - 提出 parameter-less、适合实践部署的 MO-P3-O2，并与已调参的 MOEA/D、NSGA-II、MO-GA 比较。

## 核心理念与算法流程

- 核心理念：先做 problem structure diagnosis，再构造优化器。若变量依赖可分解，则 linkage/group operator 可能有用；若几乎所有变量都互相依赖，使用分解结构会退化或误导，此时更应使用保持多样性、能重组排列片段且少调参的 population pyramid + PMX。
- MOHRAP-STE 建模：
  1. 一个 job offer `o` 有招聘容量 `o_cap` 和已招聘数 `o_r`，可用岗位槽位数为 `o_cap - o_r`。
  2. 单个可用位置称为 slot `s`，其所属 job offer 为 `Offer(s)`。
  3. 解为 permutation `pi={pi_1,...,pi_n}`，表示 slot processing sequence；`n` 是所有可用 slots 数，通常 `n > c_max` 或 `n >> c_max`，而可用候选人数 `c_max` 事先未知。
  4. 目标 1 `PlanProfit(pi)=sum_i g(i,pi)`，其中 `g(i,pi)=sum_{j=1}^i Profit(Offer(pi_j))`，表示从前缀计划累积看的期望利润。
  5. 目标 2 `PlanPriority(pi)=sum_i p(i,pi)`，其中 `p(i,pi)=sum_{j=1}^i Priority(Offer(pi_j))`，表示前缀计划累积优先级。
  6. 目标 3 `PlanBalance(pi)=sum_i b(i,pi)`，其中 `b(i,pi)=min_o(o_r(i,pi)/o_cap(i,pi))`，鼓励所有 offer 的填补比例保持均衡。
  7. 三个目标均最大化。高 priority offer 未必高 profit，而 balance 往往与二者冲突。
- 变量依赖发现：
  1. 使用 permutation-based Empirical Linkage Learning (pbELL)。
  2. 对排列中相邻的两个 genes `i,j` 做 flip，构造 `pi*`；若 `fitness(pi) != fitness(pi*)`，则认为这两个 genes 依赖。pbELL 的特点是只报告真实依赖，但可能漏报。
  3. 原始 pbELL 是单目标方法；本文用 10 个 weight vectors 将三目标暂时标量化，对每个 weight vector 运行 pbELL，且每个权重考虑 10000 个个体。
  4. 由于同一 offer 的多个 slots 对目标影响相同，交换同 offer slots 不改变目标值，因此依赖分析在 offer 层而不是 slot 层进行。
  5. joint dependency 定义为：任一 weight vector 下发现依赖，则认为该 offer pair 依赖。
- 依赖分析结论：
  - 对 RC1-RC4 和 AC1-AC3，joint dependency 下所有 offer pairs 都被发现依赖；真实实例和人工实例结构相似。
  - 当 `PlanBalance` 权重为 0 时，部分 pair 未被发现依赖；但只要纳入 balance，大多数甚至全部 pair 被发现依赖。
  - 作者据此认为 MOHRAP-STE 是高 epistasis / heavily overlapping dependency 的排列问题，state-of-the-art linkage decomposition operators 未必适合。
- MO-P3-O2 流程：
  1. 初始化空的 pyramid levels，每个 level 是一个 subpopulation。
  2. 每次迭代随机生成 normalized weight vector，把三目标临时标量化为单目标 fitness，导向 PF 的不同区域。
  3. 随机创建一个新个体 `climber`，加入 Level 0。
  4. 从低到高遍历 pyramid levels；每层内部按随机顺序取 donor individuals。
  5. 用 donor-like PMX：从 level member 中取排序片段，单向修改 `climber`，而不修改 donor。
  6. 若 PMX 后的 `climber` 在当前 weight vector 下 fitness 提高，则接受并标记 improved；若 fitness 持平，也接受以保留中性漂移；否则拒绝该 donor 修改。
  7. 若 `climber` 与某层混合后发生 improved，则把该版本加入下一层。更高层个体代表经历更多成功改进的更强结构。
  8. 终止后，从所有 levels 中选择非支配解作为输出 PF。
- 与 P3/P4/MO-P3 的关系：
  - 采用 P3 的 pyramid-like population management 保持多样性；
  - 类似 P4，不在初始化时用 local search 改进 climber，以限制成本；
  - 采用 MO-P3 中随机 weight vector 引导多目标搜索；
  - 用 donor-like PMX 替换依赖 linkage 的 optimal mixing / DSM mask，因为高 epistasis 下 linkage 分解不适合。
- 可能被修改的位置：
  - pbELL 可换成 wVIG、SLL、DG2、变量交互图或领域依赖图；
  - 高 epistasis 诊断可用于选择 PMX、OX、partition crossover、path relinking、large neighborhood search；
  - 随机 weight vector 可换成 reference vector、偏好向量或 epsilon 约束；
  - donor-like PMX 可换成 problem-specific permutation operators；
  - pyramid levels 可与外部 archive、重启或多岛模型结合。
- 必须保留的核心：
  - 先做结构诊断，再选 operator family；
  - 当依赖高度重叠时，不要机械使用 linkage decomposition；
  - 对排列型 MOO，保留可解释排序算子和高多样性 population management；
  - 现实部署中减少调参负担是优化器设计目标之一。

## 实验证据

- 测试问题和实例：
  - 真实实例 RC1-RC4 来自 EWL Group，job offers 数为 39-99，slots 数为 166-901；最大 RC4 有 99 offers、901 slots。
  - 人工实例 AC1-AC3 用于补充更宽 profit/priority 范围和不同 slots-per-offer 结构；AC1 9 offers/135 slots，AC2 14 offers/264 slots，AC3 60 offers/264 slots。
  - 人工与真实实例经依赖分析显示结构相似，尤其在含 `PlanBalance` 的权重组合下依赖高度重叠。
- 对比算法和设置：
  - MOEA/D：PMX crossover probability 0.6、neighborhood range 6、population 45。
  - NSGA-II：PMX probability 0.6、mutation probability 0.1% per gene、population 200。
  - MO-GA：10 个 subpopulations，每个用一个 weight vector 优化单目标标量化问题；PMX 60%、mutation 0.1% per gene、population 100。
  - 所有 competing optimizers 都用全体测试集调参；作者认为这反而有利于基线，因为现实中通常只能用少量案例调参。
  - MO-P3-O2 parameter-less，不需要调参。
- 评价指标：
  - IGD：用所有优化器输出 PF 合并后的非支配集合构造 pseudo-optimal PF。
  - HV：nadir point 设为 `[0,0,0]`。
  - PFsize：报告输出 PF 点数，帮助理解算法是否只是返回大量点。
  - 计算预算：standard 为 `10 x 10^6` FFE，large 为 `40 x 10^6` FFE；每个实验 30 次；统计检验用 Mann-Whitney-Wilcoxon，显著性 5%。
- 主要实验结论：
  - Table 5 显示 MO-P3-O2 与对比方法的差异几乎全部显著；只有 4 个 case 不显著，其中 3 个是 PFsize，1 个是 IGD；多数 p-values `<10^-10`。
  - IGD：MO-P3-O2 在 14 个 case 中 10 个平均 IGD 最好，MO-GA 在 4 个最好；AC3* 中 MO-P3-O2 与 MO-GA 统计上并列。IGD 平均 rank：MO-P3-O2 1.2857、MO-GA 1.6429、MOEA/D 3.0000、NSGA-II 4.0000。
  - HV：MO-P3-O2 在 14 个 case 中 8 个最好，MO-GA 在 6 个最好；HV 平均 rank：MO-P3-O2 1.4286、MO-GA 1.5714、MOEA/D 2.9286、NSGA-II 4.0000。
  - PFsize：MO-GA 在所有实验中输出最大 PF；MO-P3-O2 输出点数通常显著更少。例如 RC4 standard 下 MO-P3-O2 平均 PFsize 156，而 MO-GA 为 7940；RC4 large 下 MO-P3-O2 为 673，MO-GA 为 11629。
  - 作者解释：MO-P3-O2 的 PF 点数少，但点质量高且分布足够好，因此在 IGD/HV 上更优；适合需要高质量、分布好的少量候选方案的实践场景。
  - 预算比值分析：MO-P3-O2 的 `IGD_standard / IGD_large` 在所有 test cases 中最高且均大于 1，说明它不是因过早收敛在小预算下占优；预算增加后相对表现还会改善。
  - 工业部署：作者称 MO-P3-O2 已在真实行业中实现/部署。
- 消融或机制证据：
  - 该文的主要“机制证据”是结构诊断：Table 4 显示 joint dependency 下所有 offer pairs 依赖，这直接解释为什么不用 linkage decomposition。
  - 没有单独比较“P3 without PMX”“PMX without pyramid”“with/without pbELL diagnosis”的消融，因此不能把收益完全分配到某个单组件。
- 证据边界：
  - Pseudo-optimal PF 由所有算法输出合并构造，不是真正已知最优 PF。
  - MO-P3-O2 与 MO-GA 各有优势：MO-GA 通常输出更大 PF，且部分 IGD/HV case 更好；MO-P3-O2 更偏高质量少量点。
  - 算法主要验证在 MOHRAP-STE，作者虽称可用于任何 permutation-based problem，但仍需跨问题验证。
  - Data availability 声明与正文中“去除敏感信息后的实例可在网页获得”的说法存在轻微不一致，需要复现实验时再确认。

## 局限与未来工作

- 作者明确说明的局限：
  - MO-P3-O2 输出 PF size 较小，不适合需要大量 Pareto 点密集覆盖的场景。
  - 依赖分析发现高 epistasis 后没有进一步利用加权依赖强度；当前只是把“全连接依赖”转化为放弃 linkage decomposition 的设计选择。
  - 主要证据来自 MOHRAP-STE，外推到其他排列型 MOO 需要验证。
- 作者未来工作：
  - 考虑其他 permutation-based operators，例如 partition crossover 及其排列优化版本；
  - 使用 weighted Variable Interaction Graph (wVIG)，为发现的变量依赖赋权；
  - 基于 wVIG 的分解可能产生即使在每个 gene 依赖大多数 genes 时仍有效的算子；
  - 在 MOHRAP-STE 以外的排列型问题上验证 MO-P3-O2。
- 我们认为仍需确认的问题：
  - 高 epistasis 诊断阈值如何自动映射到 operator choice：何时用 linkage mask，何时用 PMX/OX/partition crossover，何时用 LNS/ILS。
  - 随机 weight vector 标量化会不会遗漏某些 PF 区域，是否需要 reference-vector coverage 管理。
  - PFsize 小是优势还是劣势取决于决策场景；若用户需要完整 tradeoff map，需要额外 archive densification。
  - pbELL 成本较高，若每个新实例都运行 10000 个体 x 10 权重，实践中需要抽样或复用结构诊断。

## 可复用知识与创新线索

- 值得建立或补充的设计知识：
  - 新建设计知识：依赖诊断驱动的排列 P3-PMX 搜索。它可用于排列型组合 MOO：先诊断变量依赖结构，再决定采用 linkage-based decomposition 还是高多样性 population pyramid + permutation crossover。
- 暂留在论文卡中的方法、原理或架构启发：
  - MOHRAP-STE 的“候选人数未知时优化 slot prefix plan”是有价值的资源规划建模思路，但目前业务域较具体，暂不单独建场景卡。
  - `PlanBalance` 作为最小填补比例的前缀累积目标，可迁移到客户组合、服务公平和资源覆盖，但需要更多应用证据。
- 局部创新线索：
  - 将 pbELL/wVIG 作为 preprocessing，为排列型 MOEA 自动选择 PMX、OX、partition crossover、PR、LNS 或 linkage mixing。
  - 在 MO-P3-O2 中加入外部 archive 或参考方向，弥补 PFsize 小的问题。
  - 用多目标结构诊断的结果控制 mutation/PMX 片段长度：高依赖时用大块重组，低依赖时用局部分组混合。
  - 将 donor-like PMX 与业务可行 repair 结合，处理带约束资源排序。
- 结构创新线索：
  - 构建“结构诊断器 -> 算子族选择器 -> 参数少 MOEA”的通用离散 MOO 框架。
  - 对现实组合问题先用少量真实实例做依赖图诊断，再生成匹配的人工 benchmark，避免算法只适配随机构造问题。
  - 在交互式决策中，若用户偏好改变，可重新采样 weight vector 而无需重调主算法参数。
