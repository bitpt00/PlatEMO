# P2026-0114 - Evaluation-based multi-objective optimization for responsive-resilient supply chain network under hybrid uncertainty

## 一句话概括

本文面向混合随机-模糊不确定下的响应-韧性供应链网络设计，建立成本、响应性和韧性三目标 MIP/IFRSP 模型，并把 CRITIC-TOPSIS 评价嵌入多目标元启发式循环，用实时绩效排序选择精英并反向引导演化搜索。

## 研究问题

论文处理多层供应链网络设计：海外供应商、国内供应商、中央仓库、区域仓库和服务仓库构成多级网络，需求、成本、运输时间、容量和中断损失同时存在随机与模糊不确定。管理目标并不只是降低成本，还要提高客户响应和网络韧性。

作者指出现有供应链优化常有三类缺口：

- 只优化成本或单一绩效维度，缺少经济、响应性和韧性的统一多目标建模。
- 混合不确定模型常把随机和模糊部分分开处理，或只对部分约束加罚，导致可行性鲁棒控制不足。
- 多目标元启发式往往先生成 Pareto 集再事后评价，评价结果没有进入搜索循环，难以持续引导算法靠近管理上更有价值的区域。

## 模型与方法

### 响应-韧性供应链三目标模型

模型目标包括：

| 目标 | 含义 |
|---|---|
| `Z1` | 最小化总运营成本，包括设施开设、库存持有、运输、订购和存储成本 |
| `Z2` | 优化响应性，由运输时间和客户需求满足水平共同刻画 |
| `Z3` | 优化韧性，由节点复杂度、节点关键性和流复杂度刻画 |

韧性建模的重点是把供应链视为网络结构：节点复杂度反映启用设施规模，节点关键性刻画设施在物料流中的重要性，流复杂度反映产品流量和连接复杂性。这样可以把“抗中断能力”转成可计算指标，并与成本和响应性一起进入多目标模型。

### IFRSP 混合不确定建模

论文在 fuzzy robust stochastic programming 基础上提出 improved FRSP。原始 FRSP 用场景随机规划处理场景型不确定，用鲁棒项控制目标偏差，并用控制约束违反项处理场景约束的可行性风险。

作者认为传统 FRSP 仍有缺口：控制约束包含场景型不确定参数，而结构约束中也有模糊不确定参数；若只惩罚控制约束违反，会忽略结构约束的可行性鲁棒性。因此 IFRSP 在目标函数中加入结构约束违反的罚项，用 `alpha`、`beta` 表示机会约束满足水平，用 `pi` 表示机会约束违反罚成本，并与控制约束违反罚项 `delta`、目标偏差罚项 `eta` 一起控制鲁棒性。

### CRITIC-TOPSIS 评价反馈演化框架

论文提出一个 combined solution methodology，把多目标元启发式作为 optimization operator，把 CRITIC-TOPSIS 作为 evaluation operator。流程是：

1. 初始化元启发式参数、种群和外部档案。
2. 元启发式产生后代和 Pareto 候选。
3. 将后代中的非支配个体与档案合并，更新外部非支配档案。
4. 对档案内每个方案计算供应链绩效指标，CRITIC 计算客观指标权重，TOPSIS 计算综合绩效值。
5. 按绩效值排序，绩效最高个体作为 elite，引导下一代演化。
6. 重复直到终止，最终输出档案中绩效最高的方案。

这与常见“优化后再 MCDM 排序”不同：评价模块在每一代进入循环，综合绩效值会影响后续搜索方向。

### 嵌入的元启发式

论文把上述评价反馈框架分别嵌入四类多目标元启发式：

- CT-NSGA-II
- CT-MODE
- CT-MOPSO
- CT-MOALO

算法参数通过 L25 Taguchi 试验设计调优，避免对 5 个或 6 个参数做完整组合枚举。

## 实验设置

| 项目 | 设置 |
|---|---|
| 数值案例 | 2 个海外供应商、3 个国内供应商、3 个中央仓库、5 个区域仓库、6 个服务仓库 |
| 产品/运输/场景 | 2 种产品，国际运输/国内城际/区域短途多车辆模式，5 个中断场景 |
| 不确定性 | 产品需求、成本、运输时间和容量等用梯形模糊数；设施容量损失为场景型不确定 |
| 求解方法 | CT-NSGA-II, CT-MODE, CT-MOPSO, CT-MOALO |
| 重复次数 | 四种 combined solution methodologies 各运行 20 次 |
| 参数调优 | L25 Taguchi design；S/N ratio 选参数 |
| 评价指标 | 设施开设、库存持有、运输、订购、运输时间、准备时间、韧性指标等 |

## 主要结果

四个评价反馈式元启发式都能得到分布较均匀的可行 Pareto 方案，但综合绩效排序不同：

| 方法 | 最优方案 | 最优绩效值 |
|---|---:|---:|
| CT-NSGA-II | scheme 6 | 0.8796 |
| CT-MODE | scheme 1 | 0.8535 |
| CT-MOPSO | scheme 2 | 0.9344 |
| CT-MOALO | scheme 8 | 0.9698 |

作者据此选择 CT-MOALO 做后续敏感性分析，并认为它在稳定性、鲁棒性和综合绩效上最好。

评价策略对比中，CRITIC-TOPSIS 反馈式方法优于只用 TOPSIS 和不使用评价策略的传统 MOOA。表 11 中三类平均目标值均显示 CRITIC-TOPSIS 最优：经济目标平均值 6,337,527，TOPSIS 为 6,455,708，无评价策略为 6,565,383；响应目标平均值 34.97943，TOPSIS 为 36.32747，无评价策略为 38.1671；韧性目标平均值 110,888.2，TOPSIS 为 114,553.9，无评价策略为 118,691.9。

鲁棒模型对比中，IFRSP 优于传统 FRSP 和确定性模型。表 12 的平均值显示 IFRSP 在经济、响应性和韧性目标上均更好；正文还报告 IFRSP 相比传统 FRSP 降低约 7.8% 总成本，相比确定性模型降低约 15.6%，并避免确定性模型在不利场景下响应性和韧性下降超过 20%。

## 敏感性分析

需求变化方面，需求上升会推高成本；正文报告从基准到 1.2 倍需求时总成本增加约 9.1%，进一步到 1.5 倍时增加约 21.4%。响应性先随需求提高而改善，但超过约 1.2 倍后因容量瓶颈下降；韧性也在低到中等需求下因备用路径启用而增强，但超过约 1.3 倍需求后下降。

设施容量中断方面，中断比例上升会显著增加成本并降低响应性。容量中断从 0% 到 10% 时，总成本约增加 6.8%；继续到 20%-25% 时，总成本增加超过 15%，响应性下降接近 12%。超过 15% 容量损失后，韧性明显下降。

响应性目标阈值方面，`RES0` 从 0.7 提高到 1.0 时，平均满意度提高约 12.3%；继续提高到 1.3 时满意度只额外提高约 2.5%，但成本持续上升。论文认为 `RES0≈1.0` 是较好的成本-服务-稳定性折中。

罚项敏感性方面，提高结构/机会约束罚项和控制约束罚项会提升可行性保守程度，但也推高总成本。正文报告 `pi` 增大时总成本约线性增加 6.3%，罚项成本下降约 18%；`delta` 增大时总成本增加 4.7%，罚项成本下降 15.5%。这说明罚项需要在可行性风险和经济效率之间折中。

## 局限性

1. 模型同时包含混合整数变量、多场景不确定性和迭代群智能算法，计算复杂度高。
2. 当供应链节点、场景数或不确定参数规模扩大时，求解时间可能显著增加。
3. 元启发式参数敏感，需要细致调参，实际部署门槛较高。
4. 虽然论文称罚项具有自适应或动态意义，但 Markdown 正文中更清楚的是可调罚项和敏感性分析，未见完整的在线罚项学习规则。
5. 工业案例为工程机械备件供应链的工业规模合成案例，真实部署中的数据质量、行为反馈和执行约束仍需验证。

## 复用提示

如果要把本文思想迁移到其他多目标工程优化，CRITIC-TOPSIS 反馈框架更像一个外层控制器：它不替代 NSGA-II/MOPSO/MODE/MOALO 的基本进化算子，而是替换“如何从档案中选精英、如何定义下一代引导方向”。IFRSP 则更像建模层组件，适用于同时有随机场景和模糊参数的 MILP/MINLP。

## 证据边界

本文证据主要来自一个供应链数值案例、一个工业规模合成案例以及若干敏感性分析。其 CRITIC-TOPSIS 反馈机制尚未在标准连续 MOO 基准、昂贵仿真、动态 MOO 或强约束通用 benchmark 上系统验证；IFRSP 的优势也依赖于不确定参数建模、罚项尺度和场景设定。
