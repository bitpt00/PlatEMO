# 统计等价驱动的多标签 CMOP 算法选择方法

## 一句话理解

论文认为算法选择不应强行把每个问题标成单一最佳算法，而应先用统计检验找出性能与最佳算法无显著差异的一组算法，再把该组算法作为多标签目标，用 ELA 特征训练模型预测多个可选的最佳算法。

## 问题与动机

- 研究问题和场景：
  - 面向 constrained multiobjective optimization problem (CMOP) 的算法选择：给定一个新的 CMOP，预测哪些多目标优化算法最可能在给定评价预算下表现最好。
  - 输入特征来自 CMOP 的 exploratory landscape analysis (ELA)，输出不是一个单独算法，而是一组可被视为最佳的算法。
- 现有算法选择为什么不足：
  - 作者指出，既有算法选择研究通常按多次运行的平均指标值挑一个单一赢家，忽略性能分布和统计显著性。
  - 当多个算法性能非常接近时，强行指定一个赢家会让模型学习微小、随机或统计上不显著的差异，从而增加过拟合和不可复现风险。
  - 作者举例：在 MW6 上用 5000 次评价比较 SPEA2 和 NSDE，十组各 31 次独立运行中，SPEA2 在 6 组被识别为最佳，NSDE 在 4 组被识别为最佳，说明轻微运行波动会改变单一赢家标签。
- 本文希望解决什么：
  - 用统计检验识别“与当前最佳算法性能可比”的算法集合。
  - 用多标签分类模型预测这个最佳算法集合，而不是预测单一算法。
  - 提出 Algorithm Selection Precision (ASP) 评价指标，使模型既要命中至少一个真实最佳算法，又要少误报非最佳算法。

## 动机链

1. 算法选择的实际目标是为新问题找到可靠可用的算法，而不是区分统计上无意义的微小指标差。
2. 单标签方法把一个问题压成单一赢家，忽略多次运行分布，可能产生不稳定标签。
3. 若其他算法与赢家无显著差异，用户还可能基于运行时间、内存、实现可得性和熟悉程度选择其中一个。
4. 因此，应先在每个问题上识别统计等价的最佳算法集合。
5. 最佳算法集合天然是多标签目标，需要使用多标签分类和适配算法选择任务的评价指标。

## 核心理念与算法流程

### 整体方法

- 方法名称：multi-label algorithm selection methodology。
- 核心理念：把“算法选择标签”从单一赢家改成统计等价最佳算法集合，降低对微小性能差异的过拟合，并给用户保留多个可行算法选择。
- 主要组成：
  - 多次运行后的性能指标矩阵；
  - 基于 MAD、ANOVA 和 Tukey HSD 的最佳算法集合识别；
  - CMOP ELA 特征；
  - classifier chain 多标签分类器；
  - ASP 算法选择评价指标。

### Algorithm 1 流程

1. 对每个问题 `p`、每个候选算法 `a`，执行 `k` 次独立运行，每次预算为 `n` 次函数评价。
2. 对每次运行得到的解集计算 `I_CMOP` 指标，形成每个问题和算法的性能分布。
3. 对每个问题调用 `BestPerformingAlgorithms`，得到统计等价最佳算法集合 `A*_p`。
4. 对每个问题重复 `s` 次抽样，计算 ELA 特征，形成多个机器学习实例；同一问题的这些实例共享标签 `A*_p`。
5. 对每个测试问题采用 leave-one-problem-out：用其他问题的 ELA 实例训练多标签分类器，再预测测试问题的最佳算法集合。
6. 用 ASP 计算每个测试问题上的算法选择质量，再对所有问题求平均。

来源：Algorithm 1，PDF 3；ASP 与实验说明，PDF 5-6。

### Algorithm 2：最佳算法集合识别

对一个问题上的所有候选算法：

1. 先按多次运行的性能指标中位数选择当前最佳算法 `a*`。本文使用 `I_CMOP`，数值越低越好。
2. 用一倍 median absolute deviation (MAD) 判断候选算法与 `a*` 的性能分布是否重叠，只把有重叠的算法放入候选集合 `A_cand`，从而减少后续统计检验次数。
3. 对 `A_cand` 的性能分布执行 ANOVA，论文使用严格阈值 `p=0.005`。
4. 若 ANOVA 未发现显著差异，则 `A_cand` 全部作为最佳算法。
5. 若 ANOVA 发现差异，则用 Tukey HSD 后验检验，并以 `alpha=0.005` 将与 `a*` 无显著差异的算法保留为最佳算法集合。

来源：Sec. 3.1、Algorithm 2，PDF 3-4。

### 多标签分类与 classifier chain

- 每个候选算法对应目标向量中的一个二元标签；若算法属于 `A*_p`，对应元素为 1，否则为 0。
- 作者选择 classifier chain，而不是彼此独立的二元分类器，因为最佳算法标签之间存在依赖：加入一个新算法可能改变所有算法是否为最佳的标签。
- classifier chain 会把前序标签预测作为后续分类器的额外输入，从而学习算法之间的共现关系。
- 本文使用 scikit-learn 中的 Decision Tree、Random Forest、kNN 作为 classifier chain 的基分类器，并用 dummy classifier 作为基线。
- Fig. 3 中 NSDE 与 NSDE-R 在各维度中通常正相关，5D/10D 中 NSGA-II、NSGA-III 和 SPEA2 高度正相关，作者用这些现象支持标签依赖假设。

来源：Sec. 3.2，PDF 4；Fig. 3 与 Sec. 5.1，PDF 6、8。

### ASP 评价指标

- 对每个机器学习实例，定义 `IP_i = TP_i / (TP_i + FP_i)`。
- `TP_i` 是被正确预测为最佳的算法数；`FP_i` 是被错误预测为最佳的算法数。
- 若模型完全没有命中真实最佳算法，则 `TP_i=0`，`IP_i=0`。
- ASP 是测试数据中所有实例的 `IP_i` 平均值。
- 该指标的设计目标是：奖励模型至少识别出一个真实最佳算法，同时惩罚把非最佳算法误报为最佳。

来源：Sec. 3.3、Eq. (2)-(5)，PDF 5。

## 实验设置

- 问题集合：7 个 CMOP benchmark suites，包括 C-DTLZ、CF、CTP、DAS-CMOP、DC-DTLZ、MW 和 NCTP。
- 问题规模：2D、5D 和 10D 的双目标 CMOP；可用问题数分别为 33、65 和 65。这里 D 是决策空间维度，不是目标数。
- 候选算法：NSGA-II、NSGA-III、MOEA/D-IEpsilon、AGE、C-TAEA、SPEA2、GDE3、NSDE、NSDE-R。
- 实现来源：NSGA-III、C-TAEA、NSGA-II、AGE 和 SPEA2 来自 pymoo；GDE3、NSDE 和 NSDE-R 来自 pymoode；MOEA/D-IEpsilon 基于 pymoo 扩展。
- 运行设置：每个算法种群规模 200；每个问题和算法执行 31 次独立运行；每次运行 `300 * D` 代，总评价数 `n = 200 * 300 * D`。
- 预测预算：分别在 `n/24`、`n/6`、`n/2` 和 `n` 次评价后识别和预测最佳算法集合。
- ELA 特征：目标先用 ideal/nadir 做 min-max 归一化；sample features 使用 Latin hypercube sampling，样本量 `1000 * D`；random walk features 使用长度 `(D/W) * 10^3` 的随机游走，`W = 2D + 1`；特征计算重复 100 次，因此每个问题生成 100 个机器学习实例。
- 评估方式：leave-one-problem-out；一个 CMOP 作为测试集，其余 CMOP 作为训练集，最后平均 ASP。

来源：Sec. 4、Tables 2-3，PDF 5-6。

## 实验证据

### 最佳算法集合识别

- 论文实验直接支持：在运行早期 `n/24` 次评价时，更多算法会被识别为最佳；随着评价次数增加，最佳算法数量减少，更多 CMOP 只有单一最佳算法（Sec. 5.1、Fig. 2，PDF 6-7）。
- 论文实验直接支持：即使到完整预算 `n` 后，多数分析的 CMOP 仍有多个算法被统计检验识别为最佳，这支持作者保留多标签目标的核心动机（Sec. 5.1、Conclusion，PDF 6、9）。
- 论文实验直接支持：单一最佳算法随维度变化，2D CMOP 中最常见的单一最佳算法是 SPEA2，5D 和 10D 中则是 MOEA/D-IEpsilon（Sec. 5.1，PDF 6）。
- 论文实验直接支持：把统计检验阈值从 `p=alpha=0.005` 放宽到 `0.05` 时，识别出的最佳算法集合变化最多为 5%，作者据此认为该识别方法对这些参数变化相对稳健（Sec. 5.1、Appendix A、Table A.5，PDF 6、9）。
- 证据边界：5% 是本文 benchmark、候选算法和预算设置下的观察，不保证在其他算法池、指标或真实问题上同样稳健。

### 多标签预测效果

- 论文实验直接支持：所有算法选择模型在 ASP 上都超过 dummy baseline；差异在 dummy 较弱时更明显。例如 10D、完整预算 `n` 时，dummy ASP 为 0.195，最佳模型为 0.524，提升 0.329（Sec. 5.2、Table 4，PDF 6-7）。
- 论文实验直接支持：Random Forest 和 kNN 通常是最好的基分类器。Table 4 中，`n/24` 时 2D 和 10D 最佳均为 Random Forest，ASP 分别为 0.798 和 0.714；5D 最佳为 kNN，ASP 为 0.746。完整预算 `n` 时，Random Forest 在 2D、5D、10D 均最佳，ASP 分别为 0.612、0.491、0.524（Table 4，PDF 6）。
- 论文实验直接支持：dummy 在运行早期 ASP 更高，例如 `n/24` 时为 0.612、0.331、0.240，而完整预算 `n` 时降到 0.432、0.217、0.195；作者解释为早期多个算法共同最佳，任务更容易（Sec. 5.2，PDF 7）。
- 论文实验直接支持：Appendix B 中 LRAP、Hamming Loss 和 Subset Accuracy 的额外评估保持“模型优于 dummy、Random Forest 和 kNN 通常最好”的总体结论，但作者强调 ASP 更符合算法选择目标（Appendix B，PDF 10-11）。

### 机制证据

- 作者观点：多个算法经常共同最佳，说明单标签算法选择会丢失重要信息，并可能让模型过度区分无意义差异（Sec. 5.3，PDF 7）。
- 论文实验直接支持：Fig. 3 显示部分算法对常共同被识别为最佳，例如 NSDE 与 NSDE-R 在各维度中通常正相关，5D/10D 中 NSGA-II、NSGA-III、SPEA2 高度正相关。这为 classifier chain 利用标签依赖提供经验依据（Sec. 5.1、Fig. 3，PDF 6、8）。
- 我们的判断：该证据支持“标签间存在相关性”，但没有单独消融 classifier chain 相对独立二元分类器的收益。

## 局限与未来工作

### 作者明确说明的局限

- 统计检验需要设置 `p` 和 `alpha`，不同参数可能改变最佳算法集合，从而改变整个算法选择任务；作者称这是方法的瓶颈。
- 评估受限于本文选择的问题集、候选算法、问题维度和评价预算；这些设置改变后，结果和解释也可能改变。
- 实验只覆盖 2D、5D、10D CMOP。作者观察到维度增大时共同最佳算法数量减少，因此更高维问题上单标签方法可能已经足够，但公开高维真实 CMOP 较少。
- 实验只使用人工 benchmark CMOP，没有真实问题；人工问题的特征可能不同于现实问题。
- 方法虽然可推广到其他优化问题，但本文只在 CMO 上评估。
- 来源：Sec. 5.3，PDF 8-9。

### 我们认为仍需确认的问题

- 该方法是离线算法选择框架，需要对每个训练问题和候选算法做大量独立运行；若候选算法池很大，构造标签的成本很高。
- 最佳算法集合依赖候选算法池；加入一个更强算法后，已有算法标签可能整体变化，模型和数据集需要重建或校准。
- ANOVA 和 Tukey HSD 对分布假设、方差齐性和异常值敏感；虽然作者使用 MAD 预筛选和严格阈值，但未比较非参数或 Bayesian 等价检验。
- ELA 特征来自随机抽样和随机游走，特征质量受采样预算、归一化和 problem generator 影响；真实约束问题中可行区域稀疏时，采样可能难以捕捉关键结构。
- 本文没有把预测出的多个算法进一步组成并行 portfolio、顺序 warm start 或动态切换策略；目前输出仍是推荐列表。
- 对 classifier chain 的链顺序、概率阈值、校准和不确定性没有深入分析。

## 可复用知识与创新线索

### 已升级为设计知识

- `K-statistical-equivalence-multi-label-algorithm-selection`：统计等价驱动的多标签算法选择。该知识可直接替换单标签算法选择或算法推荐模块，也可作为算法 portfolio 与 hyper-heuristic 的外层选择逻辑。

### 暂留在论文卡中的方法、原理或架构启发

- MAD 重叠预筛选可作为通用“少做统计检验”的候选缩减步骤，但单独价值暂不够建立独立卡。
- ASP 指标可迁移到其他推荐型优化任务，用于奖励命中任一真实好选择并惩罚误报。
- 用 ELA 特征重复采样生成多个机器学习实例，可估计同一问题的特征随机性，但会使训练集存在同题多样本共享标签。
- 用户偏好在模型预测之后使用，而不是进入训练标签，可避免把实现可得性、运行速度、熟悉程度等主观因素混入性能标签。

### 局部创新线索

- 将已有单标签算法选择器的标签生成方式替换为统计等价多标签目标，尤其适合算法性能差异小、运行方差大的问题集。
- 在 CMOP 算法推荐中加入不确定性输出：当模型预测多个算法相近时，返回候选集合并让用户按成本或代码可得性选择。
- 将 ASP 与运行成本结合，形成 cost-aware ASP，惩罚误报高成本且非最佳的算法。
- 用非参数等价检验、bootstrap 或 Bayesian posterior overlap 替换 ANOVA/Tukey，比较标签稳定性。

### 结构创新线索

- 构建“算法候选池 + 问题特征器 + 多标签选择器 + 用户/成本过滤器”的算法组合推荐框架。
- 把预测出的多个算法作为并行 portfolio 初始集合，先短跑评估，再按在线表现分配预算。
- 将该方法嵌入自适应算法调度：离线多标签模型给出初始可行算法池，在线监控收敛、可行解比例和约束违反后动态切换或融合算法。

## 核验结论

- 作者观点：算法选择应允许多个算法共同被视为最佳，否则模型可能学习统计上不显著且不稳定的微小差异。
- 论文实验直接支持：在多数 CMOP 中，即使完整预算后也存在多个统计等价最佳算法；多标签模型在 ASP 上总是优于 dummy baseline。
- 论文实验未充分支持：classifier chain 相比独立二元分类器的单独贡献、真实世界 CMOP 的有效性、高维问题上的必要性，以及统计检验参数在更广泛场景中的稳健性。
- 我们的判断：最值得复用的是“先用统计等价构造多标签目标，再训练算法选择器”的标签生成与推荐架构；它适合算法组合和自动算法选择研究，但不能被视为新的底层 MOEA 算子。
