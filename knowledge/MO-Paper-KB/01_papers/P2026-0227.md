# 代理辅助 EMO 中异构目标评价时间处理

## 一句话理解

HET-EMO 不再把一个候选解的所有目标一次性都做高保真评价，而是把真实评价预算分配到“某个解的某个目标”上。它用 HFS 指标综合目标评价时间、代理不确定性和该解在参考向量邻域内成为非支配的概率，决定下一步最值得真实评价的解-目标组合，从而在同样 wall-clock 预算下跑更多代理辅助迭代。

## 研究问题

- 很多工程多目标问题的目标函数评价时间不同，例如 FEA、EMA、CFD 或第三方仿真软件调用。
- 常规 EMO/SA-EMO 在选择一个 infill solution 后，会对该解的所有目标执行高保真评价，这在目标评价时间差异大时不一定最省时间。
- 代理辅助 EMO 通常只问“哪些候选解需要真实评价”，较少问“这个候选解的哪些目标值得真实评价”。
- 若目标可独立评价，部分目标可以高保真、部分目标继续用代理预测；这样可以把真实时间预算集中到最能改善搜索和代理质量的位置。

## HET-EMO 总体流程

1. 用 LHS 生成 `N_DoE` 个初始样本，对所有目标做高保真评价。
2. 为每个目标独立训练 Kriging surrogate，并保存每个目标的高保真 archive `A[m]`。
3. 用 NSGA-III survival operator 从 DoE 样本中选初始种群；参考向量由 Riesz-s Energy 方法生成。
4. 在代理模型上运行 `tS` 代 surrogate-assisted NSGA-III，不消耗额外高保真评价。
5. 合并上一轮父代 `P` 与代理后代 `Q` 得到 `R`，重新用当前代理评估目标，并按参考向量关联。
6. 对 `R` 中每个解 `s` 和每个目标 `m` 计算 HFS metric `rho_s[m]`。
7. 按参考向量逐个选择高 HFS 的解-目标组合进行高保真评价，形成下一轮父代。
8. 更新对应目标 archive 和 surrogate，重复直到时间预算不足以完成最终解集全目标高保真评价。
9. 终止时对最终 `N` 个解的所有目标做高保真补齐，确保输出解集真实可信。

## HFS 指标

HFS metric `rho_s[m]` 用三类信息决定是否高保真评价解 `s` 的目标 `m`：

- **参考向量邻域内的非支配潜力**：
  - 先把解关联到参考向量；
  - 在同一参考向量邻域内，使用代理均值与不确定性计算两个解在目标 `m` 上“谁更差”的概率；
  - 得到解 `s` 在该目标上不差于邻域其他解的概率 `P_s[m]`；
  - `P_s[m]` 越高，说明该解在该参考方向上更可能有价值。
- **目标评价时间**：
  - 使用平均评价时间 `ET[m]`，并按最大目标评价时间归一化；
  - 被选中时，总时间预算 `T` 增加 `ET[m]`，而不是整解的所有目标评价时间；
  - 通过参数 `alpha` 调节对便宜/昂贵目标的偏好。
- **代理预测误差/不确定性**：
  - 使用 Kriging 提供的预测不确定性 `sigma_s[m]`，并按当前目标范围归一化；
  - 误差越大的目标越需要高保真评价来校正代理；
  - 参数 `eta` 控制不确定性项权重。

## 自适应 alpha

- 早期解通常离 Pareto front 远，不必对昂贵目标过早精确评价；此时偏向便宜目标可以用同样时间获得更多高保真反馈。
- 后期高潜力解需要更准确的昂贵目标值，否则最终解集可能因关键目标预测误差而偏离 PF。
- HET-EMO 让 `alpha` 随迭代从偏向便宜目标逐渐转向重视昂贵目标。
- 两目标参数实验显示，自适应 `alpha` 相比固定 `alpha=-1` 或 `alpha=1` 通常更稳。

## 选择与多样性

- HFS 不是直接全局选最高分，而是按参考向量方向逐个选择。
- 对每个参考向量，从其关联解及所有目标组合中选 `rho_s[m]` 最大的解-目标组合。
- 若某目标已被高保真评价过，则不重复评价；同一个解可能被多个目标选中，也可能只补一个目标。
- 这种做法把真实评价预算和 NSGA-III 的参考向量多样性维护结合起来，避免只评价少数热点区域。

## Block-evaluated objectives

- 一些工程问题中，多个目标由同一个第三方软件一次输出。
- 作者用 block mapping `beta(m)` 表示哪些目标同属一个评价块。
- 若目标 `m` 被选中高保真评价，同块目标同时获得高保真值，额外时间不再重复计入。
- HET-EMO 将 HFS 中的目标评价时间替换为 block evaluation time，并扩展选择逻辑处理同块目标。

## 实验设置

- 宿主算法：HET-NSGA-III。
- 对比算法：NSGA-III、SA-NSGA-III、HK-RVEA、ParEGO、K-RVEA、NSGAII-M1-2。
- HK-RVEA 只用于两目标问题，因为它原本面向 bi-objective nonuniform latency。
- 所有测试问题决策变量数设为 10。
- 两目标和三目标问题：population size `N=50`，`T_max=300`，`N_DoE=100`。
- 五目标问题：`N=60`，`T_max=360`，`N_DoE=120`。
- 八目标问题：`N=70`，`T_max=350`，`N_DoE=140`。
- 默认 surrogate generations `tS=30`。
- 每个问题独立运行 15 次。
- 指标：IGD+；统计检验使用 Wilcoxon signed-rank test，且表格底行报告 Holm-Bonferroni correction。

## 主要结果

- 全部 234 个测试与工程实例中，HET-NSGA-III 相对对比方法取得 121 个 better、111 个 equivalent、2 个 worse。
- 两目标 ZDT1-ZDT3 和 DTLZ2：
  - HET-NSGA-III 在绝大多数评价时间组合上显著更好或相当；
  - 只有 ZDT1 的极端 `(0.1, 0.9)` 组合中，ParEGO 和 NSGAII-M1-2 在一个简单实例上优于 HET-NSGA-III。
- DTLZ2 `(0.9, 0.1)` 行为分析：
  - HET-NSGA-III 对便宜且更需要校正的 `f2` 做更多高保真评价；
  - SA-NSGA-III 每轮整解全目标评价，300 时间单位只完成约 4 次 surrogate update；
  - HET-NSGA-III 因部分目标评价可完成约 29 次迭代。
- 三目标 DTLZ/WFG：
  - HET-NSGA-III 在所有测试实例上统计上更好或相当。
- 五目标和八目标 DTLZ/WFG：
  - 表格结论为 HET-NSGA-III 未被任何对比算法显著超越；
  - 八目标 DTLZ7 和 WFG6 上表现尤其明显。
- 工程问题：
  - two-objective four-bar truss 和 three-objective crash-worthiness 上，HET-NSGA-III 的收敛和多样性较好。
- Block evaluation：
  - 三目标和五目标 block objectives 中，HET-NSGA-III 仍优于对比方法；
  - block 中昂贵目标越多，利用一次评价同时补齐多个目标的收益越明显。

## 参数敏感性

- `N_DoE=0.33*T_max` 通常比 `0.1*T_max` 和 `0.5*T_max` 更合适：
  - 太少初始样本导致代理差；
  - 太多初始样本导致后续优化时间不足。
- `eta=20` 表现最好；
  - `eta=infinity` 等价于不考虑 surrogate prediction error，表现不可靠。
- `tS` 过大时，代理上能找到更“好”的解，但如果代理与真实函数偏差大，后期不确定性会增加；
  - 作者认为 `tS≈30` 是较好折中。

## 局限与阅读边界

- 当前主框架面向无约束目标；作者把加入 constraints 和 objective-constraint block evaluation 作为未来工作。
- 目标平均评价时间 `ET[m]` 需要由用户知识或初始 DoE 估计；若真实耗时高度随机或随解变化，静态平均时间会偏差。
- 方法假设目标可独立高保真评价，除非明确给出 block mapping；强耦合仿真接口可能无法拆分目标。
- HFS 指标是启发式组合，`alpha`、`eta`、`tS`、`N_DoE` 都有问题依赖性。
- Kriging 在 10 维测试中效果好，但高维真实工程问题可能需要其他代理或降维。
- 论文主文很多表格为图片占位，精确数值需查 PDF 或 supplementary。

## 可复用知识与创新线索

- 可复用机制：
  - 把真实评价选择从 candidate-level 细化到 solution-objective level；
  - 用目标评价时间、代理误差、非支配潜力共同决定高保真评价；
  - 用参考向量保证不同 PF 区域都能获得真实评价；
  - 用 block mapping 处理一次仿真输出多个目标的工程接口。
- 局部创新线索：
  - 将 HFS 中的评价时间从静态均值改成随机耗时分布或在线成本代理；
  - 把 `rho_s[m]` 扩展到约束：解-目标-约束三元组的高保真评价调度；
  - 将 Kriging 替换为 ensemble GP、deep kernel、RF/GBDT 或 conformal surrogate，并校准不确定性；
  - 在并行仿真环境中加入 worker availability、排队时间和 block batching。
