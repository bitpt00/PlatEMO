# 通过张量化连接演化多目标优化与 GPU 加速

## 一句话理解

这篇论文不是只把 EMO 程序搬到 GPU 上跑，而是把种群、目标值、参考向量和邻域关系改写成张量，把循环、分支、逐个体更新尽量改成 broadcasting、mask、`vmap` 和批量选择。作者用 TensorNSGA-III、TensorMOEA/D、TensorHypE 证明：只有算法结构真正张量化，GPU 才能在大种群和高维问题上释放数量级加速。

## 研究问题

- EMO 算法长期以 CPU 串行或低并行实现为主，代码库分散，难以服务大种群、高维决策和复杂仿真任务。
- 既有 GPU 加速多是 CUDA 局部改写或某个组件加速，不够通用，也不易让普通 EMO 研究者复用。
- 直接把原始 NSGA-III、MOEA/D、HypE 程序放到 GPU 上并不一定更快；循环、分支、CPU-GPU 数据传输和 GPU 核心利用不足会抵消硬件优势。
- 需要一种系统化改写方法，把 EMO 的数据结构、算子和环境选择都转成适合 GPU 批处理的形式。

## 核心方法：EMO 张量化

### 张量化数据结构

- 把种群表示为解张量 `X in R^{n x d}`，其中 `n` 是种群规模，`d` 是决策维度。
- 把目标值表示为目标张量 `F in R^{n x m}`，其中 `m` 是目标数。
- 参考向量、权重、邻域索引也改写为张量，例如参考向量 `R in R^{r x m}`、权重 `W in R^{n x m}`。
- 算法步骤尽量沿种群维度批量执行，使候选解评价、比较、关联、更新可在 GPU 上并行。

### 控制流张量化

- 用 broadcasting 或 `vmap` 替代逐个体循环。
- 用 element-wise mask、indicator 和 `where` 替代大量 if-else 分支。
- 用 sort、argsort、min、max、argmin、Hadamard product、Heaviside step 等基础张量算子组合出环境选择逻辑。
- 例如 Pareto 支配关系可以构造二维支配关系张量，而不是双重循环逐对比较。

### 适用性边界

- 最适合独立计算多、分支少、可批量比较或批量采样的 EMO 组件。
- 对顺序依赖强、递归、复杂分支或逐个体即时更新的算法，张量化需要先重构算法流程。
- 大规模支配关系张量会带来显著显存压力，张量化不是无成本加速。

## 三个代表算法的改写

### TensorNSGA-III

- 主要张量化环境选择中的 nondominated sorting、normalization、association、niche count 和 niche selection。
- 合并父代和子代后得到 `2n x m` 目标张量，通过 broadcasting 和 mask 构造支配关系张量，批量计算支配计数与等级。
- 归一化后批量计算每个解到参考向量的垂直距离，得到最近参考向量和距离。
- niche count 由 indicator 张量计算；niche selection 用调整后的距离张量从欠填充 niche 中选解。
- 由于原始 niche selection 含有较强随机和顺序逻辑，论文用批量随机操作近似模拟，这会带来少量质量差异。

### TensorMOEA/D

- 原始 MOEA/D 的 reproduction、evaluation、ideal point update、neighborhood update 有强顺序依赖。
- 作者把内层循环解耦：一次性并行生成 `n` 个 offspring，再批量计算目标值和理想点。
- 环境选择拆成两个 `vmap` 步骤：
  - comparison and population update：对邻域和权重方向批量比较 PBI 聚合值；
  - elite selection：沿每个权重方向挑选更合适的解更新种群。
- 这种改写牺牲了部分“即时更新后立即影响下一次交配”的序列特性，但显著提高 GPU 并行度。

### TensorHypE

- HypE 的核心瓶颈是 hypervolume 贡献估计。
- 作者把 Monte Carlo HV estimation 中的采样边界、采样权重、支配得分、距离更新和 HV 计算改成批量张量操作。
- Monte Carlo 采样天然适合 GPU 并行，因此 TensorHypE 的加速收益明显。

## MoRobtrol 基准

- 作者构建 MoRobtrol，把多目标演化优化与 GPU 物理仿真结合，用 Brax 作为底层仿真引擎。
- 决策变量是 MLP policy 的权重，目标包括前进奖励、控制成本、高度、距离惩罚、速度惩罚、接近奖励等。
- 任务包括 MoHalfcheetah、MoHopper、MoSwimmer、MoInvertedDoublePendulum、MoWalker2d、MoPusher、MoReacher、MoHumanoid、MoHumanoidStandup。
- 决策维度从约 161 到 4209 不等，适合检验 GPU 大批量搜索和复杂动态控制。

## 实验设置与主要结果

### 加速实验

- 平台：RTX 4090 GPU server + AMD EPYC 7543 CPUs，基于 EvoX 实现。
- 算法：NSGA-III、MOEA/D、HypE 及其 tensorized 版本。
- 测试：DTLZ1，重复 10 次，运行 100 generations，统计平均每代运行时间。
- 种群扩展：`d=500, m=3`，种群规模从 128 增至 32768。
- 维度扩展：`m=3, n=100`，维度从 1024 增至 1048576。
- 在 `n=32768` 时，TensorNSGA-III、TensorMOEA/D、TensorHypE 相对 CPU 版本分别约有 191x、1113x、186x 加速。
- 在 `d=1048576` 时，三者分别约有 304x、228x、263x 加速。
- 直接把非张量化算法放到 GPU 上可能更慢：NSGA-III 在大种群下超过 5 小时阈值，HypE 在若干规模上甚至慢于 CPU 原始实现。

### 数值优化实验

- 测试集：LSMOP1-9 和 DTLZ1-7。
- 设置：31 次独立运行，100 generations，population size 10000，dimension 5000。
- 指标：IGD 与 runtime，使用 Wilcoxon rank-sum test。
- 总体结论：张量化算法在同代数下保持同量级精度，同时运行时间大幅下降；若按相同 wall-clock time 比较，tensorized 版本能完成更多代并取得更好指标。
- 边界：TensorNSGA-III 的批量随机 niche selection 和 TensorMOEA/D 的批量 offspring/update 可能造成同代数下的轻微质量波动。

### 多目标机器人控制

- 算法：TensorNSGA-III、TensorMOEA/D、TensorHypE、TensorRVEA、Random Search。
- 设置：9 个 MoRobtrol 任务，10 次重复，population size 10000。
- 指标：HV、expected utility 和最终非支配解分布。
- TensorRVEA 在 MoHalfcheetah、MoHopper、MoWalker2d、MoPusher、MoReacher 上表现突出。
- TensorMOEA/D 在 MoHumanoid 和 MoHumanoidStandup 上更强，说明 decomposition-based 张量化算法对高维策略权重更有潜力。
- 一些任务上 TensorRVEA/TensorMOEA/D 的 HV 会先升后降，提示参考向量或权重方向可能导致早熟和多样性下降。

## 局限与阅读边界

- 张量化不是简单的代码替换，而是算法流程重构；顺序依赖和复杂分支越强，改写越困难。
- 支配关系、距离矩阵和采样张量可能产生 `O(n^2)` 或更高显存压力，超大种群下需要分块或近似。
- 为了并行性，某些选择逻辑被批量近似，可能与原算法的逐步随机行为不完全一致。
- 论文展示的是代表性算法，更多 EMO 组件如约束处理、动态响应、混合离散编码和代理辅助模块还需逐一张量化。
- MoRobtrol 很适合检验 GPU 并行搜索，但不等同于真实机器人部署中的安全、噪声和 sim-to-real 问题。

## 可复用知识与创新线索

- 可复用机制：
  - 把种群、目标、参考向量、权重、邻域和采样点统一表示为张量；
  - 用 mask 与批量矩阵运算替代逐个体循环和分支；
  - 对强顺序算法先做流程解耦，再批量 offspring、evaluation 和 environmental selection；
  - 把 GPU benchmark 与 EMO 搜索闭环放在同一张量框架中，减少 CPU-GPU 往返。
- 局部创新线索：
  - 为 nondominated sorting、reference association、PBI update、HV estimation 设计显存友好的分块张量版本；
  - 对张量化近似引入质量补偿，如周期性精确选择或小批量顺序修正；
  - 在 decomposition-based 算法中自适应调整权重张量和参考向量张量，避免 GPU 大种群早熟；
  - 将张量化与 surrogate、dynamic MOO、MORL 或 NAS 结合，让昂贵模块和演化模块共享 GPU 数据结构。
