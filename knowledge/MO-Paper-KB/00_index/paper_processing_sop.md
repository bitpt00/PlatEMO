# 单篇论文处理流程

## 目标

读懂论文，保存可靠知识，并保留未来进行局部创新和结构创新所需的依据。

## 处理步骤

### 0. 自动领取论文

新对话首先运行：

```powershell
& 'E:\多目标优化\MO-Paper-KB\00_index\paper_queue.ps1' -Action claim
```

只处理脚本领取并标记为 `in_progress` 的论文。处理成功后运行 `complete`；本次无法完成时运行 `release`。

### 1. 阅读与核验

- 以论文 Markdown 作为深度提取的主要阅读来源，完整理解其中具有科研价值的内容；
- 内容缺失、语义不清，或涉及核心公式、伪代码、图表和实验结论时回查 PDF；
- PDF 用于定点核验，不默认通篇重复阅读 Markdown 已经清楚表达的内容；
- 优先通过关键词、公式编号、算法编号、表格编号或页码定位需要核验的 PDF 内容；
- 记录关键内容的章节或 PDF 页码。
- 如为目视核验临时生成 PDF 页面截图，应使用包含论文 ID 的专用临时文件名；核验后直接删除本次自行生成的临时截图，不询问用户、不弹出确认窗口。
- 该清理授权只适用于工作区内名称明确匹配的流程临时页截图；不得删除原始 PDF、Markdown、知识库文件或其他用户文件。

### 2. 创建论文卡

论文卡应按照模板详细提取所有具有科研价值的知识，包括：

```text
研究什么问题
现有算法为什么不足
本文提出什么算法或方法
算法主要如何运行
实验支持什么
有哪些局限和未来工作
有哪些可复用知识和创新线索
```

同时详细保留真正重要的 Introduction / Related Work 评价、方法细节、算法可修改位置和关键来源页码。目录结构保持简单，但论文卡内容应尽可能完整。

### 3. 更新论文索引

`papers.csv` 由队列脚本统一维护，不手工修改。论文 ID、文件路径和状态流转由队列脚本负责；详细元数据与来源质量写入论文卡。

### 4. 判断是否需要设计知识卡

只有发现能够跨论文复用、能够用于改进算法或设计新结构的高价值知识时，才创建或更新设计知识卡。具体可直接使用的方法优先，单篇论文抽象出的原理和架构通常先留在论文卡。

```text
没有高价值可复用知识：论文卡完成后结束
先查看设计知识 README 中的极简索引
只打开可能相关的设计知识卡
索引无法判断时，再按名称、别名、问题和作用机制定向搜索
已有相同设计知识卡：补充新论文证据
无法确认是否重复：暂时留在论文卡
确认是新的高价值知识：满足升级条件后新建卡片
```

不默认通读全部设计知识卡。创建、重命名设计知识卡或索引字段发生变化时，应同步更新极简索引。

## 完成检查

- [ ] 论文卡能够说明问题、动机、方法、流程和结论；
- [ ] 关键结论有章节或 PDF 页码；
- [ ] 本次自行生成的临时 PDF 页截图已直接清理；
- [ ] 作者观点、实验支持和我们的判断没有混淆；
- [ ] Related Work 中真正重要的评价已经记录；
- [ ] 小方法和未成熟想法没有被过度拆分成独立文件；
- [ ] 新建设计知识卡前已通过极简索引和必要的定向搜索检查现有卡片；
- [ ] 新建、重命名设计知识卡或索引字段变化时已同步更新极简索引；
- [ ] 只在确有复用价值时创建或更新设计知识卡。

## 处理状态

```text
unprocessed       尚未处理
in_progress       已由某个对话领取
extracted         已完成核心抽取
reviewed          已复核关键内容
missing-md        尚缺 Markdown
missing-pdf       尚缺 PDF
```
