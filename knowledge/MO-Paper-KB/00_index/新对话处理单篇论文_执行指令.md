# 新对话处理单篇论文：执行指令

## 用途

本文件供新开的 AI 对话直接执行单篇多目标优化论文处理任务。

每个新对话默认只处理一篇论文。目标是尽可能完整地提取具有科研价值的论文知识，同时保持知识库结构简单。

## 新对话开始后的最小必读内容

```text
E:\多目标优化\MO-Paper-KB\03_templates\paper_card_template.md
E:\多目标优化\MO-Paper-KB\02_design_knowledge\README.md
```

本执行指令已经包含完整的单篇论文处理规则。默认不重复阅读根目录 `README.md`、项目需求说明和 `paper_processing_sop.md`；只有规则存在歧义或需要审查知识库结构时才打开它们。

不默认读取完整 `papers.csv`、既有论文卡或全部设计知识卡。论文 ID 和文件路径以队列脚本输出为准；设计知识查重先查看 `02_design_knowledge/README.md` 中的极简索引，只打开相关卡片。

## 额度优化原则

以下规则只减少重复阅读，不降低深度提取和设计知识建卡标准：

1. Markdown 是论文深度提取的主要阅读来源，应完整理解其中具有科研价值的内容；
2. PDF 用于定点核验 Markdown 缺失、模糊或关键的内容，不默认通篇重复阅读；
3. 先通过设计知识极简索引筛选候选，只读取可能相关的设计知识卡；
4. 需要查重但索引无法判断时，优先使用关键词全文搜索，再打开命中的少量卡片；
5. 初次阅读后再次查找信息时，使用章节、关键词或行号定向定位，不重复整篇读取同一来源；
6. 不为了节省额度省略重要方法、证据、局限或创新线索。

## 默认输入方式：自动领取下一篇

用户无需指定论文路径。新对话开始后，首先运行：

```powershell
& 'E:\多目标优化\MO-Paper-KB\00_index\paper_queue.ps1' -Action claim
```

脚本会自动：

1. 扫描 `E:\多目标优化\MD` 与 `E:\多目标优化\pdfs`；
2. 将新增论文加入 `papers.csv`；
3. 按稳定顺序选择下一篇 `unprocessed` 论文；
4. 将该论文标记为 `in_progress`；
5. 输出论文 ID、Markdown 路径、PDF 路径、DOI 和年份。

本对话只处理脚本领取的这一篇论文。若输出 `no_unprocessed_paper=true`，说明当前没有可领取论文，应直接汇报并停止。

如果用户明确要求处理某个已经登记的论文 ID，可以运行：

```powershell
& 'E:\多目标优化\MO-Paper-KB\00_index\paper_queue.ps1' -Action claim -PaperId <论文ID>
```

## 必须执行的任务

### 1. 确认论文身份与文件

- 运行 `paper_queue.ps1 -Action claim` 自动领取下一篇；
- 使用脚本输出的论文 ID、Markdown 路径与 PDF 路径；
- 不自行重新分配论文 ID；
- 检查文件内容是否对应同一篇论文；
- 如果领取后发现文件损坏、论文不属于处理范围或本次无法完成，应在结束前释放论文：

```powershell
& 'E:\多目标优化\MO-Paper-KB\00_index\paper_queue.ps1' -Action release -PaperId <论文ID>
```

### 2. 详细解读论文

论文卡内容应尽可能完整，但不要复制论文全文。重点提取：

#### 研究问题与动机

- 论文研究的具体多目标优化问题；
- 问题场景、特征与困难；
- 为什么该问题重要；
- 现有算法为什么不足；
- 作者如何从已有不足推导出本文动机。

#### Introduction 与 Related Work

- 重要技术路线和代表方法；
- 作者对已有方法优点、不足和适用条件的评价；
- 哪些已有不足直接支撑本文方法；
- 单篇论文的评价必须标记为作者观点，不能写成领域事实。

#### 本文算法与方法

- 算法名称和核心理念；
- 整体运行流程；
- 主要组成部分及每部分作用；
- 本文提出、采用和组合的大小方法；
- 重要输入、输出、信息传递和反馈；
- 与已有算法的主要区别；
- 如果适合作为基础算法，说明可能修改的位置和必须保留的核心。

#### 实验与证据

- 测试问题、真实问题、对比算法和指标；
- 主要实验结论；
- 消融实验和参数实验分别支持什么；
- 方法是否具有移植实验或跨场景证据；
- 不保存无必要的全部实验数字，但要保存能支持科研判断的结论。

#### 局限与科研机会

- 作者明确说明的局限；
- 作者未来工作；
- 实验暴露但作者未充分解决的问题；
- 可以用于局部创新的方法线索；
- 可以用于结构创新的原理或架构启发；
- 我们的判断和仍需确认的问题。

### 3. 按需回查 PDF

遇到以下内容必须按需回查 PDF：

- Markdown 缺失、乱码或语义不清；
- 核心公式、伪代码和算法流程；
- 图表与算法结构；
- 关键实验结论、消融实验和未来工作；
- 任何准备写入设计知识卡的重要证据。

PDF 核验不等于通篇阅读 PDF。Markdown 已经清楚、完整且不存在关键歧义的内容，不应在 PDF 中重复阅读。应优先通过标题、关键词、公式编号、算法编号、表格编号或页码定位需要核验的位置。

只有以下情况才考虑扩大 PDF 阅读范围：

- Markdown 严重缺失或抽取质量很差；
- 核心算法结构无法通过 Markdown 可靠理解；
- 准备复现该算法或将论文升级为 `reviewed`；
- 用户明确要求通篇复核。

关键知识应记录章节或 PDF 页码。必须区分：

```text
作者观点
作者未来工作
论文实验直接支持
我们的判断
```

#### PDF 临时页截图清理授权

- 为目视核验 PDF 图表、公式、伪代码或实验结果而临时生成的页面截图，属于单篇论文处理流程内的临时文件；
- 核验结束后必须直接清理这些临时页截图，不需要逐次询问用户或弹出确认窗口；
- 临时截图应使用能够识别当前论文 ID 的专用文件名，例如 `.codex_tmp_<论文ID>_p<页码>.png`，并只删除本次处理自行生成且名称明确匹配的文件；
- 清理前应确认目标文件位于当前工作区内；清理失败时应自动重试完成，不因权限确认中断论文处理；
- 此授权仅适用于流程内自行生成的临时 PDF 页截图，不适用于原始 PDF、原始 Markdown、论文卡、设计知识卡或任何其他用户文件。

### 4. 创建或更新论文卡

- 使用 `03_templates/paper_card_template.md` 的结构；
- 在 `01_papers/` 创建 `论文ID.md`；
- 所有具有科研价值的内容首先完整保存在论文卡；
- 小方法、抽象原理、架构启发和未成熟想法默认只留在论文卡；
- 不创建算法模型卡、创意卡、场景卡、Gap 卡或其他新类型文件。

### 5. 判断是否更新设计知识

首先查看 `02_design_knowledge/README.md` 中的极简索引，比较：

```text
名称和别名
解决的问题
作用机制
可以修改的算法位置
适用条件
```

只打开索引中可能相同或相关的设计知识卡。索引无法判断时，再使用名称、别名、问题和作用机制对 `02_design_knowledge/` 进行关键词全文搜索，并打开命中的卡片；不默认通读全部设计知识卡。

处理规则：

```text
已有相同知识：更新原设计知识卡，补充新论文证据和差异
无法确认是否相同：只留在论文卡，不新建
确认是新知识：满足严格升级条件时才新建设计知识卡
```

新建设计知识卡必须满足基本条件：

1. 能明确用于修改其他算法或设计新结构；
2. 能说明解决的问题、作用机制、适用条件和风险；
3. 具有可追溯的论文证据；
4. 值得未来跨论文查询和复用。

同时至少满足以下一项：

- 已被至少两篇论文采用、讨论或共同支持；
- 虽然只来自一篇论文，但属于实现明确、可以直接移植或改造算法的具体方法；
- 当前研究已经明确准备使用该知识。

不得因为论文提出了新方法，就自动建立设计知识卡。

创建或重命名设计知识卡，或者索引中的名称、主要问题、使用位置、类型、来源论文发生变化时，必须同步更新 `02_design_knowledge/README.md` 中的极简索引。

### 6. 更新论文索引

完成论文卡和必要设计知识更新后，运行：

```powershell
& 'E:\多目标优化\MO-Paper-KB\00_index\paper_queue.ps1' -Action complete -PaperId <论文ID>
```

该命令会检查论文卡是否存在，并将状态从 `in_progress` 标记为 `extracted`。只有成功完成全部任务后才能调用 `complete`。

`papers.csv` 由队列脚本统一维护，不要手工修改。论文中的详细元数据和来源质量记录在论文卡中。

## 不允许做的事情

- 不为每篇论文自动创建设计知识卡；
- 不创建新的顶层目录或卡片类型；
- 不创建创意卡、算法模型卡或复杂 CSV；
- 不绕过队列自行挑选或重新分配下一篇论文 ID；
- 未完成论文卡时不将论文标记为 `extracted`；
- 不把单篇论文观点直接写成领域共识；
- 不仅依赖摘要完成论文卡；
- 不因追求结构化而遗漏论文中的重要科研知识；
- 不修改与当前论文无关的已有知识。

## 完成标准

任务完成前必须检查：

- [ ] 已确认 Markdown、PDF、标题和 DOI 的对应关系；
- [ ] 当前论文是通过队列领取并处于 `in_progress` 状态；
- [ ] 论文卡已详细记录问题、动机、算法、方法、Related Work、实验、局限和创新线索；
- [ ] 关键知识已按需回查 PDF，并记录章节或页码；
- [ ] 本次自行生成的临时 PDF 页截图已直接清理，无残留；
- [ ] 作者观点、实验支持和我们的判断已区分；
- [ ] 已通过极简索引和必要的定向搜索检查现有设计知识，未产生明显重复卡片；
- [ ] 新建、重命名设计知识卡或索引字段变化时，已同步更新极简索引；
- [ ] 已运行 `paper_queue.ps1 -Action complete -PaperId <论文ID>`；
- [ ] 没有创建知识库规则之外的新目录或文件类型。

## 新对话最终汇报格式

完成后简要说明：

```text
论文 ID：
论文卡路径：
Markdown/PDF 核验情况：
提取的核心算法与方法：
新增设计知识卡：
更新的已有设计知识卡：
仅保留在论文卡中的重要线索：
仍需确认的问题：
```

没有新增设计知识卡是正常结果。

